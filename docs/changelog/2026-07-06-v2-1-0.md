## Record

The evidence release: the blind eval ran (Arc B complete), the repair
loop was proven on independent data, the answer layer was measured and
repaired, and everything a manual operator needs — batch embedding,
grounding over HTTP, token hygiene, a persistent embedding cache, and
the DataOps guide — landed alongside. 344 tests; all hygiene items
(H1–H8) closed.

- **Grounding over HTTP — `POST /construct/ingest` (2026-07-06):** the
  gap the DataOps guide exposed. Chunks + a stored space type →
  evidence-bound fact edges, with the space's ACCEPTED neurons applied
  automatically (hints extend triggers, blockers veto); negation-aware,
  no model involved, idempotent for post-revision re-ingest (entities/
  chunks keyed deterministically, edges upsert). GraphWrite scope,
  OpenAPI entry (drift-test enforced), in-module tests incl. negated
  trigger and accepted-blocker veto; dataops guide 04 now uses the route
  as the primary manual path.
- **DataOps guide (docs/dataops/, 2026-07-06):** five walkable guides for
  developers setting things up manually (no agentic tooling): data
  preparation and batch embedding, a CGQL-for-DataOps cookbook with
  inline runnable queries, retrieval routes and cache behavior, the full
  Semantic Neurons lifecycle (ontology authoring → grounding → eval →
  propose → review → graduation) with the exact collection contracts,
  and recurring maintenance routines. Cross-linked from README and the
  operations runbook.
- **Full-suite verification sweep #2 (2026-07-06, post trace-to-answer):**
  all gates and all four benchmark harnesses re-run — 340/340 tests,
  clippy/fmt clean, every figure within noise of the day's snapshot and
  several on the good side of it (flagship CGQL scan 0.81 ms, vector
  search 0.34 ms at 100% recall@10, grounding 5.7 µs/chunk, 139.9k
  persistent point reads/s @ c=128). The suite's documented noisiest
  cell (persistent mixed @ c=128) read 2.4k req/s in-band, reconfirming
  the earlier anomaly as disk-state noise. No snapshot churn: nothing
  performance-relevant changed since the morning re-run.
- **Trace-to-answer stage repaired (2026-07-06):** answer-level recall on
  the blind kits 32/68 → **53/68 (78%)** with restraint unchanged at
  0/36. A deterministic diagnostic (`answer_trace_diag`) split the loss:
  the 12-edge trace cap withheld 13/68 expected facts from the model;
  selectivity lost the rest. Fixes: 48-edge answer trace (retrieval bound
  measured out — every expected fact now reaches the model),
  exhaustive-selection prompt, and a fabrication guard (trace-absent
  assertions flagged, never credited toward recall; restraint stays
  behavioral on raw assertions, test-pinned). Remaining misses are pure
  answerer selectivity, concentrated in boundary/meta questions.
- **Gap-bearing authored-fixture runs
  (2026-07-06):** `blind_gap_derive` mechanically strips every rule
  trigger from a blind kit (vocabulary intact, zero pathways, no content
  judgment); all four B1 kits re-run from 0/67 per-mention baseline — the loop
  proposed 63 repairs, recovered **62/67 (93%) with 0/36 violations** under
  the historical per-question-mention evaluator,
  and answer-level results on fully loop-repaired graphs matched the
  human-authored ontologies (31/68 vs 32/68, 0 forbidden both ways).
  All 5 unfilled gaps are governed refusals: 4 paraphrased-trigger
  proposals rejected by the verbatim self-check, 1 verbatim trigger
  refused by negation-aware grounding (its only occurrence is in a
  negated clause) — an organic third-party-prose instance of the
  grounding half working. New deterministic reviewer tool
  `blind_recheck` re-applies a saved proposal set offline.
- **B1 session-separated authored fixture evaluation — Arc B complete
  (2026-07-06):** four assistant-authored evaluation spaces built from
  author-curated public-source research corpora (181 chunks, 68 expected
  fact mentions, 36 forbidden mentions, 16 questions), assembled outside the
  implementation session. This is not an independent external evaluation.
  Historical per-question-mention construction score: recall 67/67,
  restraint 0/36. Answer level: restraint
  perfect across two completion models (72/72 traps held); recall 32/68,
  model-dependent (24/68 on the older model) — the answerer-selectivity
  bound replicated on fresh data. Honest limit recorded: the complete

  is the follow-up. `COGNIGRAPH_COMPLETION_MODEL` (new) selects the
  evaluation completion model; default now `gpt-5.4-mini`.
- **Full-suite verification sweep (2026-07-06):** post-hygiene-arc re-run
  of all gates and all four benchmark harnesses — 337/337 tests, clippy/
  fmt/CI clean, every figure within noise of its recorded baseline
  (flagship CGQL scan 0.87 ms, vector search 0.37 ms at 100% recall@10,
  139.6k mixed req/s @ c=128 in-memory, persistent writes at the known

- **Batch embedding pipeline (H8, decision_batch_embedding.md):**
  `POST /documents/embed` (and `cognigraph embed COLLECTION FILE.jsonl`)
  embeds each item's text server-side — provider batches of 64, up to 4
  requests in flight — and stores everything in one atomic backend
  transaction. All-or-nothing: validation precedes the first provider
  call; a key conflict stores nothing. Items arrive pre-chunked
  (chunking stays with cognigraph-chunker). Fixed in passing: semantic/
  hybrid/graph-augmented hits without a `document_id` pointer now
  resolve to their own `_id` instead of `document: null` or silent
  omission from RRF fusion.
- **Persistent cache backend (H7, decision_cache_backends.md):**
  `COGNIGRAPH_QUERY_CACHE_BACKEND=persistent` +
  `COGNIGRAPH_QUERY_CACHE_PATH` stores the EMBEDDING cache in a redb
  file so cached embeddings survive restarts (each miss avoided is a
  provider round-trip); search results deliberately stay memory-only
  (TTL-bounded). Measured: put 4.4 ms (fsync, amortized against the
  embed call), memory hit 4.3 µs, cold read-through 16 µs. Redis
  deferred with a recorded multi-instance trigger.
- **Token hygiene (H6, decision_token_hygiene.md):** API tokens gain
  opt-in expiry — `COGNIGRAPH_TOKEN_TTL_SECS` server default plus
  per-token `expires_in_secs` (0 = non-expiring); expired tokens fail
  like revoked ones but stay listed with `created_at`/`expires_at`/
  `expired` for audit. In-place rotation keeps the record and key while
  killing the old secret immediately: `POST
  /users/{key}/tokens/{token_key}/rotate` and `cognigraph token rotate
  USER TOKENKEY [--ttl-secs N]` (issue also takes `--ttl-secs`).
  `last_used_at` tracking and auto-purge deliberately not taken —
  recorded with rationale.
