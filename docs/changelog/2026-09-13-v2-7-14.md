# v2.7.14 — Stable Docker image aliases

- Date: 2026-09-13
- Status: v2.7.14
- Kind: Maintenance release

## Changes

Both Docker editions publish a mutable `latest` alias after both immutable
`x.y.z` images pass runtime checks, upload, and registry digest readback.
Aliases use the tested image IDs and must match their numbered release digests.
The publisher rejects tag-policy drift, changed main and concurrent alias changes.
Failed or partial publication retains receipts and requires inspected recovery.

The [publishing guide](../operations/docker-publishing.md) owns the contract,
including its sequential-update limitation. Docker Hub overview sources now
show the short `latest` pull commands and explain version/digest pinning.
Numbered releases retain registry-side protection against overwrite and deletion.

## Validation

Regression tests cover publication ordering, tag policy, missing or mismatched
registry digests, main/alias drift and partial failures. The release requires
the full shared local CI and both Linux/amd64 Docker/Helm suites, followed by
GitHub CI and independent pulls of the published images. Publication receipts
and post-pull runtime results belong in private evidence. This change does not
modify database behavior or initiate Railway tests.
