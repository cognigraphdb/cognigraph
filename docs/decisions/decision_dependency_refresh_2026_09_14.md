## Decision

Refresh all application dependencies and compatible transitive resolutions under
the [develop qualification policy](decision_develop_qualification.md), without
freshness exceptions. Prepare local candidate v2.7.15; source publication, merges
and Docker Hub publication require their separate authorized workflow.

Adopt Argon2 0.6 despite its Rust API changes. Its published changelog removes
the `std` feature and upgrades `password-hash` to 0.6. Use its OS-random salt
generation and PHC parser; retain Argon2id v19, 19,456 KiB, two iterations and
one lane. Verify both a PHC string generated by 0.5.3 and an actual database
created with the preceding server. Existing users must not need password resets.

Upgrade redb 4.1 to 4.2 and Tantivy 0.26.1 to 0.26.2. Reopen old resident and
paged stores with the candidate, verify authentication/documents/text search,
write with the candidate and verify persistence after restart. No new redb
experimental APIs are enabled. Run existing Native recovery and text-cache tests.

The published Tantivy 0.26.2 manifest still requires `lru ^0.16.3`. Carry the
already reviewed one-line `^0.18.2` correction onto the checksummed new release;
retain its license and exact file inventory. The local patch changes no Rust
source. The upstream release includes aggregation and scorer corrections.
The [vendor guide](../../vendor/README.md) retains removal criteria: retire the
patch when a qualified released version supplies fixed lru itself.

The optional ONNX runtime and tokenizer remain at rc.13 and 0.23.2 respectively.
The compatible macro helper update to 0.2.3 removes one route to `paste`, but
tokenizers still requires it directly. Review the current reverse dependency
inventory and advisory scan, compile/lint/test ONNX and exercise deterministic
tokenization plus actual local MiniLM inference. The existing optional-only
maintenance decision remains bounded by 2026-10-12 or the next relevant change;
no warning is suppressed, no hosted provider call or research holdout is run.
