# Repository data removal

The owner requested removal of customer-specific material from the code
repository and its published history on 2026-09-11. The detailed inventory,
original backups, object maps and exact ref manifest are kept outside this
repository so this record does not reintroduce the removed information.

## Scope and evidence

The rewrite deletes dedicated research kits and historical sales assets. Mixed
fixtures lose the affected source records, labels and derived model verdicts.
Generic Rust grounding/advisor regression tests retain their assertions with
synthetic organization names. Unrelated business-intelligence terminology and
unaffected corpora are preserved.

Historical aggregate scores from the removed or reduced corpora are withdrawn.
Surviving rows remain historical observations, not a newly qualified dataset.
The offline counting example covers only the retained qualitative-research
space. Original CUAD regeneration/replay refuses execution because its frozen
inputs were partially withdrawn; its pure counting helper tests remain usable.
No provider calls or qualification holdout execution are part of this work.

## Publication boundary

History replacement requires an exact old/new ref manifest and a verified
removal report outside the checkout. The opt-in history-removal hook mode
retains clean-tree, current-candidate CI, Docker, version and incoming-PR gates.
It accepts only the reviewed branch/tag transaction and rejects remote drift;
ordinary pushes continue to require fast-forward updates and immutable tags.
Use explicit force-with-lease values and an atomic push. Historical release
versions are preserved; the new maintenance candidate has its own patch version.

GitHub pull-request refs and cached commit views require a separate server-side
removal request where eligible. Rewriting branches/tags does not establish that
all copies disappeared. Existing collaborators must replace or carefully clean
their clones before publishing again. The private sibling product-docs
repository is outside this operation.

## Verification

The out-of-repository receipt records the all-history blob/path/message scan,
PDF extraction, image inspection, preserved-path comparison and Git object
integrity. Current code verification uses the shared CI and Docker runners plus
offline fixture validation and release-binary construction replay. Remote
publication and server-side cache removal are separate from local verification.

Local verification on 2026-09-11 passed the Docker build and three release-binary
fixture validations. The intentionally stripped gap fixture reports 21 expected
missing-trigger warnings; both other retained fixtures have zero warnings.
Three offline construction replays reproduce 15/15 cold, 0/15 stripped and
12/15 repaired expected facts, each with zero forbidden facts. These are
retained-fixture regression checks, not new model-quality measurements.
