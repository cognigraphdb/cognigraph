# CG-109: Text search passes an unvalidated limit and field names into Tantivy, which panics

- Status: Resolved
- Priority: P1
- Area: Native / text search
- Found: 2026-11-11
- Verification: Reproduced live on 2026-11-11 (2.7.39); after the fix the same requests return HTTP 400 on a 2.7.48 Community release build with no panic in the server log; both test suites pass (836 Community, 1,063 Enterprise)
- Resolved: 2026-11-11

## Problem and evidence

Two inputs of `POST /api/search/text` reach Tantivy unchecked.

- **Limit.** `routes/search/basic.rs` takes `limit: usize` and Native calls
  `TopDocs::with_limit(limit.max(1))`
  (`crates/cognigraph-native/src/text_index.rs:172-176`). Tantivy
  pre-allocates `2 × limit` slots per segment. Hybrid search multiplies the
  limit by three first, and Lua `graph.text_search` passes it through as well.
- **Field names.** `validate_text_search_fields` rejects only `_key` and
  duplicates (the [CG-17](CG-17.md) fix). Tantivy's schema builder asserts
  that a name is non-empty and does not start with `-`.

Reproduced on a one-document collection:

- `"limit": 18446744073709551615` panics a worker with "capacity overflow".
- `"fields": [""]` and `"fields": ["-title"]` panic at
  `vendor/tantivy-0.26.2/src/schema/field_entry.rs:26`.

Each time the connection closes with no HTTP response and nothing reaches the
error log. A mid-range limit such as 10^12 returned normally on macOS, where
the allocation is lazy. On a host that refuses the allocation Rust aborts the
whole process; that variant was not reproduced.

## Resolution

- **Server caps.** The text, vector, semantic, hybrid and graph-augmented
  routes refuse `limit` above 1,000, the graph-augmented route also
  `seed_limit` above 1,000 and `graph_facts_limit` above 10,000, with HTTP
  400. The check is the first thing each handler does
  (`crates/cognigraph-server/src/routes/search/mod.rs`).
- **Native clamp.** `TextIndex::search` clamps the limit to the number of
  indexed documents before building the collector, which also covers the Lua
  binding.
- **Field names.** `validate_text_search_fields` calls the index library's
  own field-name predicate and returns a validation error for an empty name
  or one that starts with `-`.
- The limit multipliers in hybrid and vector search saturate instead of
  wrapping.

The [decision record](../decisions/decision_search_and_traversal_limits.md)
has the caps and the alternatives; the HTTP reference states them.

Tests: `crates/cognigraph-native/tests/text_search_limits.rs` runs limits
from 0 to `usize::MAX` and seven invalid field lists in memory-only, resident
and paged modes, before and after a restart.
`crates/cognigraph-server/src/routes/search/limit_tests.rs` checks the cap
and the boundary on every search route, including without an embedding
provider.

Live check on a 2.7.48 release server: `limit` of 18446744073709551615 and of
10^12, `fields` of `[""]` and `["-title"]`, a hybrid request with the huge
limit and a graph-augmented request with `seed_limit: 5000` each return HTTP
400; `limit: 1000` is served; a Lua `graph.text_search` call with a limit of
10^15 returns normally; the server log has no panic.

Not changed: a panic in a handler still closes the connection without a
response ([CG-128](CG-128.md)).

## Acceptance

- [x] Search limits (`limit`, `seed_limit`, `graph_facts_limit`, the hybrid fetch limit) have a documented cap and return 400 above it; Native clamps to the indexed document count before building the collector.
- [x] Field-name validation rejects every name Tantivy would assert on.
- [x] Regression tests cover `u64::MAX`, 10^12 and 0 as limits and `""` and `"-x"` as fields, for text and hybrid search in resident and paged modes.
