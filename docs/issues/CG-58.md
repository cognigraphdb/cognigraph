# CG-58: Review empty-state guidance recommends a forbidden space creation path

- Status: Resolved
- Priority: P2
- Area: UI / review
- Found: 2026-09-11
- Verification: UI checks, 151 tests, production build and real Native browser/API workflows

## Problem and evidence

The Review empty state says to create a document directly in `space_types`
([ReviewScreen.tsx](../../ui/src/screens/ReviewScreen.tsx), lines 279–294).
Enterprise now makes that collection read-only through generic mutation APIs.
The instructed POST returns 403: the collection is managed by governed Semantic
Neuron workflows. It cannot bootstrap the queue as the UI promises.

The supported path is an editable `space_type_drafts` document followed by the
dedicated accept endpoint, or governed candidate construction. The audit created
a synthetic draft and accepted it through that route successfully, without an
LLM. This confirms a UI instruction defect, not absent backend functionality.

In addition, `loadSpaces` catches all failures and sets `spaces=[]`; rendering
checks that condition before the queue error. Enterprise host-admin therefore
sees “this server has none yet” even when the server has a space and correctly
refuses that role's reads. Construct uses the same empty-on-error convention.
Community feature absence is separately covered by CG-53.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Direct operators to the dedicated draft/review/accept workflow rather than writing accepted spaces directly.
- [x] Distinguish an empty successful response, denied access, unavailable edition and failed loading; provide retry where applicable.
- [x] Test a fresh Enterprise tenant, an existing space under a denied role and a real API failure; preserve the managed mutation guard.

## Resolution — 2026-09-11

CG-53 already prevents denied roles and Community editions from mounting these
screens. CG-54 already separates catalog failures from successful empty results.
This change completes the guidance and handles the fresh Native tenant case:
listing a collection that has never been created returns 404. The loader treats
that as empty only when a separate successful collection-catalog read confirms
`space_types` is absent. Existing-collection failures, failed/invalid fallback
responses and failed continuation pages remain errors.

Review and Construct share explicit loading, permission-denied, request-failed
and confirmed-empty notices. Retry refreshes the catalog; loading and failures
cannot leave an old space driving dependent actions. The empty notice directs
writers to Construct and `space_type_drafts` review, while readers are directed
to an editor or administrator. Construct supports the existing provider-generated
or manually prepared draft paths, links to the stored JSON and labels the ID
field for either a new or existing draft. Acceptance still uses the dedicated
endpoint. No managed mutation guard or backend contract changed.
