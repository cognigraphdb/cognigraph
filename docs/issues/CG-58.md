# CG-58: Review empty-state guidance recommends a forbidden space creation path

- Status: Open
- Priority: P2
- Area: UI / review
- Found: 2026-09-11
- Verification: Source review and real Enterprise managed-collection denial

## Problem and evidence

The Review empty state says to create a document directly in `space_types`
([ReviewScreen.tsx](../../ui/src/screens/ReviewScreen.tsx), lines 279–294).
Enterprise now makes that collection read-only through generic mutation APIs.
The instructed POST returns 403: the collection is managed by governed Semantic
Neuron workflows. It cannot bootstrap the queue as the UI promises.

The supported path is an editable `space_type_drafts` document followed by the
dedicated accept endpoint, or governed candidate construction. The audit created
a synthetic draft and accepted it through that route successfully, without an
LLM. This confirms a UI instruction defect, not absent backend functionality.

In addition, `loadSpaces` catches all failures and sets `spaces=[]`; rendering
checks that condition before the queue error. Enterprise host-admin therefore
sees “this server has none yet” even when the server has a space and correctly
refuses that role's reads. Construct uses the same empty-on-error convention.
Community feature absence is separately covered by CG-53.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [ ] Direct operators to the dedicated draft/review/accept workflow rather than writing accepted spaces directly.
- [ ] Distinguish an empty successful response, denied access, unavailable edition and failed loading; provide retry where applicable.
- [ ] Test a fresh Enterprise tenant, an existing space under a denied role and a real API failure; preserve the managed mutation guard.
