# CG-129: Lua execution is limited only by VM instruction count

- Status: Open
- Priority: P2
- Area: Lua / execution control
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

The instruction hook in `crates/cognigraph-lua/src/runtime.rs:86-97` is the
only limiter. What it does not cover:

- **Memory.** No memory limit is set.
  `local t = {} for i = 1, 4000 do t[i] = string.rep("x", 1e8) .. i end`
  needs about 400 GB in roughly 20,000 instructions.
- **C library calls.** Hooks do not fire inside them. A backtracking pattern
  such as `string.find(string.rep("a", 5000), ".-.-.-.-.-.-.-b")` is one
  instruction, cannot be cancelled and pins a blocking thread (plausible).
- **Nesting.** The result is converted with `from_value` (`:128`), which
  guards against cycles but not depth. A table nested 100,000 deep recurses
  unbounded on a 2 MiB thread (plausible); the same applies to documents and
  bind variables passed in.
- **Typed bindings.** `graph.traverse(start, {max_depth = 4000000000})` skips
  the depth cap that CGQL enforces ([CG-110](CG-110.md)), and
  `graph.find_documents(c, {limit = 1e12})` skips the row budget
  (`bindings.rs:112-121`, `:182-203`).
- **Output.** `print` is still available and writes to the server's stdout.

The sandbox escape itself is [CG-104](CG-104.md).

## Acceptance

- [ ] Each script has a memory ceiling, and result, bind and document nesting are bounded.
- [ ] The typed bindings enforce the same depth and row limits as CGQL; `print` is removed or redirected to the response or log.
- [ ] `docs/architecture/lua.md` lists what is and is not limited, with tests for each bullet above.
