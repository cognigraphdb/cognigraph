# CG-134: Key expiry or revocation freezes a promotion channel and disables rollback

- Status: Open
- Priority: P2
- Area: Server / promotions; key lifecycle (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

Rollback revalidates, at the current time, that the prior evidence's policy
author and approver keys and every attestor key in its candidate and baseline
sets are active (`promotions/rollback.rs:153-173`,
`governance/queries.rs:142-178`: not expired, not revoked). New evidence
requires all four sources' attestation sets to be active now, and the baseline
set must byte-equal the head's set (`evidence_registration.rs:183-199`), so a
rotated key's re-attestation of identical bytes does not qualify.

Failure sequence: an attestor key is compromised and revoked, or simply
reaches `not_after_ms`. Rollback to the last known good state fails with
"governance key is revoked/inactive", because the prior evidence usually used
the same attestor. No new evidence can register on an M20+ target either. The
channel stays on the suspect head. On M19 targets, routine expiry of the
author or approver key alone disables rollback.

Tests cover only the refusal of promote and reject; no test or document
covers rollback or the next promotion after expiry or revocation.

## Acceptance

- [ ] It is decided and recorded whether rollback validates the prior evidence's authority as it was when accepted rather than as currently active, and the code follows.
- [ ] The way a channel continues after rotating a key bound into its head is defined.
- [ ] Tests cover rollback and next-evidence registration after expiry and after revocation.
