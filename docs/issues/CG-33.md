# CG-33: Native normalization changes opaque references in jobs and edges

- Status: Resolved
- Priority: P2
- Area: Stored identity and Unicode semantics
- Found: 2026-09-09 while implementing CG-13
- Reviewed revision: `41490db` plus the uncommitted CG-5 implementation
- Resolved: 2026-09-09 (committed locally as `9fb4933`)
- Verification: Old-binary reproduction, all Rust gates, and corrected release HTTP/restart/repair checks passed

## Problem

Native document keys and collection names retain their exact bytes, but recursive
NFC normalization changes ordinary string values, including opaque references.
A decomposed key such as `cafe\u0301` survives in `_key` and `_id`, while the same
key becomes `caf\u00e9` inside a durable job's `_execution.keys` and an edge's
`_from`. Those strings can reference a missing or different document.

The release reproduction submitted a side-view job for a decomposed key. The
persisted payload contained the composed key; the job succeeded with zero
side-views and zero provider calls. A relationship pointing to the same source
returned a composed `_from` that differed from the existing source `_id`.

## Evidence

- `crates/cognigraph-native/src/memory/helpers.rs` — `document_key` preserves the
  caller's key; `normalize_nfc` rewrites all string values; stamping restores the
  document's own exact `_key`/`_id` but leaves references normalized.
- `crates/cognigraph-server/src/jobs.rs` — `_execution` contains frozen source
  identifiers and is persisted through ordinary document stamping.
- [Sanitized release observation](evidence/unicode-reference-http-2026-09-09.json)
  records the exact differing identifiers and job outcome. No external provider
  was called.

## Interim boundary and scope

CG-13 rejects non-NFC side-view source collection names/keys before provider work,
preventing silent skips and generated references that cannot preserve identity.
That is a capability restriction, not a repair of the general identity contract.
CG-5 canonicalizes construction **evidence text** before hashes/spans; it does not
resolve opaque reference identity. Existing malformed references remain an
explicit repair concern.

## Acceptance criteria

- [x] Decide and document exact versus canonical identity semantics for document
  keys, collection names, graph endpoints, stored parent handles, and job payloads.
- [x] Apply the decision consistently without merging two distinct existing keys
  silently or rewriting signed/custodied data in place.
- [x] Provide a bounded diagnosis/repair path for existing invalid references and
  document any ambiguity that needs operator input.
- [x] Add resident/paged, embedded/sidecar, job restart, edge traversal, and
  composed/decomposed collision regressions, including the live cases above.

Run the repository Rust gates and focused release HTTP regressions before closure.

## Resolution

Native stamping and CGQL literal decoding now preserve exact Unicode values.
Canonically equivalent collection names and keys remain distinct; opaque graph
endpoints, parent handles, model names, and frozen job payloads keep their exact
contents. `NORMALIZE_NFC(value)` provides explicit canonical text comparison.
CG-5 construction evidence and governed canonicalization keep their explicit
boundaries. No existing keys or signed/custodied records are rewritten.

The bounded offline `references audit` command reports unresolved and ambiguous
known references, including cases with a wrong existing canonical target.
`references repair` requires explicit mappings and the exact snapshot SHA-256,
preserves all other JSON values/keys, refuses protected collections, and writes
a new private snapshot without overwrite or automatic import. Lost intent and
application-defined reference fields still require operator investigation.
See the [decision](../decisions/decision_exact_reference_identity.md) and
[repair procedure](../operations/reference-repair.md).

CG-13's temporary NFC-source restriction is lifted. The corrected release
passed 138 HTTP/Lua checks, six restarts including interrupted jobs, and three
repairs of snapshots created by the old binary, across all supported persistent
Native configurations. The baseline reproduced 69 mismatches. Side-view cascade,
generation-race, and canonical construction-evidence regressions also passed.
Formatting, strict Clippy, and all 945 reported Rust tests passed; eight Arango
integration entries early-returned without credentials. See the
[verification report and corrected initial attempts](exact-identity-2026-09-09.md).
