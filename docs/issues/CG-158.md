# CG-158: GET /api/documents returns the whole collection when limit is omitted

- Status: Open
- Priority: P3
- Area: Server / documents
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`crates/cognigraph-server/src/routes/documents.rs:54-74` passes an omitted
`limit` as `None`, which Native turns into `take(usize::MAX)`
(`crates/cognigraph-native/src/memory/documents.rs:371-378`). Every document,
embeddings included, is cloned under the state read lock. The response's
`count` is the page length; there is no total and no cursor, so a client
cannot tell a full page from the end of the collection.

`GET /api/documents?collection=embeddings` on a large collection builds a
multi-gigabyte response in memory. `POST /api/batch` has no operation cap
either, and its planning rescans the planned list per operation
(`memory/batch.rs:57-103`).

## Acceptance

- [ ] The list route has a documented default and maximum page size and returns a total or a next cursor.
- [ ] The batch route has a documented operation cap.
- [ ] Tests cover omitted, zero and over-maximum limits.
