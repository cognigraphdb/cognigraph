# CG-82: Enforce PR review and dependency freshness before develop integration

- Status: Resolved
- Priority: P1
- Area: CI and dependency policy
- Found: 2026-09-14
- Verification: Local implementation verified on 2026-09-14; GitHub activation pending qualified publication

## Problem and evidence

The owner requires processing incoming PRs, keeping dependencies current and
closing every vulnerability with an available fix before develop integration.
The previous hook accounted for PR heads, but the GitHub workflow did not repeat
that check before a UI merge. Cargo/Bun advisory scans did not prove dependency
freshness. A live dry-run offered 105 Cargo resolution changes while exiting zero;
six direct UI dependencies were also behind their published release channel.

## Implementation

- `dependency_freshness.py` checks all workspace direct dependencies, including
  optional/dev paths and local patches, and direct UI dependencies. It resolves
  fresh compatible transitive versions in a disposable copy. Missing data,
  changed inputs, resolver/registry errors and stale versions block qualification.
- An initially empty exception registry requires exact current/latest versions,
  rationale, a real engineering decision and UTC expiry. It cannot exempt a
  fixable vulnerability or compatible resolver drift.
- The hook and CI share PR dispositions, capture exact heads/targets/review/check
  metadata, reject outstanding changes requested on included PRs and recheck
  incoming work after source and image qualification. GitHub access stays read-only.
- [The develop gate](../operations/develop-gate.md), the
  [decision](../decisions/decision_develop_qualification.md), AGENTS.md and the release
  skill align the preparation, validation and final pre-merge sequence.
