# CG-133: M20–M23 promotion channels cannot advance after the server binary changes

- Status: Open
- Priority: P2
- Area: Server / promotions (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`same_construction_identity` (`promotions/comparison.rs:107-163`) requires the
baseline's whole five-slot attestation set to equal the current head
candidate's set, including scorer and verifier. The scorer subject embeds
`reproducibility.executable_digest` (`artifact_attestations.rs:1194-1205`),
and M21+ jobs must carry the startup-pinned executable digest
(`artifact_consumption/consume.rs:37-41`, `:455-461`). Candidate/baseline
comparability also requires equal digests and equal scorer/verifier bindings.

Failure sequence: promote A on an M22 channel, upgrade the binary, evaluate B.

- Re-running the baseline on the new binary yields new scorer and verifier
  attestations, so registration fails with "baseline construction identity
  does not match the current promoted evidence".
- Reusing A's old jobs as the baseline fails comparability, so `promote`
  records `blocked`.

The channel can never take another promotion. A fresh channel's first
promotion has no baseline constraint, so regression-versus-baseline resets at
every release. No document says an upgrade requires a new target, and no test
covers a changed digest.

## Acceptance

- [ ] Baseline identity against the head compares construction inputs only (candidate, construction configuration, corpus and graph bindings), or an explicit environment re-attestation path exists.
- [ ] A test makes a second promotion on an M21+ target after the pinned executable digest changes.
- [ ] A decision record states the upgrade rule.
