# CG-125: CGQL SORT does not use a total order, so rows with missing or mixed-type keys stay unsorted

- Status: Open
- Priority: P2
- Area: CGQL / SORT
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

The SORT comparator in `crates/cognigraph-query/src/executor/pipeline.rs:266-292`
returns `Equal` for any mixed-type pair, including null against a number, and
for arrays and objects. Null equals 1 and null equals 2 while 1 < 2, so the
relation is not transitive. `SORTED()` already has a proper type ladder
(`functions/value.rs:118-128`); the SORT clause does not use it.

Reproduced with three documents whose `score` is 3, missing and 1:
`FOR d IN docs SORT d.score RETURN d.score` returns `[3, null, 1]`.

`SORT d.score DESC LIMIT 10` over a collection where some documents lack
`score` therefore returns a wrong top ten that depends on input order. Rust's
`sort_by` may also panic on a comparator that is not a total order (plausible,
not reproduced). No test sorts a column with missing values.

## Acceptance

- [ ] SORT uses the same total order as `SORTED`.
- [ ] Corpus cases cover null, missing and mixed-type keys, ascending and descending, in both engines.
- [ ] The Sort section of `docs/reference/cgql.md` documents the ordering.
