# CG-152: issue.py allocates identifiers from the current branch only, so two branches get the same CG-N

- Status: Open
- Priority: P2
- Area: Workflow / issue registry
- Found: 2026-11-11
- Verification: Pending (observed on 2026-11-11: `issue.py next` on develop returned CG-103 while CG-103 existed on an unmerged ticket branch)

## Problem and evidence

`ids_in_git()` in `scripts/issue.py:77-88` runs
`git log --diff-filter=A -- docs/issues/` without `--all`, so only the
ancestry of HEAD counts. `original_title` (`:123-131`) has the same scope.
The repository instructions say allocation uses "committed history".
[CG-47](CG-47.md) fixed concurrency in one working tree and retitling on
HEAD; allocation across branches was not covered.

Observed during this review: [CG-103](CG-103.md) existed only on the unmerged
branch `ticket/cg-103-embedding-sidecar`, whose registry already said the next
identifier was CG-104. On `develop`, `issue.py next` returned CG-103 and
`issue.py check` passed. Registering a finding at that point would have
created a second, unrelated CG-103, and merging the branch would then have
forced a renumbering that the registry rules forbid.

Handled for this review by reserving CG-103 on `develop` with the branch's
title and file content before any new ticket was allocated.

## Acceptance

- [ ] Allocation considers every local and remote-tracking ref, and `check` fails when any ref holds a CG-N with a different original title.
- [ ] A regression test creates an issue on branch A, allocates on branch B and gets a different identifier.
- [ ] The repository instructions describe the cross-branch rule.
