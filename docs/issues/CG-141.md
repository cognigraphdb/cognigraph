# CG-141: A resumed construct.draft job can overwrite a newer draft with a truncated one marked complete

- Status: Open
- Priority: P2
- Area: Server / jobs (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

On a pass with `start > 0`, the draft worker resumes its accumulator only if
`space_type_drafts/{id}.drafting_job == job.id`
(`crates/cognigraph-server/src/jobs/worker.rs:502-541`). Otherwise it falls
through to `empty_per_document_draft` and continues from `start`. It then
replaces whatever is stored and, on the final pass, stamps `status: "draft"`
with `documents_drafted == documents_total` (`:573-622`). Nothing fails or
restarts from zero, and the "new spaces only" check runs only at submission
(`jobs/prepare.rs:154-165`).

Failure sequence:

1. Asynchronous draft A fails at document k (provider error).
2. A user runs the synchronous draft for the same id, which recreates the
   document without `drafting_job`. Another job, a manual delete or an edit
   has the same effect.
3. `POST /api/jobs/{A}/retry` in the default resume mode drafts documents
   k..N into an empty accumulator and overwrites the newer complete draft.
4. The job succeeds and the draft can be accepted with documents 0..k
   missing. If the intervening draft had been accepted, its acceptance record
   is overwritten as well.

## Acceptance

- [ ] A resumed pass with a missing or foreign accumulator fails closed or restarts from document 0.
- [ ] Execution re-checks the new-space rule and refuses to overwrite an accepted draft; synchronous and asynchronous drafting detect each other's accumulator.
- [ ] Tests cover resume after the accumulator is deleted, replaced by a synchronous draft, and replaced by another job.
