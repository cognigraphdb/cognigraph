# CG-170: Rule ingest writes fact edges to entities that were never declared

- Status: Open
- Priority: P3
- Area: Construct / validation; path parity
- Found: 2026-11-11
- Verification: Pending (source-confirmed in construct; Native's referential behaviour not executed)

## Problem and evidence

`ingest_chunks` derives a fact's `_from` and `_to` from the rule strings
(`crates/cognigraph-construct/src/ingest.rs:321-322`, `:363-368`) while
entity documents are inserted only from `config.entities`. There is no
existence check, and an empty sanitized key yields `entities/`. The
materialization path rejects the same configuration with
`MissingEntityDefinition` (`materialization.rs:576-585`). `validate_neurons`
checks neuron endpoints, but nothing validates a space type's own
`relation_rules`; draft accept only parses.

Failure case: an edited draft renames an entity but not the rule that
references it. Ingest succeeds and writes edges to a vertex that does not
exist, `evaluate` counts the fact as present, and a governed materialization
of the same inputs fails.

## Acceptance

- [ ] Ingest, or a shared space-type validator, rejects rules whose endpoints are not declared entities or sanitize to an empty key.
- [ ] A parity test runs this case through `ingest_chunks` and `derive_materialized_graph`.
