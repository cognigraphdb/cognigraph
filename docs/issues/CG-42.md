# CG-42: Collections deep links select the wrong document beyond page one

- Status: Resolved
- Priority: P2
- Area: UI / Collections navigation
- Found: 2026-09-10
- Verification: Live browser on the 2.6.1 candidate

## Problem

With 36 documents, opening `?doc=qa-page-34` clears the parameter and selects the
first record on page one. The requested document exists on page two. The list
effect only searches its loaded page; its periodic refresh can also overwrite a
search selection or reopen a closed inspector. In-flight reads have no stale
response guard when the query or collection changes.

## Acceptance

- [x] A direct link resolves an existing key outside the first page.
- [x] Search selection and paging survive background refresh.
- [x] Clearing search restores the first listing page; missing keys show no match.
- [x] Closing the inspector remains effective across refresh.
- [x] Superseded asynchronous reads cannot publish stale results.
- [x] UI checks and real browser regression pass.

## Resolution and verification

Resolved in the 2.6.1 candidate. The [Collections audit](../evidence/ui-2026-09-10-collections.md#artifact-088100ac46441b68bcc4)
records the implementation, live before/after observations, checks and explicit
coverage limits. No existing database or frozen experiment evidence was changed.
