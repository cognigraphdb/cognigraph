# CG-111: CGQL execution does not bound intermediate rows or value size, so budgets and the request timeout do not hold

- Status: Resolved
- Priority: P1
- Area: CGQL / executor budgets
- Found: 2026-11-11
- Verification: The three failure sequences were run against the Native backend in tests and over HTTP against a 2.7.53 release server with default settings; the query, Native and Lua test crates pass (315 tests), and the full suites run with the next commit of the batch
- Resolved: 2026-11-11

## Problem and evidence

The source-row and time budgets do not cover the work a query does after its
scans, and both default to unlimited.

- Nested `FOR` expansion allocates `rows × docs` environments with no charge
  and no deadline check (`crates/cognigraph-query/src/executor/run.rs:799-810`).
  A join on a non-string key falls back to the same full expansion per row
  (`:786-794`).
- The COLLECT and SORT loops in `executor/pipeline.rs` never check the
  deadline.
- Strings and arrays have no size ceiling (`functions/string.rs:62-74`,
  `functions/regex.rs:67`).
- Execution is synchronous inside the async handler, so the tower timeout
  cannot fire until it returns. `docs/reference/cgql.md:520-527` says the
  whole-request timeout remains the outer guard.

Failure sequences:

- `FOR a IN c FOR b IN c FOR d IN c RETURN 1` over 2,000 rows builds 8×10^9
  environments while charging 6,000 source rows.
- `FOR o IN orders FOR c IN customers FILTER o.customer_id == c.id RETURN 1`
  with numeric ids is a full cross product with document clones.
- `LET a = "0123456789" LET b = CONCAT(a,a,a,a,a,a,a,a,a,a) …` repeated 13
  times asks for 10^13 bytes from a 400-byte query.

The per-query stack limit is [CG-105](CG-105.md).

## Resolution

Two budgets are added and the time budget is on by default. The
[decision record](../decisions/decision_cgql_execution_budgets.md) has the
reasoning and the measured cost; the CGQL reference lists the units.

- **Intermediate rows** (`COGNIGRAPH_CGQL_MAX_INTERMEDIATE_ROWS`, default
  100,000,000): every `FOR` is charged the rows it produces, and `COLLECT`
  and `SORT` the rows they read. A cross product, including the non-string
  join fallback, is charged before it is allocated.
- **Memory** (`COGNIGRAPH_CGQL_MAX_MEMORY_BYTES`, default 1 GiB): an
  estimate of what the query builds and keeps. Expressions count what they
  read before copying it, so `CONCAT` chains, nested array literals and
  `REGEX_REPLACE` with a large replacement fail before the value exists.
- **Time** (`COGNIGRAPH_CGQL_TIME_BUDGET_MS`): unset, it is now the request
  timeout. The deadline is read per row in joins, `COLLECT`, `SORT` key
  evaluation and `DISTINCT`, and a `SORT` of more than 16,384 rows runs as
  sorted runs and stable merges so that it can stop.
- `ExecutionBudget::default()` carries the row and memory defaults, so
  internal callers and Lua `graph.query()` are covered.
  `ExecutionBudget::unlimited()` is explicit.
- The reference no longer says the request timeout guards a query. It says
  execution is synchronous and the time budget ends it.

Tests: `crates/cognigraph-native/tests/cgql_budgets.rs` runs the three
sequences. The triple `FOR` is refused by the row budget and, with nothing
configured, by the default memory budget. The numeric join is charged
40,200 rows against 400 for the string join. The thirteen-level `CONCAT`
query fails under a 1 MiB budget. Row totals are checked at the exact limit
and one below. Further cases: array literals, `REGEX_REPLACE`, repeated
string literals, `COLLECT ... INTO`, a subquery that returns its rows'
memory, a round repeated for `DOCUMENT()` lookups that is charged once, and
a join stopped by a 50 ms time budget. Unit tests cover the
meter's arithmetic and compare the interruptible sort with the standard
stable sort over ties, run boundaries and an expired deadline. A Lua test
shows `graph.query()` inherits both budgets, and a config test pins the
defaults.

Live check on the 2.7.53 release binary with default settings: see the
changelog record.

Not done: a query still holds a runtime worker until its budget ends
([CG-197](CG-197.md)); budget errors answer HTTP 500 like other execution
errors ([CG-198](CG-198.md)); `EXPLAIN ANALYZE` does not report the two new
counters. A stopped query still takes the time to free what it built, and a
single function call is not interrupted.

## Acceptance

- [x] Join expansion, COLLECT and SORT charge a row budget and check the deadline per row.
- [x] A per-value or per-query memory ceiling fails with a deterministic error, and the defaults are finite.
- [x] CPU-bound execution cannot outlive the request timeout, or the specification is corrected; tests cover the three sequences above.
