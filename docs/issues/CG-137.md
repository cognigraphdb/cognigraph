# CG-137: Blank aliases and whitespace-only or templated hint triggers pass neuron validation

- Status: Open
- Priority: P2
- Area: Construct / validation
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`validate_neurons` in `crates/cognigraph-construct/src/validate.rs` checks
`aliases.is_empty()` (`:125`) and `triggers.is_empty()` (`:144`) but not the
content of each element; blockers at `:166` do check for blank content.
Grounding then uses `contains`:

- An alias `""` makes `text_cf.contains("")` true, so the entity is
  "mentioned" in every chunk and `sentence_gate_accepts` passes for every
  sentence (`grounding.rs:168-178`, `grounding/triggers.rs:132-136`). Every
  rule gated with `require_in_sentence` on that entity grounds in off-subject
  sentences, and a MENTIONS edge is written for every chunk.
- A trigger `" "` is non-empty, so the fact grounds at the first non-negated
  space of every chunk.

`grounding/semantics.rs:34` does drop blank surfaces; the other paths do not.
The neuron create route uses only `validate_neurons`, and draft accept only
parse-validates, so an empty form field is enough.

A related contract gap: `docs/decisions/decision_grounding_gates.md` says
neurons cannot set or propose gates or templates, but hint triggers containing
`{source}` or `{target}` are accepted (`validate.rs:129-147`) and expanded
(`grounding.rs:98-101`, `:286-296`).

## Acceptance

- [ ] Validation rejects blank or whitespace-only aliases and triggers on every neuron kind, element by element.
- [ ] Grounding ignores blank surfaces and whitespace-only triggers defensively, because space types are not validated.
- [ ] Template placeholders in neuron triggers are rejected, or the decision record is amended; tests cover each case.
