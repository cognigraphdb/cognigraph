# CG-181: references repair guard list has drifted from the server, and its guide contradicts the import semantics

- Status: Open
- Priority: P3
- Area: CLI / reference repair; docs
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`protected()` in `crates/cognigraph-cli/src/references.rs:82-99` is commented
"Keep aligned with the public mutation guard" but lacks
`construction_refusals`, which [CG-90](CG-90.md) added to the server's
`GENERATED_COLLECTIONS` (`crates/cognigraph-server/src/system_collections.rs:45-63`)
and to the importer's server-owned list. The importer list has a drift test;
this one does not, and the guide's protected list omits the collection too. A
repair plan that targets `construction_refusals/<key>.document_id` is accepted
and written into the repaired snapshot.

`docs/operations/reference-repair.md` says "An import replaces snapshot
state" and "importing a partial snapshot can remove data".
`docs/operations/recovery.md` and
`crates/cognigraph-native/src/memory/mod.rs:373-433` show import is additive
and never deletes absent documents. An operator who follows the repair guide
expects a re-import to remove stale documents; it will not.

## Acceptance

- [ ] `protected()` derives from the server lists or is drift-tested against them.
- [ ] `reference-repair.md` states the additive semantics and the full protected list.
