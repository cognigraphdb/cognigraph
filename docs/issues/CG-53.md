# CG-53: Console actions ignore server edition and authenticated role capabilities

- Status: Open
- Priority: P2
- Area: UI / capabilities
- Found: 2026-09-11
- Verification: Source review, Community/Enterprise browser checks and 60 HTTP role probes

## Problem and evidence

The health response includes `edition`, but
[client.ts](../../ui/src/api/client.ts), lines 105–121, drops it. The
[sidebar](../../ui/src/components/Sidebar.tsx), lines 28–46, shows Review and
Construct in Community, and its Tenants gate checks only host-admin role.
Community cannot execute those Enterprise workflows. Most screen actions also
ignore the session's role: a viewer is offered document Edit/Save/Create and Lua
execution; host-admin sees tenant-data navigation it cannot use.

Live Community Review requests `/api/neurons` and receives 404 while rendering
an empty-space message. A viewer can enter the JSON editor and press Save;
the real API returns 403 and correctly preserves data. Enterprise host-admin
sees a false empty review queue after denied reads. See
[Community screen](../../ui/audit/2026-09-11-full-review/02-community-review.png)
and [role/edition API matrix](../../ui/audit/2026-09-11-full-review/role-api-matrix.json).

This finding concerns capability presentation, not an authorization bypass.
The concrete user-provisioning mismatch is tracked separately in CG-52, and
misleading empty/error handling in CG-58.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [ ] Propagate edition and supported capabilities into the UI, distinguishing unavailable features from empty data.
- [ ] Hide or explain controls unavailable to the current authenticated role, with an explicit policy for authentication-disabled development.
- [ ] Keep backend authorization and verify supported/denied flows for both editions and all supported roles, including direct routes.

## Follow-up from CG-52 — 2026-09-11

[Provisioning remediation](CG-52.md) now retains recognized edition metadata
from health and uses it to select creatable tenant roles. This is a prerequisite,
not closure of the broader navigation/action capability gap. The
[CG-52 verification](../../ui/audit/2026-09-11-provisioning/audit.md) also confirms
that new governance credentials work through HTTP login, while source inspection
shows that the current protected-catalog console gate cannot admit roles lacking
both data and tenant-catalog scopes. Include governance-role entry and an allowed
landing route when reconciling the shell and direct routes.
