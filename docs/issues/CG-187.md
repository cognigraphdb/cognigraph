# CG-187: Operator documents name the wrong derivative files and describe a superseded schema upgrade

- Status: Open
- Priority: P3
- Area: Docs / Native storage and recovery
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review)

## Problem and evidence

- **File names.** `docs/operations/recovery.md:30-33` and
  `deploy/helm/cognigraph/README.md:51` call the vector sidecar files
  `*.sidecar`. The real derivatives are `<db>.<identity>.vectors`,
  `.vectors.tmp` and `.tantivy/`
  (`crates/cognigraph-native/src/sidecar.rs:31`, `:104`).
  `docs/operations/authentication.md:160-161` has it right. An operator who
  excludes or deletes `*.sidecar` matches nothing.
- **Schema upgrade.** `docs/architecture/native-storage.md:132-139` and
  `docs/operations/authentication.md:184-190` describe only the 1 to 2
  upgrade ("changes the schema marker to 2", "schema-1 binaries reject
  upgraded databases"). The store is at schema 3
  (`crates/cognigraph-native/src/storage.rs:27`), and the 2 to 3 upgrade
  re-stamps `database_id` and `data_revision` (`:144-161`; confirmed by
  `decision_unique_indexes.md`). Any binary from v2.7.26 upgrades a schema-2
  file, older binaries then refuse it, and derivatives rebuild once under the
  new identity. The same guide calls the identity "immutable" (`:55`) and
  heads its table "version 3" (`:48`). The statement that a schema-2 store
  with a missing identity refuses to open now applies to schema 3; the test
  with "schema_two" in its name exercises schema 3.

## Acceptance

- [ ] `recovery.md` and the Helm README name `.vectors`, `.vectors.tmp` and `.tantivy/`, in the same words as the authentication guide.
- [ ] The upgrade and rollback text covers 2 to 3 (identity re-stamp, one derivative rebuild, rejection by older binaries), and "immutable" is qualified.
- [ ] `authentication.md` links the storage guide instead of restating a version.
