# CG-90: Construction gate refusals are not durably recorded

- Status: Open
- Priority: P2
- Area: Construct / directed
- Found: 2026-09-22
- Verification: Pending

## Problem and evidence

Refusing an unsupported fact is the product's central governance claim, and the
gate 3 baseline ([decision](../decisions/decision_gate3_baseline.md)) reports
the count of narrative candidates quarantined rather than asserted. At 2.7.15
the runtime does not keep an equivalent record for the request-time gates:

- `POST /api/construct/directed`
  (`crates/cognigraph-server/src/routes/construct/directed.rs`) returns
  `outcome.skips` in the HTTP response body only. The six gates in
  `gate_directed_proposals` (`crates/cognigraph-construct/src/directed.rs`)
  — relation in taxonomy, chunk in request, usable endpoints, verbatim quote,
  endpoints in the evidence window, affirmed `require_in_sentence` phrase —
  each produce a skip string that is discarded once the response is sent.
- `POST /api/construct/propose` returns `skipped[]` (paraphrased triggers,
  no candidate chunks) the same way.
- The only persisted refusal-adjacent artifact is the `fact_semantics`
  sidecar, which holds suspect rows flagged by the advisory detector, not gate
  refusals, and is a review aid rather than an audit record.

Consequences: an operator cannot answer "what did the gate refuse for this
space last week, and why" without having captured every response; the
`directed:<model>@directed-policy-v2` attribution exists on accepted facts but
there is no counterpart for refused nominations; and the refusal counts used in
evidence records cannot be regenerated from the database.

Confirmed from source; not reproduced live. Related in spirit to the M16
durable job audit, which records job outcomes but not per-nomination gate
verdicts.

## Scope and boundaries

- Refusals must not enter `facts`, `entities`, `mentions` or any collection
  that promotion, attestation or materialization consumes. A new generated
  collection (for example `construction_refusals`) alongside `side_views` and
  `fact_semantics` in `GENERATED_COLLECTIONS` keeps the boundary.
- Record the gate that refused, the policy revision, the model attribution,
  the nominated triple, the chunk id and the evidence quote as submitted. Do
  not store the full chunk text again; the chunk is already addressable.
- Per-tenant retention and size caps are required, as for durable jobs.
- Independent of [CG-88](CG-88.md) and [CG-89](CG-89.md).

## Acceptance

- [ ] Every skip returned by `/construct/directed` and `/construct/propose` is
      also written, in the same request, to a read-only generated collection
      with gate name, policy revision, attribution, triple, chunk id, evidence
      quote and timestamp.
- [ ] A read route or CGQL example in `docs/dataops/04-semantic-neurons.md`
      lists refusals per space and per gate, and a CLI export includes them.
- [ ] Regression test: a fixture nomination that fails each of the six
      directed gates produces exactly one refusal row per gate, and the write
      is skipped without error when the collection is at its cap.
- [ ] `system_collections.rs` tests prove the new collection is read-only
      through generic APIs and excluded from promotion and attestation.
- [ ] Retention is documented in `docs/operations/` with the tenant cap.
