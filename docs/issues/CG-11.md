# CG-11: Tenant recreation reuses the deleted tenant's text index

- Status: Resolved
- Priority: P1
- Area: Tenant storage lifecycle
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` (workspace 2.6.0)
- Verification: Live HTTP reproduction

## Problem

Tenant retirement quarantines redb and vector files but leaves `.tantivy` directories. Text-index warm loading validates only a numeric data-generation stamp. A new database at the same tenant filename can reach the same generation and reuse the old index, causing incorrect retrieval and retaining the prior tenant's searchable vocabulary.

## Evidence

- `crates/cognigraph-server/src/tenancy.rs:115-147` — retirement filename selection excludes Tantivy.
- `crates/cognigraph-native/src/text_index.rs:37-62` — warm-open identity is only the generation.
- `crates/cognigraph-native/src/memory/search.rs:190-226` — stable index filename across database incarnations.

## Reproduction / failure sequence

Create tenant `reviewtenant`, write `notes/same` with `oldvocabulary`, and search it. Delete and recreate that tenant, then write the same key with `newvocabulary`. The new term returned zero rows; the old term returned the new document. Retirement reported only the redb file quarantined. The old JWT correctly returned 401, so this is derivative reuse rather than token reuse.

## Acceptance criteria

- [x] Quarantine/remove every derivative belonging to a retired database, including text-index directories.
- [x] Bind persistent derivatives to an immutable database/tenant incarnation as well as generation.
- [x] Verify delete/recreate and backup/restore at a reused path cannot reopen unrelated derivatives.

## Resolution — 2026-09-08

Retirement quarantines text-index directories and unfinished vector files in
addition to the database and vector sidecars, including legacy filenames.
Native schema 2 adds an immutable database UUID and unique commit-revision
UUID. Persistent names bind database identity; warm text/vector validation
requires the exact revision, preventing reuse even after a divergent restore
with the same database UUID and numeric generation.

Database-replacement and backup-branch regressions failed before the fix and
now pass in both storage modes. Live upgrade/deletion/recreation/restart
checks preserved existing data, moved legacy and current derivatives, and
returned only new vocabulary/vectors for a recreated tenant. Formatting,
Clippy, and all 863 tests passed. See [verification and migration limits](derivative-isolation-2026-09-08.md).

Opening a schema-1 database upgrades its metadata atomically; older binaries
reject schema 2. General in-flight request incarnation pinning remains CG-12.

Run the repository Rust gates and a focused runtime regression before closing this issue. See [review evidence](review-2026-09-08.md).
