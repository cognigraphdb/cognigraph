# CG-136: Negation detection misses typographic apostrophes, non- prefixes and neither

- Status: Open
- Priority: P2
- Area: Construct / grounding gate
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

The tokenizer in `crates/cognigraph-construct/src/grounding/negation.rs:101-121`
builds tokens from ASCII alphanumerics and the ASCII apostrophe only, and
contractions are detected with `token.ends_with("n't")` (`:94-96`).

- A typographic apostrophe (U+2019) ends the token, so `didn’t` becomes
  `didn` and `t`, neither of which is a cue. NFC does not fold U+2019 and
  `preparation.rs` adds no compatibility normalization. This is the normal
  apostrophe in text from word processors, PDFs and the web.
- A hyphen ends the token, so `non-exclusive` yields `non`, which is not in
  `NEGATION_CUES` (`:3-18`). `neither` is missing as well.

Failure cases:

- Rule trigger `run the signal app`, chunk "The device didn’t run the Signal
  app build": the negated statement grounds the fact.
- Directed taxonomy with vocabulary `exclusiv` (the crate's own test
  taxonomy), sentence "Licensor grants Licensee a non-exclusive license": if
  the model nominates the exclusivity relation, the vocabulary gate in
  `directed/gates.rs:188-190` passes.

The only contraction test uses an ASCII apostrophe.

## Acceptance

- [ ] U+2019 and U+02BC contractions are treated like ASCII `n't`.
- [ ] `non-`-prefixed vocabulary and `neither` do not affirm, with regression tests on the rule path and the directed path.
- [ ] The grounding decision record states which negation forms are and are not covered; kit baselines are re-measured.
