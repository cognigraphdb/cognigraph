# CG-70: Track transitive dependency safety and maintenance advisories

- Status: Resolved
- Priority: P2
- Area: Dependencies
- Found: 2026-09-12
- Verification: cargo-audit and all-feature/target reverse dependency inventory

## Problem and evidence

The initial CI setup audit reported two RustSec informational advisories:

- [RUSTSEC-2026-0253](https://rustsec.org/advisories/RUSTSEC-2026-0253.html):
  `lru` 0.16.4, reached through Tantivy 0.26.1 in Native storage. The advisory
  describes panic-safety unsoundness in `pop()` with panicking key destructors
  and caught unwinds; it is fixed from 0.18.2. CogniGraph's direct cache already
  uses lru 0.18.4. Tantivy's latest published 0.26.2 still requires `^0.16.3`,
  so changing the lockfile alone cannot move that dependency to the fixed line.
  This inventory does not establish application-level exploitability.
- [RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html):
  unmaintained `paste` 1.0.15 through optional ONNX `tokenizers` and
  `macro_rules_attribute`. The optional package remains in Cargo.lock even
  though normal Community/Enterprise CI does not build ONNX.

At discovery, `cargo audit` retained these warnings under its default policy.
No advisory ID was ignored. The initial CI gate failed vulnerability errors
and unavailable scans. The resolution below strengthens that policy without
claiming an advisory-free dependency tree.

## Acceptance

- [x] Resolve the transitive lru advisory through a reviewed upstream change or bounded patch; verify Native text-index behavior and Rust suites.
- [x] Resolve or document a reviewed maintenance strategy for optional ONNX paste usage.
- [x] Record a fresh all-feature/target dependency inventory and advisory scan without rewriting historical captures.

## Resolution — 2026-09-12

The [dependency decision](../decisions/decision_dependency_advisories.md) records
both the correction and the accepted optional ONNX maintenance strategy.

- Backport [upstream Tantivy commit 5ca3933](https://github.com/quickwit-oss/tantivy/commit/5ca39332002c2c87fb5d2abc707cf527b3319d42):
  the sole source-package change is `lru ^0.16.3` → `^0.18.2` in the normalized
  manifest. The root lockfile selects lru 0.18.4 for Native and the direct cache.
  No Tantivy Rust code or storage format changes. The inspected upstream cache
  uses integer keys and get/put, not the advisory's panicking key/pop path;
  resolution nevertheless removes the affected package.
- Preserve the checksummed Tantivy 0.26.1 release and MIT license in the
  [bounded snapshot](../../vendor/README.md). CI checks 372 published file hashes
  after reversing exactly the allowed manifest change. Negative controls reject
  a restored unsafe requirement, changed source, an added file and a missing
  license. Docker builds use the snapshot and include its exact MIT notice.
- Use `cargo audit --deny unsound` in shared CI. A negative control confirms that
  the pre-fix lockfile fails on RUSTSEC-2026-0253. The corrected lockfile passes
  with **zero vulnerabilities, no unsound warning and one unmaintained warning**.
- Retain paste 1.0.15 only under the documented optional ONNX maintenance
  decision. It remains in Cargo.lock and all-feature builds; it is absent from
  standard Community/Enterprise server dependency trees. Its warning is visible
  and not described as fixed. Review before any ONNX/tokenizer dependency change,
  first ONNX-enabled distribution, or by **2026-10-12**, whichever comes first.
  No new ONNX default or provider policy is introduced.

## Verification

The [dated inventory and captures](../evidence/engineering-cg-70-2026-09-12.md#artifact-1ffb745721291f30ee83) include
all-feature/target and both server dependency lists, reverse paths, before/after
audit results, candidate hashes and a [verification summary](../evidence/engineering-cg-70-2026-09-12.md#artifact-2fac090cf33ee1179263).

- `python3 scripts/verify.py --suite ci` passed on Rust 1.98.1: formatting,
  strict Clippy and **723 Community / 914 Enterprise Rust tests**, 72 Python
  regressions, 161 UI tests, UI build/checks, workflow/advisory/docs/issue/edition/
  modularity gates, Helm rendering and all **nine** real-browser regressions.
  Two external-provider tests per edition were intentionally ignored.
- The new `tantivy_cache` regression exercises the real stored-document cache
  with separate blocks and a two-entry capacity: hits, promotion, eviction,
  exact document readback and index reopen. Existing Native tests retain BM25
  ranking, multilingual tokenization, persistent reopen and index invalidation.
- Fresh release binaries passed **514 HTTP checks and 12 startup rejections**
  across memory, resident/embedded, resident/sidecar and paged/sidecar modes.
  Captures are in `target/ci/native/run-ka7ccwzu`; binary hashes are retained in
  the summary. The existing CG-68 readiness protocol was reused unchanged.
- `DOCKER_DEFAULT_PLATFORM=linux/amd64 python3 scripts/verify.py --suite docker`
  passed both image builds, packaged authentication/CLI/CGQL/persistence/restart
  checks and both live Helm private-backup/owner/non-owner checks. Both build
  logs show lru 0.18.4; the packaged Tantivy license matches the snapshot bytes.
- Optional ONNX strict Clippy and
  `cargo test --locked -p cognigraph-embeddings --features onnx` passed: 20 existing
  unit tests, two hosted-provider tests ignored. This is compilation/unit
  evidence; no ONNX model inference, hosted provider or research holdout ran.

This resolves the issue's safety fix and maintenance-strategy acceptance criteria.
The captures qualify the local pre-publication candidate. Subsequent remote CI,
source publication and deployment belong to their own release records; none is
claimed by this local checkpoint.
