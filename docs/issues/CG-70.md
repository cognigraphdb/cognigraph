# CG-70: Track transitive dependency safety and maintenance advisories

- Status: Open
- Priority: P2
- Area: Dependencies
- Found: 2026-09-12
- Verification: cargo-audit and all-feature/target reverse dependency inventory

## Problem and evidence

The CI setup audit reports two RustSec informational advisories:

- [RUSTSEC-2026-0253](https://rustsec.org/advisories/RUSTSEC-2026-0253.html):
  `lru` 0.16.4, reached through Tantivy 0.26.1 in Native storage. The advisory
  describes panic-safety unsoundness in `pop()` with panicking key destructors
  and caught unwinds; it is fixed from 0.18.2. CogniGraph's direct cache already
  uses lru 0.18.4. Tantivy's latest published 0.26.2 still requires `^0.16.3`,
  so changing the lockfile alone cannot move that dependency to the fixed line.
  This inventory does not establish application-level exploitability.
- [RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html):
  unmaintained `paste` 1.0.15 through optional ONNX `tokenizers` and
  `macro_rules_attribute`. The optional package remains in Cargo.lock even
  though normal Community/Enterprise CI does not build ONNX.

`cargo audit` retains these warnings under its default policy. No advisory ID
is ignored. The CI gate fails vulnerability errors and unavailable scans;
passing that gate is not a claim of an advisory-free dependency tree.

## Acceptance

- [ ] Resolve the transitive lru advisory through a reviewed upstream change or bounded patch; verify Native text-index behavior and Rust suites.
- [ ] Resolve or document a reviewed maintenance strategy for optional ONNX paste usage.
- [ ] Record a fresh all-feature/target dependency inventory and advisory scan without rewriting historical captures.
