# CG-73: Route dependency updates through develop and retire stale branches

- Status: Open
- Priority: P2
- Area: CI / repository workflow
- Found: 2026-09-13
- Verification: Full local CI, Docker and optional ONNX passed for v2.7.8; remote transition pending

## Problem and evidence

Six Dependabot PRs (#2–#7) targeted main. There was no Renovate configuration or
remote develop branch, and old local/remote topic branches remained. The owner
requested processing incoming work, replacing Dependabot with Renovate, targeting
develop and retaining only main/develop and the primary worktree after cleanup.

Three upstream candidates failed CI: #3 retained duplicate CodeMirror view
versions, #4 paired React DOM 19.3.0 with React 19.2.7, and #5 updated quick-xml's
byte-oriented API without adapting its callers. The other PRs passed their
standard CI but optional tokenizer and integration coverage remained necessary.

## Resolution

The [decision](../decisions/decision_develop_integration.md) establishes develop
integration and separate main promotion. All six exact heads in the
[disposition ledger](../operations/pr-dispositions.json) are merged locally.
The combined candidate aligns React/React DOM, deduplicates CodeMirror, migrates
six XML readers and adds UTF-8/CDATA/malformed XML and offline BPE regressions.
It includes the pending CG-72 phone-login fix and CG-71 deployment evidence.

Renovate's checked configuration targets only develop, groups React/CodeMirror,
excludes vendor files and disables automerge. CI covers both branches and
executes a tested guard against dependency PRs targeting main. The intended
remote settings preserve vulnerability alerts while disabling Dependabot's
automatic security-update PRs. Actual remote activation is tracked below.
