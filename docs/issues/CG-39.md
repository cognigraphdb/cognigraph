# CG-39: Directed endpoint checks accept names embedded inside longer words

- Status: Resolved
- Priority: P2
- Area: Directed construction / evidence integrity
- Found: 2026-09-09
- Reviewed revision: `b9a97f9`
- Verification: Live release HTTP reproduction with a synthetic provider; observed in the document trial

## Problem

Directed endpoint validation uses unrestricted substring matching. A nominated
entity can be absent as a complete name but still be accepted because its bytes
occur inside another word. That can persist a fact about an entity not actually
named by the evidence.

## Evidence

- `crates/cognigraph-construct/src/directed.rs:94` — `find_loose` scans matching
  bytes without checking boundaries around the match.
- `crates/cognigraph-construct/src/directed.rs:208` and `:214` — the same helper
  decides whether the source and target occur in the evidence window.
- The [release reproduction](evidence/directed-document-contracts-2026-09-09.json)
  returned HTTP 200 and stored `Ann OWNS Acme` for the complete quoted sentence
  `Joanne owns Acme.` The source `Ann` exists only inside `Joanne`.
- The positive control `Ann owns Acme.` also stored one fact, confirming that
  the issue is endpoint boundaries rather than general request failure.
- The [Luna document trial](../../fixtures/semantic-neurons/luna-documents-2026-09-09/results.md)
  accepted a `South Africa` endpoint from text containing `South African`,
  independently motivating the minimal reproduction.

## Acceptance criteria

- [x] Require appropriate complete-token boundaries for source and target
  occurrence checks, with an explicit Unicode-aware policy.
- [x] Preserve the existing NFC, whitespace and quoted-evidence byte-span
  behavior; keep quote lookup separate from entity-boundary validation.
- [x] Reject `Ann` inside `Joanne` and word prefixes such as `South Africa`
  inside `South African`, for both source and target positions.
- [x] Cover legitimate punctuation, multi-word names, repeated mentions and
  non-ASCII names without relaxing evidence requirements.
- [x] Pass Rust gates and a focused release HTTP regression before closing.

The current evidence proves acceptance of an invalid endpoint boundary. It does
not prove that boundary checks alone establish semantic truth or complete
entity resolution. Preserve the frozen development captures and unrun holdout.

## Resolution — 2026-09-09

Policy v2 checks Unicode word characters on both sides of an endpoint match,
continues past an invalid substring to later complete mentions, and leaves quote
lookup untouched. The [contract decision](../decisions/decision_directed_extraction_contracts.md)
defines punctuation, Unicode and the existing construction-key limitations.
The [release HTTP matrix](evidence/directed-contract-fixes-2026-09-09.json)
passed 34 cases across OpenAI and Gemini, including source/target prefixes,
positive controls, repeated mentions and NFC byte spans. Formatting, strict
Clippy and all 967 reported Rust tests passed; eight Arango integration entries
returned early because the test process lacked `ARANGO_PASSWORD`.

The separately frozen [development replay](../../fixtures/semantic-neurons/luna-directed-v2-2026-09-09/replay-validation.json)
sent the original 55 proposals through the corrected release gates with no model
calls. It removed exactly the `South Africa` occurrence matched inside `South
African`, reducing stored occurrences from 32 to 31 while retaining all 16
published-reference matches. The original package and holdout remain unchanged.
