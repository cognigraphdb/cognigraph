# CG-115: Configuration parsing fails open: unrecognised values silently become the unsafe default

- Status: Open
- Priority: P2
- Area: Server / configuration
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

`crates/cognigraph-server/src/config.rs` reads booleans as
`env(..) == "true"`, numbers as `.parse().unwrap_or(default)`, and falls
through `_ =>` for unknown `COGNIGRAPH_VECTOR_MODE` and
`COGNIGRAPH_STORAGE_MODE` values. `CacheConfig::from_env`
(`crates/cognigraph-cache/src/types.rs:34-54`) does the same and does not
check ranges. The file's own comment calls set-but-ignored configuration "the
worst failure mode".

Reproduced: with `COGNIGRAPH_AUTH_ENABLED=True` the server starts without the
"Auth enabled" log line and an unauthenticated `POST /api/documents` returns
200. With `true` the same request returns 401. The same run accepted
`COGNIGRAPH_RATE_LIMIT_PER_MINUTE=100/min` and `COGNIGRAPH_STORAGE_MODE=Paged`
without a warning.

Other values that turn a control off: `COGNIGRAPH_TOKEN_TTL_SECS=90d`
(tokens never expire), `COGNIGRAPH_CGQL_TIME_BUDGET_MS=5s`,
`COGNIGRAPH_CGQL_MAX_SOURCE_ROWS=10k`, `COGNIGRAPH_LUA_INSTRUCTION_LIMIT=1e6`.

## Acceptance

- [ ] An unrecognised boolean, enum or numeric value fails startup and names the variable; cache settings validate their ranges.
- [ ] `docs/operations/configuration.md` lists the accepted spellings.
- [ ] Unit tests cover the reject path of each parser, and a live check starts the binary with `COGNIGRAPH_AUTH_ENABLED=True` and expects a refusal.
