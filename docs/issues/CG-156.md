# CG-156: HTTP reference omits implemented routes and does not mark Enterprise-only groups

- Status: Open
- Priority: P2
- Area: Docs / HTTP API reference
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review)

## Problem and evidence

`docs/reference/http-api.md` is checked by nothing. The `openapi_drift` tests
compare `crates/cognigraph-server/openapi.yaml` with the router, and
`scripts/check-docs.py` validates links only. The OpenAPI file is correct
(all 99 paths match the router); the reference has drifted.

**Missing routes** (all present in `openapi.yaml`):

- `GET` and `POST /api/semantic-repairs/generations`,
  `GET /api/semantic-repairs/generations/{id}`,
  `POST /api/semantic-repairs/generations/{id}/deploy` and
  `GET /api/semantic-repairs/deployments/current/{space_type}`. The reference
  never mentions M26 and its narrative ends at M25.
- `GET /api/auth/session`, `POST /api/tenants/{name}/admin` and
  `GET /health/promotions`, which appear only in the operations guides.

**No edition marking.** `crates/cognigraph-server/src/main.rs:573-615` mounts
`/jobs`, `/promotions`, `/governance`, `/semantic-repairs`, `/neurons`,
`/construct` and `/sideviews` only with the `enterprise` feature. Roughly 70
documented endpoints do not exist in the default Community build, where
governed routes return 404 and tenant lifecycle returns 403
`enterprise_feature_required` (`docs/operations/running.md`). The section
headings carry scopes but no edition.

## Acceptance

- [ ] Every method and path in `openapi.yaml` appears in the reference with its required role, including an M26 section or a link to its runbook.
- [ ] Each section or row states Community or Enterprise, consistent with `edition_paths.rs`, and the Community failure mode is stated once.
- [ ] A script or test fails when the reference and the OpenAPI path set diverge.
