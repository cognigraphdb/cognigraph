# CG-153: Helm backup job captures only the default tenant in multi-tenant mode and leaves partial files behind

- Status: Open
- Priority: P2
- Area: Deploy / Helm backup
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

**Multi-tenant coverage.** The backup CronJob logs in as the fixed user
`admin` and calls `GET /api/admin/export`
(`deploy/helm/cognigraph/files/backup.py:29-41`). That handler exports
`state.backend`, which in multi-tenant mode is the caller's tenant store only
(`crates/cognigraph-server/src/routes/admin.rs:172-178`, `tenancy.rs:172-186`).
The route requires the tenant Admin role, so the host admin cannot export
either. The chart renders `backup.enabled=true` together with
`enterprise.multiTenant=true` without failing or warning, and
`scripts/check-helm.py` only renders that combination; its live Enterprise
backup run is single-tenant.

Failure sequence: an Enterprise operator enables both values. Nightly jobs
succeed and print "wrote … bytes". After volume loss only the default tenant
can be restored; the other tenants' stores and the control store were never
captured.

**Partial files.** The export is streamed to a `.partial` temporary file and
then loaded whole with `json.load` for validation under a 256Mi limit
(`backup.py:42-57`, `values.yaml:128-130`). Cleanup is in a `finally` block,
which does not run on an out-of-memory kill or eviction. Retention only
matches `cognigraph-*.json`. Once the decoded snapshot exceeds the limit, each
attempt (three per night with `backoffLimit: 2`) leaves a full-size partial
until the backup volume fills.

## Acceptance

- [ ] The chart refuses `backup.enabled` with `enterprise.multiTenant` and points to a documented alternative, or the job backs up every tenant and the control store.
- [ ] The chart README and NOTES state what a backup contains in each mode; the live Enterprise Helm check covers a second tenant or asserts the refusal.
- [ ] Each run removes stale `*.partial` files first, and validation does not need the whole decoded snapshot in memory.
