# CG-77: Enforce the public evidence boundary in CI and agent workflows

- Status: Resolved
- Priority: P2
- Area: CI / Repository

- Verification: Distribution guard and seven policy regressions implemented; full CI and Docker suites passed without a private evidence sibling.

## Problem and evidence

Current agent instructions direct raw audit output into the code repository.
Research examples also default to tracked fixture directories. A one-time file
move will be undone by later routine work unless these writers and the
publication checks enforce the new boundary.

Public CI currently loads an acceptance protocol and modularity exception
configuration from the issue-evidence directory. Those executable/public inputs
must remain available after [CG-75](CG-75.md). Private research execution must
require an explicit evidence path and must not silently replace missing inputs
with a skipped public acceptance result.

- [x] Integrate the policy with the shared local/CI and push workflows; use precise exceptions for intentional synthetic fixtures.
- [x] Update root/UI agent instructions and canonical QA/research writers to separate private captures from sanitized public summaries.
- [x] Prove the public gates pass from a checkout with no evidence sibling; preserve real test execution and report optional private research separately.
