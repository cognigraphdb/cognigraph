# CG-93: Move CI runners from pinned Ubuntu 24.04 to Ubuntu 26.04 deliberately

- Status: Open
- Priority: P3
- Area: CI / tooling
- Found: 2026-09-22
- Verification: Pending
- Scheduling: Owner decision; the pinned `ubuntu-24.04` label remains supported by GitHub well past the alias migration window, so there is no deadline before the image itself is deprecated

## Problem and evidence

GitHub is migrating the `ubuntu-latest` label to Ubuntu 26.04 between
2026-10-19 and 2026-11-19 (actions/runner-images issue 14748). The
[v2.7.20 record](../changelog/2026-09-22-pin-ci-runner-image.md) pins the
three jobs in `.github/workflows/ci.yml` to `ubuntu-24.04` so the runner does
not change underneath a qualified candidate and the migration warning stops.

The move to 26.04 still has to happen, and it should happen as a reviewed
change with the usual gates rather than by alias drift. The published
software difference table lists a new kernel and systemd generation; the
Docker Buildx, Bun and Python versions our jobs use are not called out as
changing, but the container startup checks, the Trivy scan and the Helm live
checks all depend on runner-side Docker behavior that is worth re-verifying.

Renovate's `github-actions` manager keeps action SHAs current but does not
propose runner-label changes, so this ticket is the only reminder.

## Acceptance

- [ ] A pull request switches every `runs-on` in `.github/workflows/ci.yml`
      to `ubuntu-26.04`, and the source CI, Docker and required-check jobs
      pass on that image for both editions.
- [ ] Any runner-side difference that needed a workflow or script change is
      recorded in the change record, with the runner-images issue cited.
- [ ] `docs/operations/ui-testing.md` and the
      [CI guide](../operations/ci.md) name the new pinned image.
- [ ] The sibling website repository's workflow is moved in the same
      window, since it was pinned for the same reason.
