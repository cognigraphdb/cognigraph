# CG-130: Swallowed read errors in graduation, review and search hydration produce wrong output with status 200

- Status: Open
- Priority: P2
- Area: Server / neuron lifecycle; search
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

Several handlers replace a failed backend read with an empty value:

- `crates/cognigraph-server/src/routes/neurons.rs:137-141`, `:224-271`
  (list and graduation) and `routes/construct/review.rs:106-137`, `:195-200`
  use `.unwrap_or_default()` on the chunk and neuron reads and
  `filter_map(...ok())` on parsing. `load_accepted` was hardened for exactly
  this in [CG-21](CG-21.md); these paths were not.
- Search hydration in `routes/search/hybrid.rs:278`, `semantic.rs` and
  `graph_augmented.rs` uses `.ok().flatten()` and returns `document: null`.
  [CG-16](CG-16.md) fixed the same pattern for the query path only.

Failure sequences:

- A chunk read fails. `GET /api/neurons/graduation` returns 200 and flags
  every accepted blocker as `inert_blocker` with the advice to retire it,
  because with zero chunks no fact grounds without the blocker. A reviewer who
  follows the report removes the vetoes.
- The same failure during `/api/construct/review` stamps verdicts based on "no
  matching chunks" onto the whole queue. Judged proposals are skipped on later
  runs unless `rejudge` is set. (The verdict direction is plausible, not
  executed.)
- A failed neuron list returns an empty review queue with 200.

Graduation also reads all chunks unbounded and runs leave-one-out grounding
synchronously in the async handler, with graph-read scope.

## Acceptance

- [ ] Backend and parse errors propagate; only "collection not found" maps to empty.
- [ ] Graduation and review refuse to run on a failed or partial corpus read; neuron listing has a default and a maximum limit.
- [ ] Tests inject read failures into the three neuron routes and into search hydration.
