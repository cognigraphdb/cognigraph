# CG-172: Neuron transitions accept any source state and keep a single overwritten audit slot

- Status: Open
- Priority: P3
- Area: Server / neuron lifecycle (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)
- Scheduling: Needs an owner decision on the transition table before implementation.

## Problem and evidence

`transition` in `crates/cognigraph-server/src/routes/neurons.rs:162-209`
never reads the current status. Rejected to accepted, retired to accepted,
proposed to retired and accepted to accepted all succeed. Each overwrites
`reviewed_by` and `reviewed_at`, while `review_note`, `lane` and the judge
fields persist from earlier decisions. `docs/dataops/04-semantic-neurons.md`
describes proposed to accepted or rejected, and later retired.

Examples: one reviewer accepts with a note and another retires without one;
the record then shows the second reviewer next to the first one's note, and
who accepted is lost. Re-posting `accept` on a neuron the judge accepted
automatically replaces the judge attribution with a human name while
`lane: "A"` remains.

Whether re-acceptance is intended is not documented, and an existing test
pins the note retention.

## Acceptance

- [ ] A decided transition table rejects no-op and undocumented moves, or re-acceptance is documented explicitly.
- [ ] Transitions append to a history (actor, from, to, note, time), as jobs already do.
- [ ] Tests cover each illegal and repeated transition.
