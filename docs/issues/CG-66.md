## Problem and evidence

The existing [CLI import command](../../crates/cognigraph-cli/src/main.rs) reads
a whole CogniGraph JSON snapshot and posts it to `/api/admin/import`. It cannot
read Arango structure/data files, and the application import API is additive.
An offline dump converter would be a separate future feature under the
[Native-only decision](../decisions/decision_native_only.md).

Source inspection at 2.7.1 (`efe9839`) confirms the feature gap; no dump import
has been executed. The [deferred design](../plans/arangodump-import-design.md)
must be qualified by CG-64 before implementation starts.

## Scope and dependencies

The owner's 2026-09-12 clarification removes this ticket from the active batch:
there are no existing CogniGraph users to migrate. Reconsider it only after
Native-only readiness and explicit reprioritization. It depends on
[CG-64](CG-64.md) if resumed and does not block CG-67, CG-68 or first deployment.

For that optional feature, add the Community offline dump mode to
`cognigraph import`; keep ordinary snapshot import compatible.
Use Native storage directly, without the Arango adapter, a running server or
provider calls. Preserve crate modularity instead of growing the existing CLI
entry point into a dump parser.

Implement bounded parsing/staging, dry run, identity/reference/metadata checks,
safe publication to an absent destination and a machine-readable report. Import
user graph data only; do not synthesize credentials, jobs or signed authority.
External source-state limits must be defined by CG-64 before promising support.

## Acceptance

- [ ] Both editions expose the qualified CLI mode; Community can use it offline and existing HTTP snapshot import retains its behavior.
- [ ] Qualified fixtures import with exact accepted keys, edge references, collection types and user JSON values; empty collections and explicit metadata dispositions appear in the report.
- [ ] Dry run performs no destination creation/network calls. Unsupported/corrupt layouts, incompatible names, ambiguous duplicates and unresolved edges fail clearly without source changes.
- [ ] Bounded processing handles a generated multi-file/large fixture without constructing the entire dump in one JSON value; configured limits and source-fingerprint checks are exercised.
- [ ] Existing destinations and unsafe paths are refused. Injected parse/write/report failures and process interruption cannot overwrite existing data or expose a partially imported final store; report/retry behavior is unambiguous after publication.
- [ ] A real imported store passes authenticated HTTP/CGQL/traversal readback and restart checks, with synthetic search data and supported Native storage modes. New auth setup is verified separately from source data transfer.
- [ ] Record importer/source versions, fixture hashes, counts and failure evidence; pass focused tests, required Rust gates, edition checks and relevant docs/example validation.

## Verification and resolution

Resolved 2026-09-23 in v2.7.31 under the
[importer decision](../decisions/decision_arangodump_importer.md):
`cognigraph import --from-arangodump DIR --output STORE [--dry-run] [--report FILE]`
implements the [contract](../reference/arangodump-import.md) in both editions,
offline. Native gains a verbatim `bulk_insert` because the ordinary write
path stamps timestamps and edge defaults; the reference reader now checks
unique constraints inline so a streaming importer reports the same first
problem in file order.

- [x] Both editions expose the offline mode; `cognigraph import SNAPSHOT` is unchanged (argument tests).
- [x] All accepted fixtures publish exact keys, edges, collection types (including empty collections) and JSON values; dispositions appear in the report (fixture parity tests).
- [x] The dry run creates nothing at or beside the destination; unsupported, corrupt, incompatible, duplicate and unresolved inputs fail with contract codes and leave the source untouched.
- [x] A generated 5,000-document split gzip dump and a 400,000-document dump stream in chunks; record, expansion and file-count limits and source re-verification are exercised.
- [x] Existing destinations and paths inside the dump are refused; injected failures before publication, a changed source and a SIGKILL mid-import never expose a store; a failed report after publication exits 5 with a complete store and a retry is refused.
- [x] Imported stores pass authenticated HTTP, CGQL, traversal and constraint readback before and after restart in resident-embedded, resident-sidecar and paged-sidecar modes in both editions; the server creates new credentials.
- [x] Importer version, source hashes, counts and failure evidence are in the reports; a private real-dump acceptance is sealed outside the public repository.
