# CG-41: Background refresh discards unsaved document edits

- Status: Resolved
- Priority: P1
- Area: UI / Collections editor
- Found: 2026-09-10
- Verification: Live browser reproduction on the 2.6.1 candidate

## Problem and evidence

Open Collections, edit a document and leave an unsaved marker. The 15-second
health cycle refreshes the document object and the inspector effect exits edit
mode, discarding the draft. Screenshots before and after the refresh are retained
in the [Collections audit](../../ui/audit/2026-09-10-collections/).

Source review also found that Save exited edit mode before the asynchronous PATCH
completed, hiding recoverable input on failure. Successful edits assigned a fixed
July timestamp, and Metadata named every collection `documents`.

## Acceptance

- [x] Background refresh preserves an in-progress draft for the same document.
- [x] Selecting another document resets the draft without transferring edits.
- [x] Invalid JSON and failed PATCH requests retain the editor and useful errors.
- [x] Successful saves use a current timestamp and survive reload.
- [x] Cancel discards only the local draft; Metadata names the actual collection.
- [x] UI checks and the real browser regression pass.

## Resolution and verification

Resolved in the 2.6.1 candidate. The [Collections audit](../../ui/audit/2026-09-10-collections/audit.md)
records the implementation, live before/after observations, checks and explicit
coverage limits. No existing database or frozen experiment evidence was changed.
