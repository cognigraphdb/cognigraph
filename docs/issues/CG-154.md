# CG-154: Helm chart defaults point at images that do not exist, and serveConsole=false has no effect

- Status: Open
- Priority: P2
- Area: Deploy / Helm chart
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

**Image defaults.** `Chart.yaml` has `appVersion: "2.7.1"` against workspace
version 2.7.39, and `values.yaml` has `repository: cognigraph` with a tag that
defaults to `appVersion` or `appVersion-enterprise`. The defaults render
`cognigraph:2.7.1` and `cognigraph:2.7.1-enterprise`. The published names are
`cognigraph/cognigraph:<version>` and a separate
`cognigraph/cognigraph-enterprise` repository (`scripts/docker_images.py`),
and the immutable-tag rule has no `-enterprise` suffix. Nothing ties
`appVersion` to the workspace version.

- The chart README's install command ends in ImagePullBackOff.
- Setting only the repository pulls 2.7.1, which per
  `docs/operations/docker-publishing.md` was never published.
- NOTES always prints "CogniGraph 2.7.1 is deploying".
- `LICENSING.md` and the chart README say `edition` "selects the matching
  image tag"; the publishing guide says the defaults do not select the new
  repositories.
- The publishing guide recommends deploying by digest, but the chart copies
  the tag into the `app.kubernetes.io/version` label, so a `tag@sha256:…`
  value produces an invalid label.

**Console.** The image sets `COGNIGRAPH_UI_DIST=/ui` (`Dockerfile:52`). The
chart only adds the variable when `server.serveConsole` is true and never
clears it, so with the default `false` the console and its fallback (HTML 200
for any non-API path) are still served.

Also noted: the ServiceMonitor selector matches both Services, so each pod is
scraped twice, and the image HEALTHCHECK hard-codes port 3000.

## Acceptance

- [ ] Default repository and tag resolve to the published image for each edition, and a gate fails when `appVersion` differs from the workspace version.
- [ ] The chart accepts an image digest without producing invalid labels, and `serveConsole=false` yields a pod where `GET /` is not the console; the live Helm check asserts both.
- [ ] `LICENSING.md`, the chart README and the publishing guide describe one naming scheme.
