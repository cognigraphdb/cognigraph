# CG-34: Native sidecar vector search filters model identity after truncation

- Status: Resolved
- Priority: P2
- Area: Native vector retrieval / backend contract parity
- Found: 2026-09-09
- Resolved: 2026-09-09 (committed locally as `8164f4e`)
- Reviewed revision: `36a4a19` plus the completed, uncommitted CG-19 changes
- Verification: Source-confirmed and reproduced over release HTTP/Lua in resident/sidecar and paged/sidecar, before and after restart

## Problem

The sidecar implementation takes the global top `max(4 × limit, 32)` vector
candidates before checking `model_name`. A requested model with valid rows
outside that prefix can return no hits. Resident/embedded search filters the
quantized entries by model before candidate truncation and returns the match.
Changing the Native vector storage mode therefore changes model-filtering
correctness beyond ordinary quantization or approximate-recall differences.

## Evidence and reproduction

- `crates/cognigraph-native/src/memory/vector.rs:94-151` calls `scan_top` before
  the model filters in both paged and resident candidate resolution.
- `crates/cognigraph-native/src/memory/search.rs:117-140` filters model identity
  before truncation in the embedded-vector path.
- The [CG-20 fixture](../evidence/engineering-arango.md#artifact-85619321477dcd112762)
  has 80 higher-scoring model-A rows ahead of model-B rows. For query `[1, 0]`,
  model B, and limit 1, resident/embedded returns `b000` (score 0.8); both
  sidecar configurations return no hits through `/api/search/vector` and
  Lua `graph.similarity`. The result repeats after restarting each server.
- [Release baseline observations](../evidence/engineering-historical-checks.md#artifact-310e1c7c8a576866c7fd)
  include these Native controls. CG-20 changes only the Arango implementation.

## Acceptance criteria

- [x] Restrict sidecar candidate selection by the requested model before
  truncation, or use a correct supported retrieval path for filtered requests.
- [x] Preserve model-name case sensitivity and the distinction between no
  filter and an empty-string filter.
- [x] Add mixed-model parity coverage across resident/embedded,
  resident/sidecar, and paged/sidecar, including writes, rebuilds, and restarts.
- [x] Pass all Rust gates and a release HTTP/Lua regression before closure.

## Resolution

Base slots use interned model IDs reconstructed from redb, and delta entries
carry the current model alongside the vector. Both filter before candidate
truncation, including model-only writes and rows moving between models. The
sidecar file format is unchanged. Exact re-ranking and threshold behavior are
preserved.

Formatting, strict Clippy, all 928 reported Rust tests, and 162 release HTTP/Lua
checks passed across the three Native configurations. Coverage includes batch
writes, deletion/recreation, removed fields, threshold rebuilds, and restarts
from stores seeded by the previous release. Direct Native tests verify file
reuse at an unchanged revision. Authenticated startup performed no-op collection
writes that unnecessarily invalidated derivatives; that separate performance
defect, [CG-35](CG-35.md), is subsequently resolved with
[authenticated restart verification](collection-ensure-2026-09-09.md).

See the [verification report](sidecar-model-filter-2026-09-09.md) for the
pre-fix failures, corrected harness assumption, and live-test scope.
