# CG-160: Unauthenticated health endpoints disclose tenant names and storage errors

- Status: Open
- Priority: P3
- Area: Server / health; tenancy
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`GET /health/jobs` returns strings such as
``tenant `{tenant}` collection: {error}`` to any caller
(`crates/cognigraph-server/src/routes/health.rs:36-55`,
`jobs/manager.rs:159-187`). `/health/promotions` deliberately returns a fixed
string instead.

`/health/database` calls `state.backend.ping()` with no tenant scope
(`health.rs:66-68`). In multi-tenant mode the routed backend falls back to
`registry.store("default")` (`tenancy.rs:181-186`), so the first probe creates
and opens `default.redb` even when the default tenant is unused, and readiness
reflects only that store.

## Acceptance

- [ ] Unauthenticated health responses carry no tenant names and no backend error text.
- [ ] In multi-tenant mode the readiness probe checks the control store and creates no tenant store.
- [ ] Tests cover both.
