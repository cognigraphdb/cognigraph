# CG-106: CGQL mutations ignore the collection part of a full document id

- Status: Open
- Priority: P1
- Area: CGQL / mutations
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

`crates/cognigraph-query/src/executor/mutation.rs:181-185` reduces a mutation
key with `raw.rsplit_once('/')` and keeps what follows the last slash. The
collection prefix is never compared with the mutation's target collection.
The split is also from the right, while `PARSE_IDENTIFIER`
(`functions/value.rs:109-111`) splits from the left because a key may contain
`/`.

Reproduced with `persons/42` and `organizations/42` stored:
`REMOVE "organizations/42" IN persons` returns 200 and deletes `persons/42`;
`organizations/42` is untouched. UPDATE and REPLACE use the same helper. The
natural edge pattern `FOR e IN rels REMOVE e._to IN persons` therefore writes
to whichever `persons` document shares a key with the edge's target, and
`REMOVE "a/b" IN docs` targets key `b`. No test passes a full id.

## Acceptance

- [ ] A full id whose collection differs from the mutation target is an error before any write.
- [ ] Key extraction agrees with `PARSE_IDENTIFIER` for keys that contain `/`.
- [ ] Corpus cases cover mismatched prefixes and slash-containing keys for REMOVE, UPDATE, REPLACE and UPSERT, and `docs/reference/cgql.md` states the rule.
