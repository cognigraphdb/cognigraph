## Problem

The current references do not describe the same API surface. OpenAPI lists only two job kinds although the server accepts four; architecture lists three. The current architecture construction table omits directed ingestion, and operator configuration omits the separate side-view provider/model controls.

## Evidence

`crates/cognigraph-server/src/jobs.rs:75-85` versus `crates/cognigraph-server/openapi.yaml:47-50`; `docs/operations.md:206-214`; `docs/architecture.md:449-474`; `.env.example:49-53` and `crates/cognigraph-embeddings/src/completion.rs:273-293`.

## Reproduction / comparison

Compare the four JobKind variants (`construct.ingest`, `construct.evaluate`, `construct.draft`, `sideviews.generate`) with the public schema and tables. Compare `/construct/directed` and side-view configuration with current operator/integration guidance.

## Acceptance criteria

Update OpenAPI enums and current API/operator examples from the real route/config surface. Extend drift checks to enum values and request semantics, not only path presence. Document directed limits, replacement semantics, and known open issues.

Verify the affected runtime or documentation contract before closure. Rust changes require all repository gates. See [review evidence](review-2026-09-08.md).

## Resolution

OpenAPI now lists all four job kinds with matching tagged input schemas,
side-view progress, async draft controls and envelopes, side-view clamping and
source eligibility, and explicit directed limits/replacement/failure behavior.
Architecture, operations, and executable API examples use the same contract,
including main/side-view provider defaults and the then-open CG-36 judge
endpoint restriction, subsequently resolved in the
[dedicated endpoint batch](judge-endpoint-2026-09-09.md).
CG-33's exact Unicode identity remains supported.

Five added drift tests obtain enum wire names directly from Serde, compare
parsed schema/method/parameter declarations, and exercise production routes with
the checked-in request fixtures. All 15 focused OpenAPI checks passed. Standard
OpenAPI validation also identified and corrected ambiguous existing inline
YAML descriptions and the collection-delete path parameter declaration.

The release server passed 57 HTTP/CLI/schema checks with all four generic job
kinds, convenience routes, idempotency, directed replacement, rejection bounds,
and independent main/side-view provider routing. Providers were synthetic
loopback endpoints. Formatting, strict Clippy, and all 950 reported Rust tests
passed (eight unconfigured Arango integration entries early-returned). See the [verification report, corrected attempts, and limits](api-contract-2026-09-09.md)
and [runnable examples](../examples/construction/README.md).
