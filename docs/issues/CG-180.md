# CG-180: Embedding cache keys fold case and whitespace although the vector comes from the raw text

- Status: Open
- Priority: P3
- Area: Cache / embedding cache
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

The key is `(normalize_query(query), model)`, lowercased with whitespace
collapsed (`crates/cognigraph-cache/src/normalize.rs:5-7`,
`memory.rs:141-168`); the value is the provider's embedding of the original
string. `docs/architecture/cache.md` describes the key as "(query text,
model)". Persisted entries never expire, are keyed by model name only, and
`decode` drops trailing bytes and checks no dimension
(`persistent.rs:36-43`, `:99-116`).

- "IT strategy" caches its vector; a later "it strategy" (or "US" and "us",
  "Polish" and "polish") gets the other casing's vector. Results depend on
  which casing arrived first, across restarts with the persistent backend.
- An empty or wrong-dimension vector from the provider
  ([CG-149](CG-149.md)), or the same model name served by another
  endpoint or version, is replayed until the cache is cleared.

Also noted: `/api/admin/import` calls `cache.clear()`, which wipes the durable
embedding table although invalidating results would suffice
(`crates/cognigraph-server/src/routes/admin.rs:218`, `:251`); multi-tenant
mode ignores the persistent backend setting with only an info log; and
`PersistentCache::store_put` commits with an fsync inside an async function.

## Acceptance

- [ ] The embedding cache is keyed on the exact text sent to the provider; result-cache normalization may stay.
- [ ] Persistent entries carry and verify the dimension, ideally with a provider and model fingerprint; a mismatch is a miss.
- [ ] Tests cover the casing collision and a stored vector of the wrong length.
