# CG-119: One wrong-dimension or empty embedding fails vector search for the whole collection in sidecar mode

- Status: Open
- Priority: P2
- Area: Native / vector sidecar
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`VectorSidecar::build` takes the dimension from the first row in key order and
returns a validation error if any other row differs
(`crates/cognigraph-native/src/memory/vector.rs:58-92`,
`sidecar.rs:88-93`). Writes are never checked against it. `apply_delta`
rejects the vector, logs a warning and leaves the sidecar behind, so the next
rebuild fails (`vector.rs:208-210`). `embedding: []` counts as dimension zero.

Failure sequence: a collection holds 768-dimension vectors. One document is
written with a 1536-dimension embedding (a model switch; the
[CG-34](CG-34.md) model filter implies mixed-model collections) or with
`embedding: []`. The write succeeds. After the next restart or rebuild, every
`vector_search` on that collection returns an error until the row is found and
fixed. Embedded mode skips such rows. No reference or decision record states
the restriction.

## Acceptance

- [ ] Either the sidecar tolerates mixed dimensions (skips or groups them) or the write is refused up front; the behaviour matches embedded mode or the difference is documented.
- [ ] A test adds a mismatched and an empty embedding to a sidecar collection in resident and paged modes, forces a rebuild, and search still answers for the conforming rows.
