# CG-146: Side-view lookups scan or load whole collections on deletes and job submission

- Status: Open
- Priority: P2
- Area: Server / side views (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`parent_rows` in `crates/cognigraph-server/src/side_views.rs:285-302` filters
`side_views` on `document_id`. Native's filtered listing uses an index only
for `_from`/`_to`; anything else scans the collection, and nothing creates an
index on `side_views.document_id`.

- **Deletes.** `delete_document` runs one scan per delete and `execute_batch`
  one per delete operation, holding the per-tenant scope mutex that also
  serializes publication. Once side views exist, each delete in any ordinary
  collection costs O(|side_views|). At the job's own ceiling of 10,000
  documents × 12 views, a 1,000-document batch or CGQL `REMOVE` does 1,000
  serial scans of 120,000 rows. This is a cost side effect of the
  [CG-13](CG-13.md) cascade.
- **Generation.** The job scans once or twice per parent, and
  `drop_collection` projects the whole collection.
- **Submission.** `sideviews.generate` calls
  `list_documents(collection, None, None)`, full documents with embeddings,
  only to extract `_key`, and rejects afterwards if there are more than 10,000
  (`jobs/prepare.rs:237-251`). A rejected attempt repeats the load.
- **Gap detector.** `selected_side_views` projects every side view in the
  tenant before applying its limit, even when at most 1,000 documents were
  named (`routes/construct/sideview_gaps.rs:130-154`).

Costs are from the code path, not measured.

## Acceptance

- [ ] Parent lookup is an index or key-prefix lookup; a batch resolves its parents in one pass and the mutex is not held across unrelated scans.
- [ ] Key enumeration uses a `_key` projection with `limit = cap + 1`, and the gap detector queries by parent or pages with an early stop.
- [ ] Regression tests bound the delete cost with a large `side_views` collection and assert an over-cap source is rejected without a full read.
