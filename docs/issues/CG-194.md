# CG-194: Migrate the preparation contract to Unicode 18 when the Rust standard library moves

- Status: Open
- Priority: P3
- Area: Construct / preparation contract; dependencies
- Found: 2026-11-11
- Verification: Pending (pin and compile guard observed on 2026-11-11 during CG-192)
- Scheduling: Waits for a stable Rust release whose `char` tables are Unicode 18; the exception for the pin expires on 2027-02-11

## Problem and evidence

The M23 preparation contract freezes Unicode 17.0.0 for NFC normalization and
for whitespace classification
(`docs/decisions/decision_m23_reproducible_raw_document_prepared_corpus_processing.md`).
`crates/cognigraph-construct/src/preparation.rs` refuses to compile unless
both `unicode_normalization::UNICODE_VERSION` and `char::UNICODE_VERSION` are
17.0.0.

`unicode-normalization` 0.1.26 moves its tables to Unicode 18.0.0, so the
[CG-192](CG-192.md) refresh failed that guard. Rust 1.99.1 still ships
Unicode 17 character tables, so taking the new crate now would normalize
under one Unicode version and classify whitespace under another, and existing
prepared-corpus digests would stop reproducing. The owner approved pinning
the crate at `=0.1.25` in the six manifests that use it, with an exception in
`docs/operations/dependency-exceptions.json` that expires on 2027-02-11.

Two things follow:

- The pin is temporary. The freshness gate fails again when the exception
  expires or a newer release appears.
- A future stable Rust release with Unicode 18 `char` tables will fail the
  same guard without any change here. The weekly toolchain canary
  ([CG-151](CG-151.md)) surfaces that as a failed build.

## Acceptance

- [ ] A preparation plan version for Unicode 18 is defined: what happens to existing prepared corpora, receipts and attestations, and how old digests remain verifiable.
- [ ] `unicode-normalization` and the toolchain move together, the compile guard names the new version, and the exception record is removed.
- [ ] Tests cover text whose normalization or whitespace classification differs between the two Unicode versions.
