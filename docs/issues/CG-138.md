# CG-138: Rule-path entity surfaces still match inside longer words

- Status: Open
- Priority: P2
- Area: Construct / grounding gate
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

[CG-39](CG-39.md) gave the directed endpoint check word boundaries
(`directed/gates.rs::find_endpoint`). Every entity-surface check on the rule
path is still `contains` on lowercased text:

- `mentions` (`crates/cognigraph-construct/src/grounding.rs:168-178`),
- the D1 sentence gate (`grounding/triggers.rs:132-136`),
- template expansions matched with plain `find` (`triggers.rs:65-74`),
- `grounding/semantics.rs:38-42`, `materialization.rs:212-217` and
  `propose/neurons.rs:47-49`.

`docs/decisions/decision_pilot_clinical_graph.md` already notes "substring
artifacts" for short aliases, without a ticket.

Failure cases: a rule gated on a target whose alias is a two-letter
abbreviation passes the gate for any sentence that has those letters inside
"administration" or "family". A template `{source} acquired {target}` with a
short source alias matches the tail of a longer company name. MENTIONS edges
are created for nearly every chunk, and the advisory detector never reports
"target absent".

## Acceptance

- [ ] Mentions, the sentence gate and template expansions require Unicode word boundaries around the surface, the same rule as CG-39.
- [ ] Kit baselines are re-measured and recorded, and the grounding snapshot is updated deliberately.
