# CG-132: Governed reads and admissions revalidate whole authority histories under one process-wide lock

- Status: Open
- Priority: P2
- Area: Server / promotions, repairs, attestations (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`transition_lock` is a single mutex shared by every tenant
(`promotions/manager.rs:33-38`) and also taken by every construction ingest.
Three paths do work proportional to stored history while holding it. Costs
below are from the code path, not measured.

- **Promotion head reads.** `current()` (`GET /api/promotions/current/…`)
  always runs `reconcile_locked` (`promotions/decision_queries.rs:42-55`). It
  loads every decision of the target with no limit, validates each up to three
  times with signature checks, reloads and reassesses every referenced
  evidence bundle, and then lists and re-verifies all governance keys,
  revocations, policy revisions, approvals and attestations
  (`governance/authority_loading.rs:17-89`). `register_evidence` additionally
  revalidates every bundle in the tenant. Blocked and rejected decisions and
  evidence bundles have no cap. The M18 decision says "indexed target
  reconciliation is bounded".
- **M26 deployments.** `validated_deployment_chains_locked`
  (`materialized_repairs/deployment_chains.rs:6-56`) loads every deployment
  decision and fully revalidates its generation (up to 16 MiB each). It runs
  on every ingest once the M26 collections exist, on every reader's
  `GET /api/semantic-repairs/deployments/current/{space}`, and on deploy.
  `scoped_record_keys` pre-allocates for the tenant maximum on each call, and
  listing generations loads full bodies to return summaries.
- **Attestation admission.** `create_artifact_attestation` lists five
  collections unprojected, lists attestations again, and re-canonicalizes
  every stored manifest (`artifact_attestations.rs:600-644`, `:713-742`).
  `semantic_repairs.rs:1259-1316` already uses projected keyset scans for the
  same job.

A target with a few hundred decisions, or a caller posting signed rejects in a
loop, makes each read cost thousands of signature checks while promotion
reads and ingest for all other tenants queue behind the lock.

## Acceptance

- [ ] Head reads, ingest admission and `deployments/current` do not grow with history length (validate the head link or cache validated state, invalidated on write); full validation stays in status, recovery and snapshot.
- [ ] Non-actionable decisions per target and evidence bundles per tenant are capped or excluded; idempotency and capacity checks use projected scans.
- [ ] One tenant's reconcile cannot block another tenant, shown by a test, and a benchmark shows admission time does not grow linearly with the number of decisions.
