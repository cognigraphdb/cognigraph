# CG-99: Concurrent text searches after a write fail while the Native text index rebuilds

- Status: Open
- Priority: P1
- Area: Native / text search
- Found: 2026-09-23
- Verification: Pending (reproduced live on 2026-09-23, 2.7.38 release build)

## Problem and evidence

Found while building the [CG-98](CG-98.md) benchmark. On a persistent Native
store (`COGNIGRAPH_NATIVE_PATH` set, resident mode), full-text searches that
run concurrently right after a write can fail. The text index is a lazily
rebuilt derivative: `text_search` in
`crates/cognigraph-native/src/memory/search.rs` checks the in-process cache,
and on a version miss every caller calls `TextIndex::build` in
`crates/cognigraph-native/src/text_index.rs`. For a persistent store that
function runs `remove_dir_all` on the shared on-disk index directory and
recreates it. Nothing serializes the rebuild per cache key. Concurrent callers
delete each other's files and contend for Tantivy's writer lock.

Observed errors, returned through `POST /api/search/text` and swallowed by
`POST /api/search/hybrid` into `"bm25": "skipped: ..."` (the hybrid search
then ranks on vectors only, silently):

- `text index: Failed to acquire Lockfile: LockBusy`
- `text index: Failed to open file for write/read: ... FileDoesNotExist(... .tantivy/<segment>.store|.fieldnorm)`

Reproduction on a release build with a temporary persistent store:

1. Insert 5 documents into an ordinary collection.
2. Run 40 `POST /api/search/text` calls with 8 concurrent workers.
3. Serial first search, then concurrency: 40 of 40 succeed. Immediately
   after one more write: 39 of 40 succeed, 1 fails with `LockBusy`. With
   no warm-up and a hybrid search per worker, the first concurrent searches
   of every configuration lost the BM25 leg.

In-memory stores build the index in RAM and are not affected by the file
race, although they rebuild redundantly under the same pattern.

## Acceptance

- [ ] Concurrent searches after a write never fail and never skip the text
      leg: a per-key build guard (double-checked under the lock), or a build
      into a fresh directory that is renamed into place atomically.
- [ ] A regression test issues concurrent text searches immediately after a
      write on a persistent store and requires every one to succeed with
      identical results.
- [ ] Hybrid search no longer hides a text-leg failure caused by this race.
      Whether `skipped` should stay a soft degradation for other causes is
      decided and recorded.
