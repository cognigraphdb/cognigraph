# CG-19: Arango traversal confidence differs from Native semantics

## Original problem

Native traversal rejects each edge below `min_confidence` and treats missing confidence as 1. Arango's generated AQL filters only the final edge of each returned path and compares a missing confidence field directly. The same options can admit a path containing a low-confidence intermediate edge on Arango while Native rejects it, or exclude an unannotated edge accepted by Native.

## Original review evidence

- `crates/cognigraph-arango/src/backend/graph_backend.rs:280-307` — `FILTER e.confidence >= @min_confidence`.
- `crates/cognigraph-native/src/memory/search.rs` and `memory/paged.rs:221-227` — per-edge pruning.
- `crates/cognigraph-native/src/memory/helpers.rs:143-148` — default confidence 1.
- `crates/cognigraph-core/src/contract.rs:240-335` — shared traversal tests omit a minimum-confidence case.

## Reproduction / failure sequence

For A→B with confidence 0.1 and B→C with confidence 1, request depth 2 and minimum confidence 0.5. Arango's final-edge filter admits the A→B→C path; Native never expands A→B. A second case with missing confidence exposes the default-value mismatch.

## Acceptance criteria

- [x] Specify minimum-confidence semantics in the shared contract and implement the same path/default behavior in both backends.
- [x] Extend conformance tests with low-confidence intermediate edges, missing confidence, and depth zero.
- [x] Run the focused contract against a disposable live Arango database before closure.

Run the repository Rust gates and a focused runtime regression before closing this issue. See [review evidence](review-2026-09-08.md).

## Resolution

Arango prunes every failing edge, including before the minimum returned depth,
then excludes the failing endpoint. Missing/null/nonnumeric confidence use 1.0;
depth zero remains eligible. Native traversal and scoring already match this
contract and remain unchanged. See the
[decision](../decisions/decision_traversal_confidence.md) and
[verification report](traversal-confidence-2026-09-09.md).

The shared 15-case fixture passes against Native resident/paged storage and
live ArangoDB 3.12.11. All six live Arango integration tests, formatting,
strict Clippy, all 923 workspace tests, the release build, and 240 HTTP/Lua
checks across four backend configurations and their server restarts passed.
The saved release reproduced 48 Arango mismatches across two server lifetimes;
the corrected binary produced none. No data migration is required.
