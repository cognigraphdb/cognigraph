## Problem and evidence

The first authorized push of the v2.7.15 candidate (with the v2.7.16 ticket
batch and the v2.7.17 rustls patch on top) was blocked twice by the
[develop gate](../operations/develop-gate.md) pre-push hook on 2026-09-22:

1. `cargo audit --deny unsound` reported RUSTSEC-2026-0285 in `rustls`
   0.23.44, published 2026-09-14, the day the candidate was qualified. The
   [v2.7.17 record](../changelog/2026-09-22-rustls-advisory.md) patched it.
2. `scripts/dependency_freshness.py` then found these direct releases newer
   than the qualified baseline:

| Ecosystem | Dependency | Current | Latest |
|---|---|---|---|
| Cargo | pest, pest_derive | 2.9.1 | 2.9.2 |
| Cargo | redb | 4.2.0 | 4.3.0 |
| Cargo | rustix | 1.1.4 | 1.1.5 |
| Cargo | serde-saphyr | 1.2.0 | 1.3.0 |
| npm | @biomejs/biome | 2.5.13 | 2.5.14 |
| npm | @codemirror/state | 6.7.4 | 6.7.5 |
| npm | @codemirror/view | 6.43.11 | 6.43.12 |
| npm | antd | 6.6.3 | 6.6.5 |
| npm | react-router | 8.3.1 | 8.4.0 |

Fresh compatible resolution removed and added 21 Cargo identities and removed
19 and added 21 npm identities. These are dated observations from the gate
report under `target/ci/dependencies/`, not distinct library upgrades.

## Resolution

Direct requirements were raised where a manifest pinned the old patch or
minor (`rustix`, `redb` in `cognigraph-cache` and `cognigraph-native`,
`serde-saphyr` in `cognigraph-server`, the five UI ranges); `pest` already
allowed 2.9.2. A full `cargo update` and `bun update` produced the fresh
resolution. No exception record was added.

redb 4.3.0 was reviewed against its published changelog: it states no file
format change and is backwards compatible; the release adds optional
`StorageBackend` locking, shorter stored prefixes for variable-length keys,
and repair-path fixes for corrupted savepoints and freed-page records. No new
redb feature or experimental API is enabled. The [upgrade harness](../../scripts/check-dependency-upgrade.py)
passed for the v2.7.17 and v2.7.18 Enterprise binaries in resident-embedded,
resident-sidecar and paged-sidecar modes. A live reopen check confirmed the
candidate opens a store last written on 2026-08-30 under an earlier redb
series: all nine collections and their counts were read, a document was
written, and after a restart the new collection and document were present and
the pre-existing fact edges still returned their evidence spans through CGQL.

The other Rust updates are patch releases of a parser, a filesystem shim and
a YAML deserializer; the UI updates are patch and minor releases of the
linter, editor, component library and router, all covered by the UI unit,
build and browser suites.

## Verification

`python3 scripts/verify.py --suite dependencies` reports zero Cargo and npm
resolution drift across 58 direct identities. `--suite advisories` passes
with the pre-existing allowed `paste` maintenance warning unchanged.
`--suite ci` passes: UI check, unit tests and build; fmt, actionlint, vendored
Tantivy integrity, public-distribution check, audit, script regressions,
server modularity, editions, docs, decision index, issue registry; strict
Clippy and tests for both editions (1,645 passed, 0 failed, 4 ignored);
Helm rendering; Native acceptance for both editions (257 checks each); and
the browser suite for both editions. `--suite docker` passes: both edition
images build, no fixable image vulnerabilities, image checks, hardened
container startup and live Helm checks for both editions. Owned CI images
were removed afterward; no containers remained.

The Docker suite ran with the candidate labelled 2.7.17; the final commit
carries 2.7.18 with an otherwise identical source tree and lockfile. The
[verification record](../verification/dependency-refresh-2026-09-22.md)
holds the counts and limitations. Not run: external providers, model
benchmarks, research holdouts, Railway or any publication.
