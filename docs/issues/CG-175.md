# CG-175: Read-only M26 endpoints create collections and an index

- Status: Open
- Priority: P3
- Area: Server / materialized repairs (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`get_semantic_repair_generation`, `list_semantic_repair_generations` and
`current_semantic_repair_deployment`, all open to any reader role, call
`ensure_materialized_repair_repository`
(`crates/cognigraph-server/src/materialized_repairs/generation_queries.rs:14`,
`:42`, `deployment_queries.rs:13`, `repository.rs:36-98`), which creates three
collections and an index. From then on the repository counts as present, so
status reports M26 as enabled and every ingest runs the M26 admission scan
([CG-132](CG-132.md)).

A viewer who opens the generations list on a tenant that never used M26
changes the schema, the three empty collections appear in exports, and all
later ingests pay the admission path.

## Acceptance

- [ ] GET handlers return an empty result or 404 when the repository is absent, without creating anything.
- [ ] The collections are created only by build or deploy, with a test.
