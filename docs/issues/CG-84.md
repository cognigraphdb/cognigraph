## Problem and evidence

The only client guidance for JavaScript applications is
[the AQL migration guide](../reference/aql-to-cgql.md), whose endpoint table maps
`arangojs` to "HTTP + `fetch`; a TypeScript SDK is planned". No package, typed
request or response shapes, error mapping, or retry policy exists for a Bun or
Node consumer today.

A typical application that migrates from a document database reaches it through
one thin query wrapper with many call sites behind it. Replacing that wrapper
requires a client that covers `POST /api/search/query` and `POST /api/query` with
`bind_vars`, the document routes, `POST /api/batch`, the health routes, bearer
authentication, request timeouts, and a typed mapping of the documented 400, 403,
408, 429, 500 and 503 responses. Hand-writing that in each application repeats
the same undocumented decisions and hides contract drift.

This is planned compatibility work based on documentation inspection at 2.7.15;
it is not a reproduced defect.

## Scope and dependencies

Depends on [CG-85](CG-85.md) only for pagination ergonomics; the client can ship
first and interpolate `LIMIT` values with validation until CG-85 lands. Independent
of [CG-86](CG-86.md) and [CG-87](CG-87.md). Not part of any active batch.

## Acceptance

- [x] A TypeScript package, in-repo or published, that works under Bun and Node
      without a bundler and exposes typed `query`, `mutate`, document CRUD, `batch`,
      and health helpers with `bind_vars` support and bearer authentication:
      `clients/typescript` (`@cognigraph/client` 0.1.0), zero runtime dependencies,
      compiled ESM with declarations, plus login and the unique-constraint calls.
- [x] Typed error classes that preserve the server's `error` and `code` fields and
      the HTTP status, with documented retry guidance for 408, 429 and 503; retries
      are opt-in and apply to reads only.
- [x] Integration tests that run the client against a disposable local Native
      server through real HTTP, plus a runnable example under `docs/examples/`
      (`typescript-client.ts`, run by the live tests).
- [x] The migration guide's `arangojs` row and the HTTP reference link to the client.

## Resolution

Implemented 2026-09-23 in v2.7.33 under the
[TypeScript client decision](../decisions/decision_typescript_client.md). Owner
choices: in-repo and npm-ready without publishing yet; opt-in retries for reads
only; ticket scope plus login and index calls. The dependency-freshness gate now
covers every Bun project, including the client's lockfile.
