# CG-147: CLI requests fail after 30 seconds while the server keeps working

- Status: Open
- Priority: P2
- Area: CLI / HTTP client
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`crates/cognigraph-cli/src/client.rs:13-19` builds
`reqwest::blocking::Client::new()` and never sets a timeout. The blocking
client's default is 30 seconds, applied to the send and to each body read.

Failure cases:

- `cognigraph import snapshot.json` with a few thousand documents exceeds 30
  seconds, because snapshot import writes one transaction per document
  ([CG-122](CG-122.md)). The CLI prints "request failed" and exits 1 while
  the server finishes the additive import.
- `cognigraph embed notes chunks.jsonl` with enough chunks: the CLI aborts,
  the handler is dropped, the provider calls already made are billed and
  nothing is stored. A retry repeats the spend.
- `cognigraph export` of a large store: the body read times out, with the
  consequence in [CG-114](CG-114.md).
- Enterprise import pauses the tenant's jobs first; a client disconnect may
  leave them paused ([CG-142](CG-142.md); this part was not traced to the end).

## Acceptance

- [ ] The client has an explicit connect timeout and no total timeout, or a generous one configurable through a flag and environment variable, documented in `docs/operations/cli.md`.
- [ ] A test with a slow stub proves a response slower than 30 seconds succeeds.
- [ ] The server's behaviour when the client disconnects during import and embed is decided and documented.
