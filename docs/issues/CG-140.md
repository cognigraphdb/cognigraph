# CG-140: Chunk reconciliation deletes facts built by another construction mode or taxonomy

- Status: Open
- Priority: P2
- Area: Construct / ingest reconciliation
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`ingest_chunks_grounded_by` (`crates/cognigraph-construct/src/ingest.rs:228-256`)
deletes every fact, mention and semantics row of the submitted chunk ids in
the space, filtered only by `space_id` and `evidence_chunk_id`, and then
writes what the current grounder returns. Provenance and `reviewed_by` are not
part of the filter. The directed route runs with a rule-less configuration
(`directed.rs:172-183`) and accepts an existing rule space without a check
(`crates/cognigraph-server/src/routes/construct/directed.rs:56-83`; its
comment assumes "no rules").

Failure sequences, each returning 200:

- Directed run with taxonomy A over chunk `c`, then with taxonomy B over the
  same chunk: all facts from A are gone.
- Directed run on a chunk of a rule-built space: its rule-grounded facts and
  ontology MENTIONS edges are deleted. A later rule ingest deletes the
  directed facts.

`docs/reference/http-api.md` documents "atomic replacement of all occurrences
for supplied chunks" but not the cross-mode or cross-taxonomy effect, and no
test covers it.

## Acceptance

- [ ] The reconciliation scope includes the construction source (policy or relation set), or the directed route refuses spaces with rules and a single taxonomy per space is enforced and documented.
- [ ] Tests cover two taxonomies over one chunk and a directed run over a rule-ingested chunk.
