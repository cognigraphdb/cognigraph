# CG-62: Plain-text construction imports reuse chunk IDs and replace earlier evidence

- Status: Resolved
- Priority: P1
- Area: UI / construction
- Found: 2026-09-11
- Verification: Source review, browser first ingestion and exact-payload HTTP replacement

## Problem and evidence

[parseChunks](../../ui/src/lib/construct.ts), lines 40–46, generates
`chunk-1`, `chunk-2`, … for every plain-text submission and JSONL record without
an explicit id. [ConstructScreen](../../ui/src/screens/ConstructScreen.tsx),
lines 158–172, sends those IDs unchanged to `/construct/ingest`. The UI describes
grounding chunks and gives no replacement preview or warning.

The backend intentionally replaces the prior occurrence set for an existing
space/chunk identity ([ingest.rs](../../crates/cognigraph-construct/src/ingest.rs),
lines 155–195). Thus a second ordinary text import reuses the first import's
identities and removes/replaces its evidence and facts.

Live: the browser ingested “DataCloud runs on Nimbus.” in `audit_space`, creating
one chunk and one fact. A second HTTP submission using exactly the UI parser's
one-line payload (`id=chunk-1`, new unrelated text) returned 200. The same stored
chunk now contained the second text and the fact count fell from one to zero.
[Before/after records](../evidence/ui-2026-09-11-full-review.md#artifact-8bdf0e1e581ab903d450).
The second step was an HTTP reproduction of the client payload, not a second
browser click. Backend atomic replacement worked as designed; UI-generated
identity and missing impact disclosure cause this data-integrity defect.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Assign identities that distinguish new imports while remaining stable for retries; do not regenerate the same positional IDs for unrelated corpora.
- [x] Make deliberate replacement explicit and reviewable, including supplied JSONL IDs and affected existing evidence.
- [x] Ingest two distinct plain-text corpora through the browser and verify both survive; separately verify idempotent retry and explicitly confirmed replacement.

## Resolution — 2026-09-11

Generated IDs now use a versioned SHA-256 text/title identity, stable across
retries, reordering and reloads. Explicit JSONL IDs remain supported; duplicate
or colliding IDs are rejected. Every import previews new/existing source IDs.
Existing text and evidence-rebuilding impact require explicit confirmation;
a fresh read refuses stale previews before submit. This UI guard does not add
an atomic compare-and-swap contract across external writers.

Two distinct browser imports retained both source/fact sets. A retry kept
identities and counts, cancellation wrote nothing, confirmed replacement changed
only its source, an intervening write invalidated the preview, and Viewer writes
were denied. Keyboard focus/scrolling and three desktop viewports passed.

[Resolution report and reproducible captures](../evidence/ui-2026-09-11-data-preservation.md#artifact-6afad6337a2d11fc893d).
UI lint/type checks, all 85 helper tests and the production build pass.
