## Problem and evidence

[CG-88](CG-88.md) delivered side views as a proposal source for
`POST /api/construct/propose` under the
[side-view gap detector decision](../decisions/decision_sideview_gap_detector.md).
Its behavior is covered by deterministic tests with scripted completions, but
nobody has measured it on real side views. The Semantic Neurons paper calls
this source "a design direction the architecture licenses, not a measured
result", and that remains true until this run exists.

A measurement needs model calls twice: the side-view generation job to create
the side views over a kit's documents, and the proposal step to draft
verbatim triggers. Reviewing the proposals needs a human or the attested
judge lane. None of that can run in the local test gates.

## Plan

1. Load one public kit from `fixtures/semantic-neurons/` (for example
   `digital_forensics` with `digital_forensics_case_alpha`) into a disposable
   server: its space type, its chunks as documents of a source collection, and
   construct ingestion of the same chunks.
2. Generate side views for that collection with the configured side-view
   provider, recording model, count per document and cost.
3. Run the detector as a dry run at `min_support` 1 and 2 and record
   candidates and skips by reason.
4. Run the proposal step, then review every proposal (human, or the attested
   judge lane with its policy recorded).
5. Compare the candidates with the kit's evaluation: how many name expected
   facts that baseline construction misses, and how many name forbidden facts.

## Resolution

Resolved 2026-09-23 in v2.7.38. The owner chose trigger ablation on the
alpha and bravo kits, evaluation-backed review, and `gpt-5.6-luna` with three
repetitions. The [research note](../research/semantic-neurons/sideview-gap-measurement-2026-09-23.md)
has the results and the
[harness](../verification/harnesses/sideview-gap-measurement.py) reproduces
them ([change record](../changelog/2026-09-23-sideview-gap-measurement.md)).

- **Candidates:** every missing expected fact was a candidate in all six
  runs. The only other candidate was bravo's forbidden, negated
  `iPhone 14 --RUNS_APPLICATION--> Signal`, the strongest candidate in every
  run.
- **Proposals:** the proposer declined that forbidden candidate every time.
  Every stored proposal survived review, and none built a forbidden fact.
- **Recall after repair:** 5/6 on alpha, and 8/9, 8/9 and 7/9 on bravo. The
  gaps come from proposer declines on "contained" phrasing.
- **Defaults:** the
  [decision](../decisions/decision_sideview_gap_detector.md#measurement-2026-09-23)
  keeps `min_support` at 1.
