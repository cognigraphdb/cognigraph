# CG-47: Issue identity checks must survive commits and concurrent allocation

- Status: Resolved
- Priority: P2
- Area: Workflow / issue registry
- Found: 2026-09-10
- Verification: Disposable Git repositories and concurrent allocator subprocesses

## Problem and evidence

The new issue guard compared titles only with HEAD. Once a replacement title
and matching registry row were committed, CI compared the record with itself.
Deleting the highest issue and its row could similarly hide its identity.
Independent allocators also wrote the registry without serialization: exclusive
file creation protected individual issue files but not the shared index.

## Resolution

Check each title against its first committed addition, and retain identifiers
from committed history as well as the index and working tree. Fail on shallow
or unavailable history; CI checks out full history. Validate link targets and
priorities as well as titles/statuses. Reject empty, multiline and pipe-containing
allocator fields before writing.

Serialize allocators with a stable POSIX advisory lock outside `.git/`. Keep
exclusive issue creation, publish the registry through an atomic replacement,
and roll back the newly created file if registry publication fails. This is
serialization for cooperating allocators, not a crash-atomic transaction across
two files or a guard against arbitrary manual edits. The consistency check
catches an interrupted update. The ignored lock file must not be removed while
allocators may be running.

## Verification

`python3 -m unittest discover -s scripts/tests -p test_issue_registry.py` passes
11 tests, including a committed retitle, committed deletion, mismatched links
and priorities, invalid fields, shallow-history refusal and eight concurrent
allocator subprocesses. Every concurrently allocated file retains its row and
the resulting registry passes `check`. The real repository's 47 records and
47 rows also pass against their original committed titles.

## Acceptance

- [x] Committing a changed title does not defeat the identity guard.
- [x] A deleted historical identity cannot be reused.
- [x] Concurrent allocators preserve every registry row.
- [x] Invalid input and incomplete history fail visibly.
