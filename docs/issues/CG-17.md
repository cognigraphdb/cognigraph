# CG-17: Duplicate text-search fields panic instead of returning validation errors

- Status: Resolved
- Priority: P2
- Area: Native text search
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` (workspace 2.6.0; current drafts where noted)
- Verification: Source-confirmed

## Problem

The text-search API accepts arbitrary field lists. The schema always inserts an internal `_key` field and then inserts every requested field without checking duplicates. Tantivy's schema builder panics on duplicate names, so `fields:["_key"]` or a repeated ordinary field can unwind a request instead of producing a controlled client error.

## Evidence

`crates/cognigraph-native/src/text_index.rs:26-33`; `crates/cognigraph-server/src/routes/search/basic.rs:57-79`. The installed Tantivy schema builder explicitly panics when a field already exists.

## Reproduction / comparison

Use a nonempty collection and request text search with `_key` or two copies of `content`. The duplicate reaches `SchemaBuilder::add_field`. No process-wide crash is claimed; the defect is an avoidable request panic.

## Acceptance criteria

Validate/deduplicate field lists and handle the internal identity field explicitly; test both direct text and hybrid search in resident/paged modes and return a stable 4xx error for invalid requests.

## Resolution — 2026-09-08

Native BM25 validates field identity before cache lookup or schema creation.
The hybrid endpoint applies the same check before embedding or result-cache
access. Duplicate fields and `_key` produce a validation error; release-server
HTTP checks returned 400 for both text and hybrid routes in resident/paged modes,
before and after restart. In-memory backend tests also pass. All Rust gates
passed; see [batch verification](fixes-2026-09-08.md).

Verify the affected runtime or documentation contract before closure. Rust changes require all repository gates. See [review evidence](review-2026-09-08.md).
