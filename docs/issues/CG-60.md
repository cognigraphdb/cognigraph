# CG-60: CI omits the UI checks and browser regression coverage

- Status: Resolved
- Priority: P2
- Area: UI / verification
- Found: 2026-09-11
- Verification: Complete local CI gate, nine real browser cases and negative-candidate rejection

## Problem and evidence

The only workflow calls `verify.py --suite ci` and the Docker suite. Neither
runs Bun or builds/tests the UI. The UI suite exists only as a separate manual
choice in [scripts/verify.py](../../scripts/verify.py), lines 12–34.
[CI](../../.github/workflows/ci.yml) installs Rust but no Bun. The current
[Dockerfile](../../Dockerfile) packages Rust binaries and does not build the
console, so its successful build supplies no indirect UI coverage.

The current UI suite passes Biome/TypeScript, 72 tests and bundling. All 14 test
files are helper tests under `ui/src/lib`; there are no screen, API-client or
browser regression tests. A green CI can therefore accompany a broken UI build,
and the current local tests miss the origin, persistence and access-contract
defects reproduced in this audit. Both HEAD and the pending Docker workflow
have this omission; it was not introduced by this review.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [x] Include the shared UI install/check/test/build suite in the applicable local and remote CI gate with an explicit Bun toolchain.
- [x] Add deterministic browser smoke/regression coverage against disposable real Community/Enterprise APIs, including fresh production origin, document round trips and denied-role behavior.
- [x] Keep provider-dependent and holdout work out of routine CI; report intentional skips and make a deliberately broken UI candidate fail the gate.

## Resolution — 2026-09-11

The shared CI suite now includes the frozen Bun install, Biome/TypeScript, all
161 unit tests, production bundling and deterministic Chromium regressions.
The workflow installs current stable Bun and the lockfile's Playwright Chromium
dependencies. Pre-push and initial publication use this combined gate without
repeating the UI suite. The manual CI trigger and Docker publication scope stay
unchanged. [Setup and commands](../operations/ui-testing.md).

The browser runner builds and verifies real Community and Enterprise binaries,
using temporary Native stores, random loopback origins and synthetic identities.
Four cases run in both editions, plus HostAdmin coverage in Enterprise: fresh
origin and deep-link login, invalid-login recovery, encoded keys, keyboard links,
history/reload, document create/edit/delete and JSON fidelity, Viewer UI/API
denials, edition gating and host/data boundaries. Source/type checks include the
browser suite; Bun's ordinary unit discovery remains confined to `src/`.

External embedding tests now require explicit `--ignored` qualification before
dotenv loading. CI disables the live LLM loop opt-in; browser processes receive
an environment allowlist and reject external-origin requests. The runner stops
servers and removes temporary stores on success or failure. There are no retries
or optional browser skips. Generated diagnostics omit traces/authentication state.

Both a broken TypeScript candidate and a broken production bundle were rejected
by the actual gates. [Combined verification, negative cases and limits](../../ui/audit/2026-09-11-ui-ci/audit.md).
This is deterministic Native console coverage, not complete UI/backend parity,
Arango/provider qualification or evidence of a remote CI run.

The final `python3 scripts/verify.py --suite ci` completed with exit 0: frozen UI
install, lint/types, 161 unit tests, production build, 64 workflow tests, docs and
edition/modularity checks, formatting, strict Clippy and workspace tests for both
feature sets, then all nine Chromium cases. Two embedding tests are explicitly
ignored per Rust suite; existing credential-gated Arango/live-loop entries are
not new live service coverage. Actionlint and the 216-package Bun audit also pass.
