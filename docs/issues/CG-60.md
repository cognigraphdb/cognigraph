# CG-60: CI omits the UI checks and browser regression coverage

- Status: Open
- Priority: P2
- Area: UI / verification
- Found: 2026-09-11
- Verification: Workflow/source inspection and executed UI gates

## Problem and evidence

The only workflow calls `verify.py --suite ci` and the Docker suite. Neither
runs Bun or builds/tests the UI. The UI suite exists only as a separate manual
choice in [scripts/verify.py](../../scripts/verify.py), lines 12–34.
[CI](../../.github/workflows/ci.yml) installs Rust but no Bun. The current
[Dockerfile](../../Dockerfile) packages Rust binaries and does not build the
console, so its successful build supplies no indirect UI coverage.

The current UI suite passes Biome/TypeScript, 72 tests and bundling. All 14 test
files are helper tests under `ui/src/lib`; there are no screen, API-client or
browser regression tests. A green CI can therefore accompany a broken UI build,
and the current local tests miss the origin, persistence and access-contract
defects reproduced in this audit. Both HEAD and the pending Docker workflow
have this omission; it was not introduced by this review.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [ ] Include the shared UI install/check/test/build suite in the applicable local and remote CI gate with an explicit Bun toolchain.
- [ ] Add deterministic browser smoke/regression coverage against disposable real Community/Enterprise APIs, including fresh production origin, document round trips and denied-role behavior.
- [ ] Keep provider-dependent and holdout work out of routine CI; report intentional skips and make a deliberately broken UI candidate fail the gate.
