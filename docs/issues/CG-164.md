# CG-164: Paged-mode paths swallow storage read errors

- Status: Open
- Priority: P3
- Area: Native / paged mode
- Found: 2026-11-11
- Verification: Pending (source-confirmed; the trigger needs a failing read)

## Problem and evidence

- Building the triple index uses
  `store.scan_collection(..).unwrap_or_default()`
  (`crates/cognigraph-native/src/memory/mod.rs:484-489`). A failed edge scan
  produces an empty index that is then cached.
- Text hits, vector candidates and traversal vertices whose fetch fails are
  dropped or replaced by `{"_id": …}` with a 200 response
  (`memory/paged.rs:126-128`, `:187-191`, `memory/vector.rs:115`, `:121`,
  `:151`).

With one unreadable row in an edge collection (an I/O error, or the over-deep
document of [CG-107](CG-107.md)), every `upsert_edge` in paged mode stops finding
existing triples and inserts a new duplicate edge each time, and searches
return fewer hits with no error. This is the class [CG-16](CG-16.md) fixed
for the query path only.

## Acceptance

- [ ] The triple-index build propagates the scan error.
- [ ] Search and traversal propagate fetch errors; only "not found" is skipped.
- [ ] A fault-injection test shows an upsert fails rather than duplicating.
