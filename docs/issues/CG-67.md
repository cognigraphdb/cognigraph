# CG-67: Remove the ArangoDB runtime backend and reject retired configuration

- Status: Open
- Priority: P2
- Area: Storage / runtime
- Found: 2026-09-12
- Verification: Pending

## Problem and evidence

At 2.7.1 (`efe9839`), [the server manifest](../../crates/cognigraph-server/Cargo.toml)
depends unconditionally on `cognigraph-arango`, and
[startup](../../crates/cognigraph-server/src/main.rs) selects it through
`COGNIGRAPH_BACKEND=arango`. Its unknown-backend branch falls back to Native.
Simply removing the Arango match arm could therefore turn a retired setting
into an apparently successful empty Native deployment.

The owner approved [Native-only storage](../decisions/decision_native_only.md).
The owner clarified that there are no existing users or live deployments, so
the cleanup may freely break earlier development configuration. Preserve useful
Native capability and public CGQL/authorization contracts, without maintaining
Arango-specific compatibility behavior.

## Scope and dependencies

Depends only on [CG-65](CG-65.md); blocks [CG-68](CG-68.md).
CG-64/CG-66 are deferred and must not delay this work.
Remove the adapter crate, workspace/dependency edges and startup/configuration
surface. Review server search/query, Lua, construct/server test dependencies,
query-language enum branches and edition/verification scripts. Remove obsolete
AQL-specific behavior where it has no retained contract owner; keep useful
`GraphBackend` capabilities and test doubles.

Do not move support into Enterprise or an optional feature. The existing AQL
comparison can remain external migration education; there is no importer to
preserve or implement here. Historical reports remain separate from current
runtime guidance.
Never edit local `.env` files, existing stores or source dumps during cleanup.

## Acceptance

- [ ] The adapter directory, workspace member and runtime/dev dependency edges are removed; default and Enterprise dependency trees contain no `cognigraph-arango` and no replacement Arango runtime driver.
- [ ] Native startup works directly. Delete the advertised backend selector or restrict any retained selector to Native with generic validation before writes; eliminate the invalid-value fallback. No Arango-specific shim, migration diagnostic or legacy-setting compatibility is required.
- [ ] Arango URL/database/user/password and vector-mode configuration and help/examples are removed. No advertised configuration or API path selects Arango.
- [ ] Public HTTP/Lua queries retain parsed CGQL, mutation/read authorization and budgets. Tenant/cache wrappers and supported Native modes retain their contracts without Arango-name conditionals substituting for capabilities.
- [ ] Both editions pass fresh Native startup and CRUD/query/traversal/search/auth/restart probes, plus rejection probes for any retained selector. Verification needs no importer or Arango service.
- [ ] Pass required Rust checks, edition/modularity checks where applicable, shared UI/browser gates for affected surfaces, and documentation/issue validation. Update owning guides with the implemented state and link final qualification in CG-68.

## Verification and resolution

Pending. The original title is retained as a stable issue identity; the clarified
acceptance allows deleting configuration entirely rather than preserving a legacy
error surface. No mandatory major-version bump or customer migration is required
for this owner-authorized pre-deployment cleanup. Normal validation and the
version increment before an authorized push still apply.
