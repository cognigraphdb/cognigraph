# CG-14: Dropping a collection does not clear paged document cache entries

- Status: Resolved
- Priority: P1
- Area: Native paged storage
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` (workspace 2.6.0)
- Verification: Live HTTP reproduction

## Problem

Native `drop_collection` removes durable rows and collection metadata but never purges that collection from the paged document cache. `get_document` checks the cache without checking that the collection still exists. A successful collection drop can therefore leave deleted documents readable until eviction or process restart, including after recreation of an empty collection.

## Evidence

- `crates/cognigraph-native/src/memory/backend.rs:253-260` — drop omits document-cache cleanup.
- `crates/cognigraph-native/src/memory/paged.rs:245-264` — cache hit bypasses store/catalog checks.

## Reproduction / failure sequence

Run with `COGNIGRAPH_STORAGE_MODE=paged` and `COGNIGRAPH_VECTOR_MODE=sidecar`. Create and GET `notes/a`; DELETE `/api/collections/notes` returns `{"dropped":"notes"}`. A subsequent GET `/api/documents/notes/a` still returns HTTP 200 with the deleted document.

## Acceptance criteria

- [x] Purge collection cache entries as part of drop and ensure stale fills cannot repopulate them afterward.
- [x] Use a collection/database incarnation or equivalent check for cache validity.
- [x] Test drop/get and drop/recreate/get in paged mode, including concurrent cache misses; retained data must not be exposed.

## Resolution — 2026-09-08

Collection drop removes matching LRU entries, recency records, byte accounting,
and the loaded vector sidecar while holding the state write lock. Point reads
validate the resident catalog/key under the shared lock and retain it through
cache fill. Ordered purge plus that catalog check prevents old fills from
surviving drop/recreate within the backend instance; cross-database incarnation
binding remains CG-11 work.

Warm-cache and paused-fill regressions failed on the original code and now
pass. Release HTTP checks returned 404 after drop and empty recreation,
preserved other collections, and read/searched a new document using the same
key after recreation and restart. Formatting, Clippy, and all 857 tests passed.
See [verification and scope](paged-cache-2026-09-08.md).

Run the repository Rust gates and a focused runtime regression before closing this issue. See [review evidence](review-2026-09-08.md).
