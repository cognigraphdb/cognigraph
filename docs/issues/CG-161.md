# CG-161: Implicit collection creation bypasses the collection-name rules

- Status: Open
- Priority: P3
- Area: Server / documents, batch, graph
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

`POST /api/collections` rejects empty names and names containing `/`
(`crates/cognigraph-server/src/routes/collections.rs:48-60`). Document create,
batch, embed and relationship writes pass the name straight to Native, which
rejects only NUL (`crates/cognigraph-native/src/storage.rs:84-91`).

Reproduced:

- `POST /api/documents {"collection":"","x":1}` returns 200 with
  `_id: "/<uuid>"`. The catalog lists a collection named `""` that
  `DELETE /api/collections/{name}` cannot address.
- `POST /api/documents {"collection":"a/b","_key":"k"}` returns 200 with
  `_id: "a/b/k"`. Search hydration splits such an id as collection `a`, key
  `b/k` and returns `document: null` (`routes/search/hybrid.rs:277`).

## Acceptance

- [ ] One shared collection-name validator applies on every write path, or in the guarded backend.
- [ ] Tests cover empty and slash-containing names on documents, batch, embed and relationships.
