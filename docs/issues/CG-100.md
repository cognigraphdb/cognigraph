# CG-100: Ollama embedding requests time out after a fixed 120 seconds

- Status: Open
- Priority: P3
- Area: Embeddings / Ollama
- Found: 2026-09-23
- Verification: Pending (observed 2026-09-23 during CG-98)

## Problem and evidence

`crates/cognigraph-embeddings/src/ollama.rs` builds its HTTP client with a
30 s connect timeout and a fixed 120 s total timeout. Nothing configures it.
During the [CG-98](CG-98.md) benchmark, `POST /api/documents/embed` with the
default provider batch of 32 label chunks (up to 2,000 characters each)
through `qwen3-embedding:8b` on a 24 GiB Apple Silicon machine exceeded 120 s.
Ollama logged the request as cancelled after `2m0s`. CogniGraph reported
`Embedding error: Failed to connect to Ollama. Is it running?` although
Ollama was running. That message points the operator at the wrong cause.

The benchmark worked around it with provider batches of 8. Large local
models on modest hardware will hit the same limit in ordinary ingestion.

## Acceptance

- [ ] The Ollama request timeout is configurable (for example
      `COGNIGRAPH_EMBEDDING_TIMEOUT_SECS`), with the default and range
      documented in `docs/operations/configuration.md`.
- [ ] A timeout is reported as a timeout, not as a connection failure.
- [ ] A test covers both the configured timeout and the error message.
