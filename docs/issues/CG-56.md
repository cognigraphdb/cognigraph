# CG-56: Console results remain attached to changed inputs and failed graph requests

- Status: Resolved
- Priority: P2
- Area: UI / results
- Found: 2026-09-11
- Verification: 144 UI tests, production build, real delayed query/Lua/vector/graph requests and connection-failure browser checks

## Problem and evidence

Query, Lua and search hold result state independently of their edited inputs.
For example [QueryScreen.tsx](../../ui/src/screens/QueryScreen.tsx), lines 24–26
and 60–83, renders the previous result with the current editor and bind variables,
without a submitted-input snapshot or stale marker. The same pattern exists in
LuaScreen and SearchPanel. Out-of-order executions are additionally possible
through CG-55.

Live: execute a query returning four document keys, then replace the editor with
`RETURN "not executed"` without running. The same Result panel and timing remain
beside that new text. [Capture](../evidence/ui-2026-09-11-full-review.md#artifact-4003dfc6242e0df94075).

Graph has a stronger error case. `loadTraversal` retains `graph` after a failure;
the JSON branch renders `graph.raw` without the error shown by the visual branch
([GraphScreen.tsx](../../ui/src/screens/GraphScreen.tsx), lines 80–84 and 213–233).
After a successful Alpha traversal, the audit stopped its forwarding proxy,
entered Gamma and ran again. The old Alpha JSON remained after “Failed to fetch”
toast expiry, with no persistent error in the workspace.
[State](../evidence/ui-2026-09-11-full-review.md#artifact-3cc215c4c03d3c13db73),
[capture](../evidence/ui-2026-09-11-full-review.md#artifact-c24fdfb3d29064c8d696).

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Associate each result with immutable submitted inputs and show when current inputs differ, or clear results deliberately.
- [x] Show loading/failure state in both graph views; retained previous results must be visibly identified as previous results.
- [x] Ignore obsolete responses and test changed query/bind/vector/graph/script inputs, failed reruns and reversed completion order.

## Resolution — 2026-09-11

Query, Lua, retrieval modes and Graph now use an
[input-scoped result store](../../ui/src/hooks/useRequestResult.ts). Editing any
of the relevant inputs or starting a rerun clears the previous result and timing.
Changing back to old input values does not resurrect a discarded result. The
[request owner](../../ui/src/lib/request-result.ts) suppresses obsolete success,
failure, timing and success callbacks. Lua/CGQL retain CG-55's execution guard;
editing a script does not cancel a write already sent to the server.

Graph renders persistent loading/error feedback before either Visual or JSON
content. Clearing a graph also removes its inspector and selected path. Expansion
captures its base graph before the pending state clears it; relationship readback
that changes the root or edge collection starts only after the new inputs own the
result. JSON explicitly identifies the latest traversal's vertex and response,
while Visual combines expanded neighborhoods.

All 144 UI tests, lint/types and production build pass. Real Enterprise/Native
browser checks cover query/bind/script edits, delayed success and error suppression,
reversed vector and graph completions, all traversal parameters, local vector errors,
graph connection failure in both views, retry, expansion and relationship readback.
A Lua write persisted exactly once despite edits/shortcuts; fresh reads and reloads
verify it and both created edges. Scaled error layouts were checked at 1280 × 800
and 1067 × 667 CSS pixels. [Evidence and explicit limits](../evidence/ui-2026-09-11-result-ownership.md#artifact-8aa8b46fb43543771a2c).
