# CG-121: Any write invalidates every vector sidecar, and edge writes with embeddings can be skipped permanently

- Status: Open
- Priority: P2
- Area: Native / derivative invalidation
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

A sidecar is valid only while `applied_generation == store.data_generation()`,
a database-wide counter (`crates/cognigraph-native/src/memory/vector.rs:33-41`).
The delta is applied only to the written collection's sidecar (`:182-211`).
The paged adjacency index uses the same global stamp (`memory/mod.rs:272-281`),
and dropping a collection that does not exist still commits and bumps it
(`memory/backend.rs:268`).

- **Cost.** While ingestion writes chunks, edges or job records, every search
  on another collection rescans and re-parses that whole collection from redb
  and rewrites and fsyncs its sidecar file, under the state read lock and the
  global sidecar write lock. The only test of the "delta absorbed all writes"
  claim (`tests/persistence_modes.rs:164-196`) writes to the searched
  collection alone.
- **Correctness.** Edge write paths never call `sidecar_apply_write`
  (`memory/edges.rs:46-68`, `:118-140`). With a sidecar on edge collection
  `E`, `create_edge(E, {embedding…})` commits with no delta. A later document
  update in `E` advances `applied_generation` past it, and the new edge's
  vector is missing from results until an unrelated rebuild.

## Acceptance

- [ ] Sidecar and adjacency validity are tracked per collection, or unaffected derivatives are advanced on foreign writes.
- [ ] Edge write paths feed the delta or invalidate that collection's sidecar.
- [ ] A test interleaves writes to collection B with searches on A and asserts the rebuild count stays flat; dropping an absent collection does not bump the revision.
