# CG-124: CGQL join index hint evaluates expressions over variables that are not bound yet

- Status: Open
- Priority: P2
- Area: CGQL / executor
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

`correlated_eq_hint` in `crates/cognigraph-query/src/executor/run.rs:650-659`
takes the first `var.path == expr` conjunct from any FILTER in the plan
without a scope check, and `expr` is then evaluated in the row environment at
FOR time. `mentions_var` (`:695-723`) also skips `Field` and `Conditional`
nodes, so `expr` can mention the FOR's own variable. The fast path at `:751`
skips the hint when exactly one outer row arrives, so the failure depends on
the data.

Reproduced:
`FOR x IN [1,2] FOR a IN docs FOR b IN persons FILTER a._id == b._from RETURN 1`
returns 500 "Query execution error: identifier `b` not found".

Also by source: a three-way join such as
`FOR a IN A FOR b IN B FOR c IN C FILTER b.cid == c._id FILTER a.bid == b._id RETURN 1`
works when `A` has one row and fails with two, and a correlated subquery with
`FILTER e.kind == (e.strong ? "hard" : "soft") AND e._to == p._id` fails with
"identifier `e` not found".

## Acceptance

- [ ] The hint is used only when every identifier in `expr` is bound before the FOR; `mentions_var` covers all expression variants.
- [ ] Corpus cases cover three-way joins in both filter orders, with one outer row and with several, in both engines.
- [ ] A valid query never returns 500 for a planner choice.
