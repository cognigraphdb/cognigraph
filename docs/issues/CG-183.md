# CG-183: Embeddings crate ships unreachable providers and an optional feature that no gate compiles

- Status: Open
- Priority: P3
- Area: Embeddings / crate hygiene; CI
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

The server wires only `openai`, `ollama` and `gemini`
(`crates/cognigraph-server/src/main.rs:237-283`).

- `CloudflareProvider`, `OAuthProvider` and `OnnxProvider` have no caller in
  any crate, yet Cloudflare and OAuth are default features. Their error
  messages point at flags that exist nowhere, they read `.env.cloudflare` and
  `.env.oauth` from the working directory, the OAuth constructor takes
  `danger_accept_invalid_certs`, and none overrides `model_name()`, so all
  three would cache under `"default"`.
- `completion` is gated by `#[cfg(feature = "ollama")]` while the `ollama`
  and `gemini` modules are ungated, so the `openai` and `ollama` features are
  misleading; building with only `openai` drops `completion`. The crate
  documentation lists "OpenAI, Ollama, ONNX, Cloudflare, OAuth" and omits
  Gemini.
- No CI job compiles `--features onnx`. Clippy and tests run with default
  features and with `enterprise` only (`scripts/verify.py`), while the
  freshness gate runs with all features and keeps moving `ort` (a release
  candidate) and `tokenizers`. A bump can break `onnx.rs` with CI green.
- The `paste` maintenance exception was to be reviewed by 2026-10-12
  (`docs/decisions/decision_dependency_advisories.md`, [CG-70](CG-70.md)).
  No record exists, and unlike `dependency-exceptions.json` nothing enforces
  the date.

## Acceptance

- [ ] Unreachable providers and their flag references are removed or explicitly quarantined, and the feature gates and crate documentation are corrected.
- [ ] CI at least type-checks and lints the `onnx` feature, or the feature and its dependencies are removed.
- [ ] Dated review commitments are machine-checked, or the exception moves into the enforced exceptions file.
