# CG-50: Document inspector rewrites valid stored JSON through a lossy projection

- Status: Resolved
- Priority: P1
- Area: UI / documents
- Found: 2026-09-11
- Verification: Source review and browser mutation verified by an independent HTTP read

## Problem and evidence

The JSON inspector is a projection of a fixed document template, not the
stored JSON. [normalizeDocument](../../ui/src/lib/api-documents.ts), lines 14–61,
removes `content` from the remainder and only keeps its original value when it
is an object. String, array and null content are replaced by the remainder.
[documentJson](../../ui/src/lib/documents.ts), lines 27–43, displays this projection;
[editedDocument](../../ui/src/lib/document-edit.ts) only accepts its fixed fields;
`documentPayload` sends the projected content on every PATCH.

Live reproduction: insert `audit_notes/raw_content` with
`content: "original raw string must survive"`. Open it in the browser, change
only its title and save. The server returns 200, but an independent GET shows
`content` replaced by an object containing timestamps. The UI never showed the
original content. See [before/after JSON](../evidence/ui-2026-09-11-full-review.md#artifact-4d328cb7b741f478c1aa)
and [inspector capture](../evidence/ui-2026-09-11-full-review.md#artifact-5e69f3e13a907f56b27f).

Unknown top-level fields are also displayed under `content`, so edits to that
representation do not edit the original fields. This is especially misleading
for arbitrary JSON and editable ontology drafts. The server's PATCH semantics
are not the cause; the client sends a changed value.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Keep authoritative raw JSON separate from display metadata and preserve every untouched field and JSON type through an edit.
- [x] Make the JSON editor edit actual stored fields, with explicit identity and reserved-field rules.
- [x] Add round-trip regressions for object/string/array/null content and unknown fields; verify a title-only edit and a custom-field edit through browser save and independent GET.

## Resolution — 2026-09-11

The inspector retains raw API JSON independently of display metadata and sends
only changed top-level fields from the edit-start snapshot. It preserves
unknown fields, JSON types, and hidden Native sidecar vectors. Identity, revision
and server timestamps are read-only; unsupported field removal is explicitly
rejected. Creation now reads the stored document before opening its inspector.

Six content types passed title-only browser save and independent GET checks.
Custom edits, create/edit/reload, invalid JSON, identity refusal, Viewer denial
and a real sidecar-vector HTTP regression also passed.

[Resolution report and reproducible captures](../evidence/ui-2026-09-11-data-preservation.md#artifact-6afad6337a2d11fc893d).
UI lint/type checks, all 85 helper tests and the production build pass.
