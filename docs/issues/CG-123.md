# CG-123: Stored floating-point numbers change in the last digit on write

- Status: Open
- Priority: P2
- Area: Workspace / JSON fidelity
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

The workspace depends on `serde_json = "1"` without the `float_roundtrip`
feature (`Cargo.toml`). Without it serde_json parses a float as the
significand followed by one multiply or divide by a power of ten, which is not
correctly rounded.

Reproduced through the server: `POST /api/documents` with an array of 2,000
random doubles in shortest-representation form, then `GET` of the same
document. 219 values (11%) came back different in the last place, for example
`123.80196114964559` → `123.8019611496456`.

The same parser sits behind every JSON entry point: HTTP bodies, the snapshot
import, `references repair`, and the ArangoDB dump importer
(`crates/cognigraph-cli/src/arangodump/records.rs:120`). The importer
contract in `docs/reference/arangodump-import.md` says every other field
"keeps its exact JSON value", and `decision_arangodump_importer.md` says an
imported document reads back identical to its source. The fixture dataset
only covers `0.1` and `1e300`, which survive. Embedding vectors are float
arrays, so a source-versus-stored comparison or content hash over them fails.

## Acceptance

- [ ] `serde_json/float_roundtrip` is enabled workspace-wide, or the contracts state the tolerance.
- [ ] A fixture document with 17-significant-digit doubles reads back byte-exact through the HTTP API, snapshot export/import, `references repair` and the dump importer.
