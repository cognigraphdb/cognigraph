# CG-86: Unique constraints and user-declarable indexes on ordinary collections

- Status: Resolved
- Priority: P2
- Area: Native storage / indexes
- Found: 2026-09-20
- Verification: Shared contract in all four storage modes, Native integration tests (reopen, paged, snapshots, concurrency, batch rollback), server route/error/CGQL tests on both editions, per-mode HTTP acceptance harness, full local gate before the local develop merge on 2026-09-22
- Resolved: 2026-09-22
- Scheduling: Deferred optional backlog; reconsider after the first external application integration is ready to start (owner decision 2026-09-20)

## Problem and evidence

No user-facing index API exists. [The HTTP reference](../reference/http-api.md)
lists no index route, the OpenAPI document contains no index definitions, and the
CLI and Lua surfaces expose no index primitive. The `GraphBackend::ensure_index`
contract and the `IndexType` enum exist in `cognigraph-core`, but the Native
backend implements `ensure_index` as a no-op
(`crates/cognigraph-native/src/memory/backend.rs`, `ensure_index`). The only
indexes today are internal rebuildable derivatives: the text index, the vector
sidecar, the adjacency cache and the edge upsert triple index.

Applications routinely depend on server-enforced uniqueness for identity and
authentication records, such as a user email, an OAuth provider and provider-id
pair, or a token hash, and on secondary indexes over membership arrays and
compound sort keys. Without server-enforced uniqueness, two concurrent sign-ups
or token creations can both succeed, and there is no `_rev` or conditional write
for the application to close the window itself.

This is a capability gap confirmed from documentation and source at 2.7.15, not a
reproduced defect.

## Scope and dependencies

Uniqueness is the blocking part; secondary indexes for query acceleration are
the optional part and may be split into a follow-up issue when scheduled.
Independent of [CG-84](CG-84.md), [CG-85](CG-85.md) and [CG-87](CG-87.md).
Native is the only backend, so the redb schema and the memory-primary write path
both need the constraint check inside the single backend transaction.

## Resolution

Implemented under the
[decision record](../decisions/decision_unique_indexes.md), which records the
owner's choices: uniqueness only (secondary-index pushdown deferred to a
later ticket), definitions and entries persisted in redb (schema version 3)
and written in the document's transaction, and document collections only.
Change record: [v2.7.26](../changelog/2026-09-22-unique-indexes.md).

Code: `GraphBackend::{ensure_index, list_indexes, drop_index}` with the
`UniqueViolation` error; Native `storage.rs` tables and store ops,
`storage_indexes.rs` loader, `memory/indexes.rs` (encoding, checks, batch
shadow, ensure/list/drop) wired through create, update, replace, delete,
batch, import, export and drop-collection; server 409 mapping with
`code: "unique_violation"`, guard and tenant wrappers, the three index
routes and OpenAPI entries; CGQL executor `Conflict`/`UniqueViolation`
mapped to 409 on both query routes; CLI `index list|ensure|drop`.

Edge cases covered by tests: idempotent re-declaration and a different
definition under an existing name; non-sparse null uniqueness and sparse
exemption; compound and dotted fields; value identity (number versus string,
integer versus float, object key order, array order); update and replace
keeping a document's own value; freeing a value by update or delete;
declaring over existing duplicates; edge collections and unsupported types;
batch order (freed earlier, used later) and whole-batch rollback with
persistence; reopen in every persistent mode; paged-mode enforcement over
stored rows; snapshot round trip and a duplicate-bearing snapshot; six
concurrent inserts admitting one holder; durable drop of a collection's
indexes; the 409 shape with its code versus a plain key conflict; guard
refusals for system, managed and generated names; CGQL `INSERT`, `UPSERT`
and `UPDATE`.

## Acceptance

- [x] Unique constraints on one or more fields of an ordinary collection can be
      declared through HTTP and the CLI, persist across restarts, and are listed
      by a read route.
- [x] Document routes, `POST /api/batch`, and CGQL `INSERT` and `UPSERT` reject a
      violating write atomically with a distinct documented error code, leaving
      no partial state.
- [x] Conformance tests in the shared backend suite and HTTP acceptance harness
      cover concurrent violating writes.
- [x] Secondary indexes are not included (owner decision 2026-09-22); the
      pushdown section of `docs/reference/cgql.md` is unchanged and a later
      ticket owns pushdown.
- [x] `docs/reference/http-api.md`, the OpenAPI document and the migration
      guide's index rows are updated in the same change.
