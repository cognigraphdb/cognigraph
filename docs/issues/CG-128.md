# CG-128: SUBSTRING and DATE_ADD panic and SLICE returns a wrong result on very large arguments

- Status: Open
- Priority: P2
- Area: CGQL / functions
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

Three built-ins do unchecked arithmetic on their arguments:

- `SUBSTRING`: `start + len as usize` wraps in release builds and the slice
  `chars[start..end]` then panics
  (`crates/cognigraph-query/src/functions/string.rs:52`, `:59`).
- `DATE_ADD`: a large negative amount saturates to `i64::MIN`, and
  `Duration::milliseconds(i64::MIN)` panics in chrono (`functions/date.rs:65`).
- `SLICE`: the same wrap yields an empty result (`functions/value.rs:239`).

Reproduced on `POST /api/search/query`:

- `RETURN SUBSTRING("abc", 1, 99999999999999999999)` closes the connection
  with no response.
- `RETURN DATE_ADD("2026-01-01", -99999999999999999999, "days")` does the same.
- `RETURN SLICE([1,2,3], 1, 99999999999999999999)` returns `[]` instead of
  `[2,3]`.

The values can also arrive through bind variables. There is no panic-catching
layer, so a panicking request gets no HTTP response and no log entry; the same
applies to [CG-109](CG-109.md).

## Acceptance

- [ ] All three functions use checked or saturating arithmetic: SUBSTRING and SLICE clamp as documented, DATE_ADD returns null out of range.
- [ ] Edge-case tests cover huge, negative and fractional arguments, as literals and as bind variables.
- [ ] A panic in a handler produces a logged 500 instead of a dropped connection.
