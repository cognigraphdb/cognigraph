# CG-28: CGQL specification both supports and forbids expression-position subqueries

- Status: Resolved
- Priority: P2
- Area: CGQL specification
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` (workspace 2.6.0; current drafts where noted)
- Resolved: 2026-09-09 (committed locally with CG-23 as `b9084e6`)
- Verification: Parser/validator comparison, 18 corpus cases, all Rust gates, and 148 release HTTP/Lua observations

## Problem

The specification documents expression-position subqueries and their desugaring, but its Explicitly Unsupported list still bans all subqueries outside LET values. The approved amendment narrows that exclusion, so users cannot determine the actual supported grammar from the specification.

## Evidence

`docs/cgql-v1.md:223-237,740-748`; `docs/decisions/decision_cgql_v2.md:72-100`.

## Reproduction / comparison

Compare the expression-subquery examples with the unsupported bullet `subqueries outside LET values`.

## Acceptance criteria

Replace the obsolete broad exclusion with the exact remaining mutation/post-COLLECT restrictions. Tie representative supported and rejected examples to parser/validation corpus cases.

Verify the affected runtime or documentation contract before closure. Rust changes require all repository gates. See [review evidence](review-2026-09-08.md).

## Resolution

The specification and decision record now identify supported expression
positions and the exact post-`COLLECT`, `INTO`, nested-write, and inline mutation
operand restrictions. Post-`COLLECT` inline subqueries are correctly described
as parse errors. Examples show how to preserve precomputed values through
grouping and how read subqueries can supply mutation inputs through the body.

Eighteen corpus cases pin accepted and rejected forms, including their failure
stage. All Rust gates, 144 query tests, the Native corpus, and 148 release observations
matched the documented contract and known failures. The tests also found a separate generated-binding collision, recorded
as [CG-37](CG-37.md), and a read-only HTTP error classification defect,
[CG-38](CG-38.md). CG-37 is subsequently resolved with
[separate verification](subquery-bindings-2026-09-09.md); CG-38 is also resolved
with [query-error verification](query-error-status-2026-09-09.md). See the
[verification report, corrected attempts, and limits](subquery-contract-2026-09-09.md).
