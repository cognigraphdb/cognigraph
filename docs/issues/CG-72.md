# CG-72: Login screen is off-center and clipped in narrow viewports

- Status: Resolved
- Priority: P2
- Area: UI / authentication layout
- Found: 2026-09-13
- Verification: Local production UI passes Chromium/WebKit phone-layout checks, 161 UI unit tests and 13 Community/Enterprise browser regressions on 2026-09-13; publication pending

## Problem and evidence

The login card is centered horizontally and vertically when the viewport is at
least 960 CSS pixels wide. In a narrower browser window or embedded browser pane,
it centers inside a 960-pixel document instead of the visible viewport. At
800 × 800 it is 80 pixels too far right; at 640 × 800 it is 160 pixels too far
right and its right edge is clipped. Both local and Railway installations show
the same result. The vertical center is correct at these tested heights.

[base.css](../../ui/src/styles/base.css) applies `min-width: 960px` to `html`,
`body`, `#root` and the Ant Design wrapper. The body also hides overflow. The
otherwise correct grid centering in [auth.css](../../ui/src/styles/auth.css)
therefore uses the oversized ancestor width. The desktop workspace's minimum
width currently also constrains the unauthenticated screen.

Reproduce by opening the logged-out console in a fresh browser context, setting
an 800 × 800 or 640 × 800 CSS viewport, and comparing `.auth-card`'s bounding-box
center to `innerWidth / 2`. The [dated audit](../../ui/audit/2026-09-13-login-centering/audit.md)
contains fourteen local/hosted measurements and screenshots. No credentials were
submitted and no remote data, source or deployment configuration was changed.

Suggested scope: confine the workspace minimum width to the authenticated
workspace and let the authentication screen size against the actual viewport.
Preserve existing desktop workspace behavior and check short-screen scrolling.

## Acceptance

- [x] The login card is horizontally centered within one CSS pixel at 1600,
  1280, 1067, 960, 800, 640 and 390 pixel widths; content fits the available width.
- [x] Vertical centering is preserved where the card fits; shorter screens allow
  access to the full form and validation feedback without clipping.
- [x] Real local production-console browser measurements verify the change,
  including the long hosted-origin footer, and desktop workspace checks remain green.
- [x] UI checks/tests/build and relevant browser regressions pass.

## Resolution — 2026-09-13

The 960-pixel minimum now belongs to `.app-shell`. The authentication screen
uses the real viewport width and dynamic viewport height, with a scrolling flex
container and auto card margins. The card centers when it fits and remains
reachable by scrolling when the viewport is shorter than the form. Long server
names wrap inside the card. Narrow/coarse-pointer login fields use 16-pixel text
and inputs/buttons have a 44-pixel minimum height.

[The resolution report](../../ui/audit/2026-09-13-login-responsive/audit.md)
records Chromium and WebKit touch/viewport emulation at 390 × 844, 320 × 568,
844 × 390 and 390 × 280, including required-field validation. Thirteen automated
Community/Enterprise cases pass, adding centering, login/logout width boundaries,
scrollable invalid-login feedback and a long-origin presentation fixture. The
local release server served the actual production bundle. No phone hardware or
software keyboard was available; the short-height checks emulate limited space.

Publication follow-up: the hosted v2.7.7 bundle remains unchanged. Repeat the
same hosted measurements after an authorized versioned push/deployment. This
local resolution does not establish mobile support for the authenticated console.
