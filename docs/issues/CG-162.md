# CG-162: User administration accepts empty credentials, deletion of the last admin and overflowing token lifetimes

- Status: Open
- Priority: P3
- Area: Auth / users
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

- `create_user` and tenant `bootstrap_admin` accept empty usernames and
  passwords (`crates/cognigraph-server/src/routes/users.rs:113-140`,
  `routes/tenants.rs:34-47`).
- `delete_user` lets an admin delete themselves or the tenant's last admin
  (`users.rs:158-168`). In Community, deleting the only admin account leaves
  user management unrecoverable through the API.
- `created_at + ttl` is unchecked for a client-supplied `expires_in_secs`
  (`crates/cognigraph-auth/src/lib.rs:552`, `:584`).
  `expires_in_secs: 18446744073709551615` wraps to an already-expired token in
  release builds and panics in debug builds.

## Acceptance

- [ ] Username and password minimums are enforced server-side.
- [ ] Deleting the last admin of a tenant is refused.
- [ ] Token lifetime arithmetic is checked or capped; tests cover each case.
