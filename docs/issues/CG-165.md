# CG-165: Single-document write paths skip the shape validation that batch and bulk paths enforce

- Status: Open
- Priority: P3
- Area: Native / write-path contract
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

Update and replace stamp a document on any collection without a type or
`_from`/`_to` check (`crates/cognigraph-native/src/memory/documents.rs:122-288`);
the batch path refuses the same input (`memory/batch.rs:36-56`).

- `replace_document("rels", key, {"x":1})` stores an edge without endpoints.
  It disappears from `get_edges`, adjacency and traversal. In a batch the same
  operation fails with "edge missing _from".
- `upsert_edge(…, data = 42)`, reachable through the Lua `data` argument,
  persists the scalar `42` as an edge document and records it in the triple
  index (`memory/edges.rs:105-164`).
- `create_document` accepts arrays and scalars (stored under a random key
  with no `_key`) and `_key: ""`; `bulk_insert` refuses both
  (`memory/helpers.rs:46-72`).
- Resident `upsert_edge` calls `collection_mut` (`edges.rs:142`) before
  `persist` (`:150`). A failed commit leaves a phantom collection in memory
  that `ensure_collection` then treats as existing.

Also noted: paged projection and keyset listing do not strip `embedding` as
the resident sidecar path does (`documents.rs:396-401`, `:428-433`).

## Acceptance

- [ ] One shared validator for document and edge shape covers create, update, replace, upsert, batch, bulk and import.
- [ ] Memory mutation in `upsert_edge` happens after the commit.
- [ ] Edge-case tests cover each path in resident and paged modes.
