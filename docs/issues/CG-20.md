# CG-20: Arango indexed vector search filters model identity too late

- Status: Resolved

## Original problem

The indexed vector path takes the global top `3 × limit` candidates before filtering `model_name`. If those candidates belong to another model, valid requested-model results outside that prefix disappear. The fallback path filters model identity before ranking, so changing execution mode changes correctness beyond ordinary approximate-neighbor variation.

## Original review evidence

- `crates/cognigraph-arango/src/backend/graph_backend.rs:348-394` — indexed post-limit model filter versus fallback pre-filter.

## Reproduction / failure sequence

With limit 1, place three highest-scoring embeddings under model A and a fourth eligible embedding under model B. Query model B. The indexed query's candidate subquery can contain only A rows and return no results, while fallback returns B.

## Acceptance criteria

- [x] Restrict the search population by model before candidate truncation, use model-specific indexes/collections, or fall back to a correct supported path.
- [x] Avoid a fixed over-fetch factor as the correctness mechanism for model filtering.
- [x] Add mixed-model retrieval parity tests, including an empty result prefix and duplicate parent documents.

Run the repository Rust gates and a focused runtime regression before closing this issue. See [review evidence](review-2026-09-08.md).

## Resolution

The indexed query filters model identity inside the vector lookup before its
candidate limit. Both indexed and fallback paths expand candidate windows until
enough distinct parents are returned or eligible candidates are exhausted;
no fixed over-fetch factor provides the correctness boundary. Existing
highest-scoring-chunk selection, thresholds, and row identity remain intact.

Filtered indexed search requires ArangoDB ≥3.12.6; older deployments can select
fallback. Approximate recall remains governed by the index and search effort.
See the [decision](../decisions/decision_arango_vector_candidates.md) and
[full verification report](vector-model-filter-2026-09-09.md).

The 12-case indexed/fallback fixture, all 58 Arango tests (eight live integration
tests), formatting, strict Clippy, all 925 workspace tests, and 88 release
HTTP/Lua checks passed. The actual release AQL uses an `EnumerateNearVectorNode`
with a model filter, and the duplicate-parent case expands from 4 to 64
candidates. The saved release reproduced 40 Arango mismatches across two
lifetimes; the corrected release produced none. The separate Native sidecar
failure remains [CG-34](CG-34.md), with eight live HTTP/Lua reproductions.
