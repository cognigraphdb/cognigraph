# CG-52: Tenant onboarding and user provisioning diverge from the authorization contract

- Status: Open
- Priority: P2
- Area: UI / access
- Found: 2026-09-11
- Verification: Browser provisioning walkthrough and real HTTP authorization probes

## Problem and evidence

The create-tenant dialog tells the operator to file users under the new tenant
through User management ([TenantsScreen.tsx](../../ui/src/screens/TenantsScreen.tsx),
lines 308–317). A host-admin can create the tenant but has no UserAdmin scope;
the suggested next page returns 403. An ordinary tenant admin cannot create a
user in another tenant. No UI control calls the implemented
`POST /api/tenants/{name}/admin` bootstrap endpoint.

The user form also offers `host-admin` and a free tenant field. Both host-admin
creation and cross-tenant creation are explicitly refused by
[users.rs](../../crates/cognigraph-server/src/routes/users.rs), lines 113–135.
The [role list](../../ui/src/lib/users.ts), lines 7–15, omits the implemented
policy-author, policy-approver, promoter and artifact-attestor roles, preventing
normal UI provisioning of those accounts.

Live: create `audit-ui-new` as host-admin, follow Users and receive 403; submit
host-admin creation as admin and receive the specific inline 403; submit
cross-tenant creation over HTTP and receive 403. Dedicated tenant-admin
bootstrap succeeds over HTTP. [New tenant](../../ui/audit/2026-09-11-full-review/10-new-tenant-no-bootstrap.png),
[forbidden role form](../../ui/audit/2026-09-11-full-review/07-forbidden-host-user-form.png).
The server correctly enforces its boundaries. The dialog's claim that quotas
are not enforced is also stale: `max_active_jobs` is enforced by the server.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [ ] Provide an authorized first-admin bootstrap step for newly created tenants, or an explicit accurate API handoff until that UI is implemented.
- [ ] Constrain tenant-user creation to the current tenant and roles the actor may create; include supported governance roles where applicable.
- [ ] Correct quota guidance and test new-tenant login, denied cross-tenant provisioning and host-admin data denial.
