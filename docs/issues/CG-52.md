# CG-52: Tenant onboarding and user provisioning diverge from the authorization contract

- Status: Resolved
- Priority: P2
- Area: UI / access
- Found: 2026-09-11
- Verification: Browser provisioning walkthrough and real HTTP authorization probes

## Problem and evidence

The create-tenant dialog tells the operator to file users under the new tenant
through User management ([TenantsScreen.tsx](../../ui/src/screens/TenantsScreen.tsx),
lines 308–317). A host-admin can create the tenant but has no UserAdmin scope;
the suggested next page returns 403. An ordinary tenant admin cannot create a
user in another tenant. No UI control calls the implemented
`POST /api/tenants/{name}/admin` bootstrap endpoint.

The user form also offers `host-admin` and a free tenant field. Both host-admin
creation and cross-tenant creation are explicitly refused by
[users.rs](../../crates/cognigraph-server/src/routes/users.rs), lines 113–135.
The [role list](../../ui/src/lib/users.ts), lines 7–15, omits the implemented
policy-author, policy-approver, promoter and artifact-attestor roles, preventing
normal UI provisioning of those accounts.

Live: create `audit-ui-new` as host-admin, follow Users and receive 403; submit
host-admin creation as admin and receive the specific inline 403; submit
cross-tenant creation over HTTP and receive 403. Dedicated tenant-admin
bootstrap succeeds over HTTP. [New tenant](../evidence/ui-2026-09-11-full-review.md#artifact-c716899b4d43d46f386a),
[forbidden role form](../evidence/ui-2026-09-11-full-review.md#artifact-d365aed9d9534371b052).
The server correctly enforces its boundaries. The dialog's claim that quotas
are not enforced is also stale: `max_active_jobs` is enforced by the server.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Provide an authorized first-admin bootstrap step for newly created tenants, or an explicit accurate API handoff until that UI is implemented.
- [x] Constrain tenant-user creation to the current tenant and roles the actor may create; include supported governance roles where applicable.
- [x] Correct quota guidance and test new-tenant login, denied cross-tenant provisioning and host-admin data denial.

## Resolution — 2026-09-11

Tenant creation opens a first-admin form using the existing host-authorized
bootstrap endpoint. Closing it preserves the tenant; the row's Set up admin
action resumes setup. The console retains inline conflicts, validates the
returned administrator identity and explains the switch to a tenant-admin
session. An existing Admin prevents further bootstrap; the form does not reset
credentials or grant the host-admin user-management authority.

User creation shows the authenticated tenant and omits the tenant override from
the request. Only a tenant Admin can open the form. Community offers four data
roles; a verified Enterprise edition additionally offers policy-author,
policy-approver, promoter and artifact-attestor. Host-admin is never a creatable
role. Unknown edition metadata conservatively retains the four data roles.
Quota guidance now names the enforced `max_active_jobs` limit.

UI lint/types, **100 tests** and production build pass. Real Native Enterprise
browser checks created a tenant, resumed setup after cancel/reload, recovered
from a global username conflict, refused a second bootstrap, signed in as the
new admin, and created all four governance roles plus a viewer. Fresh browser
and HTTP reads confirmed their tenant and roles. Community creation/reload/login
also passed with its four-role form. Direct HTTP attempts at cross-tenant user
creation, host-admin creation, host-admin data/user access and tenant-admin
bootstrap returned 403. Keyboard return focus and desktop/scaled layouts passed.

The [audit and sealed manifest](../evidence/ui-2026-09-11-provisioning.md#artifact-e96a930169a1f87db8a2)
record build identities, captures, executed checks and limitations. Governance
credentials were verified over HTTP; governance console navigation and workflows
remain outside this ticket, under [CG-53](CG-53.md) and the UI feature backlog.
No Rust source changed; no remote CI, push or publication was performed.
