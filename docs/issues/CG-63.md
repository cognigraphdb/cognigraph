# CG-63: Collapsed sidebar removes the accessible names of navigation links

- Status: Resolved
- Priority: P2
- Area: UI / accessibility
- Found: 2026-09-11
- Verification: Rust-served browser accessibility trees, keyboard/pointer journeys and Admin/HostAdmin checks

## Problem and evidence

[Sidebar.tsx](../../ui/src/components/Sidebar.tsx), lines 56–68, gives links
only a text span and an aria-hidden icon. Manual collapse applies
`.sidebar.collapsed .nav-item span { display: none; }` in
[layout.css](../../ui/src/styles/layout.css), lines 258–262. No `aria-label`
remains on the links.

After clicking Collapse sidebar, the browser accessibility snapshot lists nine
unnamed links. Before collapse the same links are named Overview, Collections,
Query, etc. [Captured accessibility representation](../evidence/ui-2026-09-11-full-review.md#artifact-5cc129d78dc72560e2a5).
The links still navigate by pointer or keyboard, but assistive technology loses
their purpose. This is distinct from table actions that cannot receive keyboard
focus at all (CG-57). The responsive font-size-only collapse is a separate CSS
path and was not assumed to have the same defect.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Keep a stable accessible name on every navigation link in expanded, manually collapsed and responsive states.
- [x] Provide discoverable labels for icon-only pointer use while retaining visible keyboard focus.
- [x] Check the accessibility tree and keyboard navigation in all sidebar modes; each link must retain its specific destination name.

## Resolution — 2026-09-11

Every sidebar `NavLink` now has an explicit `aria-label` from its destination
label. Its name therefore survives both manual `display: none` label hiding and
the responsive icon-only layout. Shared Ant Design tooltips expose the same
label on hover and focus, without introducing another tab stop. Native link
semantics, active-page state, existing focus outlines and route authorization
remain in place.

## Verification and limits

- Reproduced nine unnamed links on the original manually collapsed sidebar.
- All nine Admin destinations retain their distinct names in expanded,
  manually collapsed and responsive modes. Tab visits each link in order,
  with a visible 2px outline; Enter activates the expected routes.
- A real HostAdmin session exposes only Overview and Tenants. Tenants retains
  its name in all three modes, opens with Enter and survives a direct reload.
  Reciprocal Admin/HostAdmin API scope checks still return the expected 200/403.
- Pointer movement onto Query shows its tooltip while focus remains on the
  document body. Focus also reveals labels; moving focus away dismisses them.
- Actual 1280×800 and 1067×667 viewports preserve link, tooltip and focus bounds.
  UI lint/types, all 161 tests, production build and documentation checks pass.

[Browser evidence and build manifest](../evidence/ui-2026-09-11-sidebar-names.md#artifact-2bc6b4831aa16897066a).
No Rust or authorization logic changed. This verifies accessible names and
keyboard/pointer behavior; it does not certify screen-reader speech output,
native Windows scaling or every mobile viewport. No model calls or remote push.
