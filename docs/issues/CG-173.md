# CG-173: The sideviews.generate worker has no execution test, and an empty regeneration erases existing rows

- Status: Open
- Priority: P3
- Area: Server / jobs; side views (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

No in-crate test runs a side-view job through the dispatcher or references
`side_views_written`; `jobs/tests/sideviews.rs` covers preparation and
serialization only. The worker branch is
`crates/cognigraph-server/src/jobs/worker.rs:323-463`.

With `regenerate: true` and a completion that returns `pairs: []`, `publish`
deletes the parent's rows and inserts none (`side_views.rs:125-143`).
`docs/operations/jobs.md:97-99` says regeneration replaces rows "after
successful completion/embedding". `side_views_written` also under-counts
after a mid-batch failure and resume, because published parents are skipped.

## Acceptance

- [ ] Dispatcher-level tests cover checkpoint and resume, cancel at a boundary, a mid-batch provider error and retry, an embedding-count mismatch and tenant scoping.
- [ ] The behaviour for an empty regeneration result is decided (keep the rows, or fail) and tested.
