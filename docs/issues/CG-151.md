# CG-151: Enterprise Clippy gate fails on the current stable toolchain, and no toolchain is pinned

- Status: Resolved
- Priority: P2
- Area: Build / CI
- Found: 2026-11-11
- Verification: Both Clippy gates, formatting and both test suites pass on rustc 1.99.1 after the fix (809 Community and 1,036 Enterprise tests); the new gauge test and three workflow policy tests pass; `actionlint` accepts both workflows. The canary's first remote run is unverified until the change reaches the default branch
- Resolved: 2026-11-11

## Problem and evidence

`cargo clippy --locked --all-targets --features enterprise -- -D warnings`
fails on rustc 1.99.1:

```
error: use of deprecated method `std::sync::atomic::Atomic::<u64>::fetch_update`:
       renamed to `try_update` for consistency
  --> crates/cognigraph-server/src/jobs/capacity.rs:111:51
```

The Community Clippy run passes because the job module is Enterprise-only.
Both test suites pass (809 Community and 1,035 Enterprise tests, 2 ignored in
each), since a deprecation is only a warning without `-D warnings`.

The repository has no `rust-toolchain.toml` and no `rust-version`, and
`.github/workflows/ci.yml` installs floating `stable`. `docs/operations/ci.md`
records floating stable as policy. The effect is that a required gate turns
red with a compiler release rather than with a change, and a local run and a
CI run of the same commit can disagree. The push workflow treats a failed
check as blocking, so the next push is blocked until this is fixed.

## Resolution

`release_cancel_requested` in `crates/cognigraph-server/src/jobs/capacity.rs`
now uses the infallible `AtomicU64::update` (stable since Rust 1.95) with the
same saturating decrement. A test in `jobs/tests/capacity.rs` pins the
behaviour the call exists for: the gauge drops only when a job leaves
`cancel_requested`, and an unmatched release stays at zero instead of
wrapping.

The owner chose to keep floating stable and add a weekly canary. The
[decision record](../decisions/decision_toolchain_policy.md) states the
policy and the rejected alternatives: `.github/workflows/toolchain.yml` runs
formatting and both Clippy gates on the default branch every Tuesday, is not
a required check, and is covered by policy tests in
`scripts/tests/test_ci_policy.py`. No `rust-version` is declared, because no
compiler older than current stable is built or tested.

Not verified: the gauge was not exercised over HTTP against a running
Enterprise server, and the scheduled workflow has not run on GitHub yet.

## Acceptance

- [x] The deprecated call is replaced and both Clippy runs pass on the current stable toolchain.
- [x] The toolchain policy is decided and recorded: either a pinned toolchain bumped deliberately (Renovate or a scheduled job), or floating stable with a scheduled run that surfaces new lints before they block a push.
- [x] `rust-version` states the minimum supported compiler. Decided otherwise: none is declared, and the decision record says why.
