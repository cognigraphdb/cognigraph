# CG-98: Re-benchmark embedding models for side-view retrieval, including multilingual queries

- Status: Resolved
- Priority: P2
- Area: Retrieval / embeddings
- Found: 2026-09-23
- Verification: Measured 2026-09-23 through the product hybrid search on a 2.7.38 release build: five embedders, 500 queries, six configurations; harness unit tests and a provider-free preflight; raw inputs and results sealed in the private evidence repository; full local gate before the local develop merge
- Resolved: 2026-09-23
- Scheduling: Owner request 2026-09-23 after CG-97: re-run the side-view recall comparison with OpenAI small and large, and add multilingual models

## Problem and evidence

The only embedding comparison on record is the 2026-07-20 DailyMed recall
evaluation in the
[side-view decision](../decisions/decision_sideviews_provider_and_benchmark.md#recall-evaluation-2026-07-20-dailymed).
It used 130 labels, 1,300 side views and 30 lay queries. `gemini-embedding-2`
gained most from side views and became the local default. That test is stale
and cannot be re-run: its script, query set and side views are not preserved
in any repository. With 30 queries, one query moves recall by 3.3 points,
which is too coarse to separate close models. It measured English only,
although the product is sold into multilingual markets.

## Owner decisions (2026-09-23)

- 200 DailyMed prescription labels with distinct active ingredients, from the
  local pilot corpus, and 100 lay queries with drug names removed.
- Queries and their translations are written by Claude and recorded with
  their target labels.
- Cross-lingual retrieval: the same queries in Portuguese, Spanish, German and
  French against the English labels.
- Embedders: OpenAI `text-embedding-3-small` and `text-embedding-3-large`,
  Gemini `gemini-embedding-2`, and the local open models Qwen3-Embedding 8B
  and BGE-M3 through Ollama.
- Side views are generated once with `gpt-5.6-luna`. Every embedder then
  embeds the same side-view texts.

## Acceptance

- [x] The frozen inputs (label selection, queries, side views) are sealed so
      the benchmark can be re-run without side-view model calls. The
      [evidence policy](../operations/evidence-policy.md) classes labelled
      query sets and provider output as private evaluation data, so they go
      to the private evidence repository, not public fixtures.
- [x] A harness runs every embedder through the product's own hybrid search
      and reports recall@1/5/10 and MRR@10 per language and configuration,
      with 95% bootstrap intervals.
- [x] A dated research note records the results with unit, source and
      limitation; the raw run is sealed in the private evidence repository.
- [x] The side-view decision is amended with the new results and states
      whether the default embedder should change.

## Resolution

Resolved 2026-09-23 in v2.7.39
([research note](../research/benchmarks/embedding-recall-2026-09-23.md),
[decision amendment](../decisions/decision_sideviews_provider_and_benchmark.md#recall-re-benchmark-2026-09-23),
[change record](../changelog/2026-09-23-embedding-recall-benchmark.md)).

- **Gemini is best.** `gemini-embedding-2` led in every language, with
  MRR@10 of 0.846 to 0.881 in hybrid search with side views. Paired
  intervals against every other model exclude zero. It stays the default.
- **OpenAI.** `text-embedding-3-large` (0.752 to 0.793) is the recommended
  OpenAI model. `text-embedding-3-small` (0.566 to 0.668) is not
  recommended.
- **Local models.** Qwen3-Embedding 8B reached 0.691 to 0.733 through
  Ollama, mainly thanks to side views. BGE-M3 reached 0.416 to 0.543.
- **Side views.** The lift was +0.01 to +0.05 for the strong models, far
  below the July figure. Weight 0.35 made no difference.
- **Inputs are private.** The evidence policy classes the frozen inputs as
  labelled evaluation data, so they live in the private evidence repository.
  The harness reads them with `--inputs`.
- **Found along the way:**
  - [CG-99](CG-99.md) (P1): concurrent text searches after a write fail
    while the persistent text index rebuilds;
  - [CG-100](CG-100.md) (P3): Ollama requests time out after a fixed 120 s;
  - [CG-101](CG-101.md) (P3): hybrid fusion sums chunk ranks per parent;
  - [CG-102](CG-102.md) (P3): providers cannot mark queries versus
    documents.
