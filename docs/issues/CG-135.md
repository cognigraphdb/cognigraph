# CG-135: Governance admission trusts the wall clock in ways stored-authority validation later rejects

- Status: Open
- Priority: P2
- Area: Server / governance time handling (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

Acceptance time is `SystemTime::now()` with no monotonic floor
(`promotions/record_identity.rs:41-46`).

- **Backward step.** Live admission never checks
  `policy.created_at_ms <= at_ms` or `approval.approved_at_ms <= at_ms`
  (`governance/policy_binding.rs:27-82`); historical validation rejects exactly
  that (`historical_binding.rs:33-36`). After an approval at T, a clock step
  back (NTP step, VM restore) lets evidence register at T−δ. The next
  reconcile fails with "promotion binding does not match its historical signed
  policy authority". The record is immutable, so recovery never succeeds, and
  with [CG-131](CG-131.md) the next restart aborts.
- **Revocation.** The live check is
  `recorded_at_ms <= at_ms && effective_at_ms <= at_ms`
  (`governance/queries.rs:171`), so a stored revocation is ignored whenever
  `now` is below its `recorded_at_ms`. A revoked key is usable again for any
  request stamped before the revocation.
- **Forward skew of the server.** Semantic-repair review rejects
  `signed_at_ms < revision.created_at_ms` (`semantic_repairs.rs:1137-1140`).
  `created_at_ms` is the server clock and `signed_at_ms` the signer's; future
  skew has a five-minute allowance and past skew none. A review signed on a
  host one second behind the server gets 409 "authority mismatch" with no
  hint about timing. An in-file test works around it.

The first two need a clock regression to trigger; the third does not.

## Acceptance

- [ ] Acceptance timestamps are clamped to at least the newest stored authority timestamp, or admission refuses when the clock is behind it.
- [ ] The live revocation check does not depend on `recorded_at_ms`, and live admission enforces every ordering that historical validation enforces.
- [ ] The review ordering check allows the same skew as the future bound and names the timestamps in its error; tests use an injected clock.
