# CG-116: Tenant lifecycle validation failures return 401 and sign the host admin out of the console

- Status: Open
- Priority: P2
- Area: Auth / tenants (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`create_tenant` in `crates/cognigraph-auth/src/lib.rs:351-362` reports an
invalid tenant name through `auth_err(..)`, which the server maps to 401
(`error.rs:20`). The same happens for an unknown tenant in
`set_tenant_status` and `set_tenant_quotas` (`:405`, `:422`) and for "the
default tenant cannot be deleted" (`:441-445`). The console treats any 401 on
a request that carried a token as session expiry and clears the token
(`ui/src/api/client.ts:39`). The create-tenant form only requires a non-empty
name.

Failure sequence: the host admin types `Acme Corp` in "Create a tenant". The
server answers 401 with the name-rule message, and the console shows "Session
expired — please sign in again" and returns to the login screen.
`DELETE /api/tenants/default` behaves the same way.

## Acceptance

- [ ] Name-rule violations return 400, an unknown tenant returns 404, and deleting the default tenant returns 400 or 409.
- [ ] 401 is reserved for credential failures; route tests assert each status.
- [ ] The console form validates the name rule before submitting.
