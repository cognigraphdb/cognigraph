# CG-74: Login layout test can measure the transient connection card after logout

- Status: Resolved
- Priority: P2
- Area: UI QA / CI
- Found: 2026-09-13
- Verification: Twenty repeated logout journeys, full local CI and both Docker editions pass; corrected PR and promotion CI pass; v2.7.11 integrated into main.

## Problem and evidence

The v2.7.10 promotion [CI run](https://github.com/cognigraphdb/cognigraph/actions/runs/34751310005)
failed in the Community logout layout regression with `Login geometry is unavailable`.
Both Rust editions and all 514 Native checks passed before browser execution.
Five Community browser cases passed; the next case failed, the remaining case
did not run, and the Enterprise browser and Docker jobs were not reached.

`expectCentered()` waited for `.auth-card`, which is shared by `LoginScreen`
and `ConnectionGate`. Logout probes `/api/auth/session` and temporarily renders
the connection card. The generic visibility assertion can pass on that card;
React then replaces it before `boundingBox()`, which returns null. The captured
failure screenshot and final DOM show a correctly centered login form.

Scope the card locator to its exact `CogniGraph Console` heading. This waits for
the actual login form without changing production code, geometry tolerances,
overflow checks or failure policy. The earlier v2.7.10 visibility wait and its
passing historical runs remain evidence of that checkpoint, not proof that the
intermittent selector defect was fixed.

The [browser report](../evidence/ui-2026-09-13-login-card-selection.md#artifact-e88d1680df2562dd58a3)
retains the failure screenshot, source explanation and repeated local evidence.
The corrected candidate is prepared as v2.7.11 because v2.7.10 was already
pushed; changed source must not reuse that version. No images were uploaded
and production remains v2.7.7 at this checkpoint.
