# CG-198: CGQL budget and runtime errors answer HTTP 500

- Status: Open
- Priority: P2
- Area: Server / CGQL routes
- Found: 2026-11-11
- Verification: Live (seen on the 2.7.53 release server on 2026-11-11 while checking CG-111)
- Scheduling: After the P1 batch

## Problem and evidence

Both query routes map every execution error they do not name to
`CogniGraphError::QueryError`, which answers HTTP 500
(`routes/query.rs`, `cgql_error` in `routes/search/basic.rs`). That includes
the four budget errors and the type errors a query can cause itself
(`ExpectedBool`, `ExpectedNumber`, `ExpectedArraySource`, an unknown bind
variable).

Seen live: `POST /api/search/query` with a cross product answered

```
HTTP 500  Query execution error: query exceeded its memory budget (1073741824 bytes)
```

and a query stopped by its time budget answered 500 as well.

A budget refusal is the designed outcome of a request the caller wrote, not a
server fault. As 500 it is logged at `warn`, counts as a server error in
metrics and monitoring, and tells a client to retry a request that will fail
the same way. [CG-38](CG-38.md) fixed the same thing for parse and
validation errors.

## Acceptance

- [ ] The source-row, intermediate-row, memory and time budget errors answer a 4xx status chosen once and documented in the HTTP reference; the body names the budget and its limit.
- [ ] Query type errors and a missing bind variable answer 400.
- [ ] A backend or internal failure still answers 5xx.
- [ ] Route tests cover one case of each group on both query routes, and Lua `graph.query()` errors keep their text.
