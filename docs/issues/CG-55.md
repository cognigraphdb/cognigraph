# CG-55: Console keyboard shortcuts bypass the running request guard

- Status: Resolved
- Priority: P2
- Area: UI / execution
- Found: 2026-09-11
- Verification: 137 UI tests, production build, delayed real Lua/CGQL executions and persisted Lua write counts

## Problem and evidence

The buttons become disabled while a request runs, but
[LuaScreen.run](../../ui/src/screens/LuaScreen.tsx), lines 52–66, and
[QueryScreen.runQuery](../../ui/src/screens/QueryScreen.tsx), lines 60–83,
have no execution guard. Their CodeMirror shortcuts call these functions even
while `running` is true ([LuaEditor](../../ui/src/components/LuaEditor.tsx),
line 30; [CgqlEditor](../../ui/src/components/CgqlEditor.tsx), line 39).

The real Community API was forwarded through a local proxy that delayed Lua
responses by three seconds, without changing their contents. Clicking Run and
then pressing Ctrl+Enter sent two POSTs roughly 256 ms apart; both returned 200.
The button was visibly disabled during the second submission.
[Request evidence](../evidence/ui-2026-09-11-full-review.md#artifact-de4344cc55b0d4afcacc).
The test used a read-only script. A write-scoped script could duplicate its
side effects. Query has the same source defect but was not separately raced.
Overlapping completions can also clear busy state too early or replace a newer
result; result provenance is tracked in CG-56.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Use one synchronous in-flight guard for every submission path, including keyboard shortcuts and form submit.
- [x] Keep request/result ownership until that execution completes; prevent an older completion from clearing a newer busy state.
- [x] Test repeated shortcuts against a deliberately slow real request and verify exactly one execution, including a disposable write-count regression for Lua.

## Resolution — 2026-09-11

[useExecution](../../ui/src/hooks/useExecution.ts) shares a synchronous
[execution guard](../../ui/src/lib/execution-guard.ts) across each console's
submission paths. It claims the slot before invoking caller code and keeps it
through success or failure. Screen/connection cleanup invalidates publication
of results, timings, history and notifications without claiming to cancel a
server write. Busy state is scoped to its owning guard.

Five regression tests cover same-tick/reentrant submission, rejected requests,
synchronous failures, invalidated pending work and completion ownership. All
137 UI tests, lint/types and the production build pass.

The real Enterprise/Native binary served the production UI through a response-delay
proxy. Run plus repeated Ctrl/Command+Enter produced one request and one persisted
Lua document; a later intentional run produced precisely one more. CGQL form
submit and both shortcuts also produced one execution, counting non-executing
EXPLAIN validation separately. Real server errors recovered; invalid bindings
sent no execution; leaving a screen and switching query tabs preserved ownership.
[Browser, request timing, persistence and limitations](../evidence/ui-2026-09-11-execution-guards.md#artifact-ba0883e40b9f39017230).

This is a guard for a mounted console and connection, not server idempotency
across browser tabs or page reloads. Edited-input/result provenance remains
[CG-56](CG-56.md).
