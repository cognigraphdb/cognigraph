# CG-48: Quick-start examples must match network and query contracts

- Status: Resolved
- Priority: P2
- Area: Documentation / onboarding
- Found: 2026-09-10
- Verification: Source review, real release-server HTTP walkthrough and Docker binding check

## Problem and evidence

The new Docker example published port 3000 on every interface while the next
paragraph said both demo paths used loopback. Authentication defaults to off.
The Kubernetes one-line install omitted required authentication values, and the
read-only query route was described as always safe to expose despite returning
application data under the configured access policy.

## Resolution and verification

Bind the Docker example explicitly to `127.0.0.1`, direct Helm installation to
the complete authenticated instructions, and describe the query route's access
requirements accurately. The Helm verification container used the same explicit
loopback Docker binding. Its Docker port inspection and HTTP requests passed.

Run the four README HTTP examples against a fresh release-server database with
authentication disabled, embeddings off and mutations enabled. Both document
inserts, relationship creation and the correlated traversal returned HTTP 200;
the query returned Apple / Orchard Co. The opening grouped traversal also
returned Orchard Co with count 1. Disposable data and the process were removed.
These are local synthetic checks, not a deployment or load test.

## Acceptance

- [x] The unauthenticated Docker example binds only to loopback.
- [x] Kubernetes instructions include authentication prerequisites.
- [x] Query exposure guidance matches the access contract.
- [x] The data/query walkthrough executes against the real binary.
