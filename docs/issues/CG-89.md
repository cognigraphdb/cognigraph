# CG-89: Graph-augmented search defaults to document_relations and omits neuron-built facts

- Status: Open
- Priority: P2
- Area: Server / search
- Found: 2026-09-22
- Verification: Pending

## Problem and evidence

`POST /api/search/graph-augmented`
(`crates/cognigraph-server/src/routes/search/graph_augmented.rs`) embeds the
query, takes `seed_limit` vector seeds, traverses `edge_collection` from each
seed, and ranks the traversed edges into the `graph_facts` trace with
`select_graph_edges` (`crates/cognigraph-core/src/graph_ranking.rs`).
`default_edge_collection()` returns `"document_relations"`.

Governed construction writes fact edges into `facts`
(`crates/cognigraph-construct/src/ingest.rs`), and accepted `relation_rank_hint`
neurons are read from `neurons_collection` to boost relations in that same
ranking step. With the default request body the traversal never touches
`facts`, so:

- neuron-built edges are absent from `graph_facts` unless the caller passes
  `edge_collection: "facts"`;
- rank-hint boosts are computed against `document_relations` edges that no
  neuron produced, so an accepted rank hint has no observable effect on a
  default request;
- the answer-evaluation route (`crates/cognigraph-construct/src/answers.rs`)
  reads `facts` directly, so `/answer-eval` and a default `/search/graph-augmented`
  call rank different edge sets for the same question.

`docs/reference/http-api.md` documents `edge_collection` as optional and does
not state that neuron facts require the override. Confirmed from source at
2.7.15; not reproduced live.

## Scope and options

Either outcome closes the issue as long as it is decided and documented:

1. Keep `document_relations` as the default for Community and make the
   Enterprise default `facts` when the construct feature is compiled in; or
2. Keep one default and reject silently-inert rank hints by returning a
   warning in the response when `neurons_collection` holds accepted rank hints
   and `edge_collection` is not `facts`; or
3. Traverse both collections and merge, with the ranking already distinguishing
   configured relations from low-signal ones.

Independent of [CG-88](CG-88.md) and [CG-90](CG-90.md).

## Acceptance

- [ ] A decision record states the default edge collection per edition and
      why, and `docs/reference/http-api.md` plus the OpenAPI description of
      `edge_collection` say when neuron-built facts enter the trace.
- [ ] A route test asserts that, on the documented default, an accepted
      `relation_rank_hint` changes `graph_facts` ordering for a fixture space
      whose facts were built by `/api/construct/ingest`.
- [ ] A real-runtime regression on the Enterprise build runs `/construct/ingest`
      on a fixture kit, then `/search/graph-augmented` with no `edge_collection`,
      and shows at least one `facts` edge with `evidence_chunk_id` in the trace
      (or the documented warning if option 2 is chosen).
- [ ] Query-cache entry meta still separates the two edge sets so a cached
      `document_relations` trace is never served for a `facts` request.
