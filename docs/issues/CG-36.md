# CG-36: Dedicated review judges ignore the configured OpenAI base URL

- Status: Resolved
- Priority: P2
- Area: Review-provider configuration
- Found: 2026-09-09 during CG-21 runtime verification
- Reviewed revision: `8164f4e` plus CG-21 changes
- Resolved: 2026-09-09 (local commit `57d65af`)
- Verification: Rust gates and controlled release HTTP routing/startup matrices

## Problem

At the reviewed revision, the shared completion resolver honors `OPENAI_BASE_URL`, including when the
review judge falls back to the completion provider. Setting
`COGNIGRAPH_JUDGE_MODEL` instead constructs an OpenAI provider with `None` for
the base URL. The agreement-lane partner does the same. Both therefore use
`https://api.openai.com/v1` even when construction and fallback review use a
configured proxy or compatible endpoint.

Adding a dedicated judge model can silently change the destination for review
material and credentials. It also prevents a fully local two-judge release
regression through the existing base-URL setting. This is independent of model
qualification and does not call for a new model benchmark.

## Evidence

- `crates/cognigraph-server/src/main.rs`: both dedicated judge constructors
  call `OpenAiCompletion::new(key, None, Some(model))`.
- `crates/cognigraph-embeddings/src/completion.rs`: a missing base URL selects
  the external OpenAI endpoint.
- `crates/cognigraph-embeddings/src/completion/config.rs`: the shared resolver
  validates and passes `OPENAI_BASE_URL` for normal and inherited completions.
- CG-21's release harness consequently uses the configured completion provider
  as its fallback judge. Dedicated partner races are covered through the real
  routers with injected providers, rather than an external model call.

## Acceptance criteria

- [x] Honor a validated, documented endpoint setting for dedicated primary and
  partner judges, preserving their explicit model selection and qualification
  rules. Do not silently reinterpret judge provider selection.
- [x] Share endpoint parsing/validation with the existing completion resolver.
- [x] Verify fallback, dedicated primary, and dedicated partner routing against
  controlled local endpoints with the Rust gates and release HTTP checks.

## Resolution

Both dedicated models are captured in `CompletionConfig` and resolved through
its existing OpenAI credential/endpoint validation before storage opens. They
retain explicit OpenAI model selection even when the main provider is Gemini.
Blank/absent models preserve fallback/absent-partner behavior; a nonempty
dedicated model now requires a nonempty OpenAI key and valid selected endpoint.
Qualification, prompts, symbolic validation, and publication rules are unchanged.

The saved release reproduced nine blocked default-endpoint attempts without
forwarding connections. The corrected release passed 22 review scenarios and
12 invalid-configuration rejections across the documented matrix, with 58 local
screen/quality requests and zero outbound judge connection attempts. Formatting,
strict Clippy, 21 focused embedding tests, 24 review route tests, and 961 reported
workspace tests passed. Eight unconfigured Arango entries early-returned; the
two existing live embedding tests passed with local credentials. No real judge
qualification or model benchmark was run. See the
[verification report](judge-endpoint-2026-09-09.md) for evidence and limits.
