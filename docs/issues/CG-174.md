# CG-174: Compatibility branches for unreleased clients and the retired non-atomic backend remain in jobs, side views and M26

- Status: Open
- Priority: P3
- Area: Server / maintenance
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

With no users and Native as the only backend, these paths serve clients and
stores that never shipped:

- Non-atomic and "remote backend" branches in
  `crates/cognigraph-server/src/side_views.rs:165-181`, `:254-261`,
  `:275-283`, `:324-340` and `routes/documents.rs:142`; Native always reports
  atomic batches.
- Non-atomic probes in `materialized_repairs/backend_capability.rs:15-38`,
  `legacy_ingest.rs`, `recovery.rs`, `status.rs` and `snapshot_preflight.rs`.
  `RoutedBackend::supports_atomic_batches` returns false whenever the tenant
  store cannot be resolved (`tenancy.rs:199-202`), so an M26 request for such
  a tenant may report "requires atomic batch support; backend is unsupported"
  instead of the real error (plausible; store failure modes not traced).
- Version 1 job cursors (`jobs/cursors.rs:54-64`).
- The deprecated offset job listing (`jobs/listing.rs:120-172`,
  `routes/jobs.rs:114-144`), an uncapped hot scan open to graph-read callers.
- `legacy:{created_at}` tenant incarnations (`jobs/tenant_identity.rs:8-9`,
  `routes/tenants.rs:150-151`).
- The "on every backend" rationale in `jobs/mod.rs:4-7` and
  `docs/operations/jobs.md:124-130`.

## Acceptance

- [ ] Each path is removed, or a decision to keep it is recorded.
- [ ] A capability check never converts a store-resolution error into "unsupported backend".
- [ ] `docs/operations/jobs.md` and the module comments match the result.
