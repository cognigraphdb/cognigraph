# CG-15: Dynamic query resolution resets source-row accounting

## Problem

Dynamic DOCUMENT/correlated-traversal execution creates fresh RunCx instances for the materialized query head, each resolution round, and the deferred tail. Their row counters are independent. Backend fetches also occur outside a shared accounting object. The documented per-query source-row budget can consequently permit more total source work than configured.

## Evidence

- `crates/cognigraph-query/src/executor/mod.rs:294-299,423-462,479-545` — fresh contexts and unmetered dynamic fetches.
- `crates/cognigraph-query/src/executor/run.rs` — RunCx owns the row counter.
- `docs/cgql-v1.md:445-452` — total source-row budget contract.

## Reproduction / failure sequence

Construct a query with independently materialized source rows plus dynamic DOCUMENT/traversal resolution and deferred subqueries. Each phase gets the full configured row allowance instead of consuming the remaining query allowance. The wall-clock deadline object is preserved; this finding concerns row accounting and fetched work, not a claim that the deadline resets.

## Acceptance criteria

- [x] Share one query-wide row accounting object through initial materialization, dynamic fetches, head/tail evaluation, and nested plans.
- [x] Define how speculative retry work is charged and keep the public contract explicit.
- [x] Add budget boundary tests combining sources, DOCUMENT, correlated traversals, and deferred subqueries.

## Resolution — 2026-09-08

Cloned execution contexts share one row counter. Initial materialization,
distinct document lookup attempts (including misses), correlated path fetches,
and runtime array/traversal expansions consume that counter. Speculative work
remains charged. Source materialization stays cached once; the spec describes
the units and distinguishes them from all intermediate join rows/backend scan
effort. Lookup batches check the deadline and stop before sending another
document request once its row charge exceeds the cap.

The saved release accepted five units of work under a three-unit cap. The fix
passed formatting, Clippy, all 901 tests, and 240 live exact/one-below budget
checks alongside 60 analysis-parity comparisons. These covered both HTTP query
routes and Lua, resident/paged storage, and restart preservation. No final
validation or live check failed. See [implementation and evidence](dynamic-query-2026-09-08.md).
