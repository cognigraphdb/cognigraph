# CG-31: Hybrid result-cache fingerprints conflate distinct request parameters

- Status: Resolved
- Priority: P2
- Area: Server hybrid result caching
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` plus local quick-win fixes
- Verification: Reproduced in the pre-fix release; all Rust gates and fixed release HTTP checks passed across resident/paged storage and memory/persistent caches

## Problem

Hybrid search serializes `search_fields` with `join(",")` inside a delimiter-separated parameter string. Requests with `["a,b"]` and `["a","b"]` therefore share a result-cache key when their other parameters match. A strong cache hit returns before fresh text search, bypassing the corrected Native index identity. Unescaped collection/view names inside the same parameter string also make its boundaries ambiguous.

## Evidence

- `crates/cognigraph-server/src/routes/search/hybrid.rs:99-117` — parameter serialization.
- `crates/cognigraph-server/src/routes/search/hybrid.rs:120-147` — a strong cached hit returns without fresh BM25 execution.
- `crates/cognigraph-cache/src/types.rs:88-99` — cache identity requires exact result-shaping parameters.

## Reproduction / failure sequence

With result caching enabled, search a collection containing different text in `a,b` and `a`/`b`, first with one field list and then the other, using the same query. Both requests construct identical parameter strings; a strong hit can return the first request's results. CG-18 fixes the Native text-index cache and persistent index identity, which are separate from this server result cache.

## Acceptance criteria

- [x] Encode the complete set of result-shaping parameters structurally, including collection/view identities and ordered field lists.
- [x] Reuse the production fingerprint builder in cache tests instead of duplicating serialization in fixtures.
- [x] Test exact and similarity-assisted cache hits with delimiter-bearing names and prove they remain isolated; verify against the running server with a local embedding stub.

## Resolution — 2026-09-08

Hybrid parameter identity now uses versioned JSON serialization of every
request field except the separately normalized query. Three new regressions
cover parameter completeness, default/normalization/order behavior, and actual
hybrid cache collisions. Formatting, Clippy, all 872 tests, and release HTTP
exact/strong/assisted/restart probes passed in four storage/cache combinations.
See [verification and reproduction script](hybrid-cache-2026-09-08.md).
Related semantic/graph-augmented fingerprint defects are separately tracked
in [CG-32](CG-32.md).
