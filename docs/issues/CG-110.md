# CG-110: Typed traversal and graph-augmented search accept unbounded depth outside every budget

- Status: Open
- Priority: P1
- Area: Server / graph; Native / traversal
- Found: 2026-11-11
- Verification: Pending (reproduced live on 2026-11-11, 2.7.39 Community release build)

## Problem and evidence

`POST /api/graph/traverse` and `POST /api/search/graph-augmented` pass
`max_depth: u32` (and `seed_limit`) straight to Native. Native enumerates every
simple path breadth-first and clones the full vertex and edge documents for
each partial path (`crates/cognigraph-native/src/memory/search.rs:54-94`,
`memory/paged.rs:194-247`). CGQL caps traversal depth at 10; these routes and
Lua `graph.traverse` do not. The work is synchronous inside the async handler
and holds the state read lock, so neither `COGNIGRAPH_REQUEST_TIMEOUT_SECS`
nor the CGQL budgets apply, and writers wait behind it.

Reproduced on a complete graph of 10 documents (45 edges), `direction: "any"`,
with a 5 s request timeout and both CGQL budgets set:

| `max_depth` | Response | Time | Server RSS |
|---|---|---|---|
| 4 | 5 MB | 0.04 s | 78 MiB |
| 6 | 161 MB | 1.6 s | 2.0 GiB |
| 8 | 1.6 GB | 27.7 s | 5.5 GiB |
| 50 | none after 59 s | – | 5.6 GiB |

The traverse route needs graph-write scope, but graph-augmented search is open
to any role that can search.

## Acceptance

- [ ] Native enforces a maximum depth and a path or visited budget and returns a bounded error; `TraversalOpts` carries the limits.
- [ ] The HTTP routes and the Lua binding apply the same cap as CGQL, and the traversal honours the time budget.
- [ ] A test on a small complete graph with a large `max_depth` finishes within the budget in resident and paged modes.
