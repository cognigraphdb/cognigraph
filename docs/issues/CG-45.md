# CG-45: Community binary cannot exclude Enterprise Components

- Status: Resolved
- Priority: P2
- Area: Build / cognigraph-server
- Found: 2026-09-10
- Verification: Both feature sets, dependency graphs, release HTTP/CLI probes and Docker/Helm backup checks

## Problem and evidence

The [licensing decision](../decisions/decision_licensing.md) splits the
workspace into Community crates (FSL) and Enterprise crates
(`cognigraph-governance`, `cognigraph-construct`, `cognigraph-artifacts`,
commercial). `cognigraph-server` depends on all three unconditionally and
there is no Cargo feature that removes them, so every server binary and the
Docker image contain Enterprise code. Multi-tenancy is not a crate at all:
`crates/cognigraph-server/src/tenancy/` and roughly 180 server source files
reference tenants. `LICENSING.md` therefore has to say the license applies by
capability rather than by binary, which is defensible but weaker than a
Community build that does not ship the components.

## Acceptance

- [x] `cognigraph-server` gains an `enterprise` Cargo feature (default off for
      the Community build, on for the Enterprise build) that gates the
      `governance`, `artifact_consumption`, `promotions`, `materialized_repairs`,
      `side_views` and `routes/construct` modules and their routes behind
      `cfg(feature = "enterprise")`.
- [x] The dependencies on `cognigraph-governance`, `cognigraph-construct` and
      `cognigraph-artifacts` become `optional = true` and are pulled in only by
      the feature.
- [x] Tenancy: the Community build serves exactly one tenant (the default),
      with tenant creation and per-tenant routing returning a clear
      `enterprise_feature_required` error rather than being compiled out, so
      the on-disk format stays identical between tiers.
- [x] `cognigraph-cli` follows the same split for artifact and governance
      commands.
- [x] The Dockerfile and Helm chart build the Community variant by default and
      the Enterprise variant by build arg / values flag.
- [x] `scripts/check-server-modularity.py` and the OpenAPI drift check pass for
      both feature sets; the OpenAPI document for the Community build lists
      no enterprise routes.
- [x] `cargo test --workspace` and `cargo test --workspace --features enterprise`
      both pass.

## Notes

Runtime license keys are out of scope for this issue. A key check can be
added later behind the same feature boundary; the boundary is the
prerequisite.

## Resolution — 2026-09-10

Community is now the default server/CLI build. Both manifests declare an
optional `enterprise` feature; the normal Community dependency trees contain
none of `cognigraph-governance`, `cognigraph-construct` or `cognigraph-artifacts`.
Governed server modules, durable jobs and tenant registries are compiled only
for Enterprise. Generic edge ranking moved into Core; neuron boosts remain
Enterprise. Community tenant requests and non-default identities return a
structured `enterprise_feature_required` response, and the CLI refuses
Enterprise commands locally.

Community startup and snapshot import refuse nonempty governed/generated state
before ordinary mutations can bypass its Enterprise lifecycle fences. Native
files and ordinary snapshots retain their format and were exercised across both
editions. `/health` reports the edition; each build generates its own OpenAPI
artifact, pruning Enterprise operations and unreachable schemas from Community.
Docker and Helm default to Community and expose explicit Enterprise selection.

### Local verification

- `cargo fmt --all -- --check` passed.
- `cargo clippy --all-targets -- -D warnings` and the same command with
  `--features enterprise` passed.
- `cargo test --all` passed: **776 entries**; `cargo test --all --features enterprise`
  passed: **967 entries**. `--all` is Cargo's alias for `--workspace`. Each total
  includes eight Arango integration entries that returned early because
  `ARANGO_PASSWORD` was not exported; no new live Arango coverage is claimed.
- `python3 -m unittest discover -s scripts/tests` passed **26 tests**.
- `python3 scripts/check-editions.py` passed all four binary/feature dependency
  checks; server modularity, issue identity, documentation and decision checks passed.
- Release server and CLI binaries built in both configurations. The reusable
  [live probe](../../scripts/check-editions-live.py) passed CRUD, parsed queries,
  Lua, text/vector/graph retrieval, auth, tenant rejection, CLI gating, ordinary
  file/snapshot interoperability, governed-data refusal and Enterprise tenant
  isolation. It found **65 Enterprise-only specification paths**; tenant paths
  retain rejection stubs and the other paths returned 404 in Community.
- Docker images built for both editions. Helm checks passed **10 rendering
  variants and 11 rejection cases**; each edition's rendered container passed
  probes, login, synthetic import and packaged snapshot backup.

The initial default run exposed Enterprise-only cascade, neuron ranking and
tenant-fixture assumptions; the final Community schema also exposed a neuron-only
cache-parameter assumption. Expectations now follow the compiled feature set,
with common behavior retained and new Community admission tests added. An
Enterprise Clippy redundant binding was removed. All resulting checks passed.

These are local results, not remote CI or Kubernetes deployment evidence. Live
edition probes used disposable Native stores and a local deterministic embedding
fixture; no existing database was reset. The optional ONNX configuration and UI
were not changed or requalified by this issue. Runtime license keys remain out
of scope. The subsequent [licensing amendment](../decisions/decision_licensing.md#read-replica-tier-amendment--2026-09-10)
assigns read replicas and manual standby to Community; replicas remain
unimplemented and were not part of CG-45 verification.

Reproduce release probes by building each edition and copying `cognigraph-server`
and `cognigraph` to separate directories, then running:

```sh
python3 scripts/check-editions-live.py --community /path/to/community --enterprise /path/to/enterprise
python3 scripts/verify.py --suite docker
python3 scripts/check-helm.py --live
python3 scripts/check-helm.py --live --enterprise
```
