# CG-148: CLI builds request paths by string interpolation, so keys with reserved characters address another resource

- Status: Open
- Priority: P2
- Area: CLI / request construction
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

The older CLI commands format path segments directly, for example
`api.delete(&format!("/documents/{collection}/{key}"))`
(`crates/cognigraph-cli/src/main.rs:114-116`, `:122-129`, `:149-154`,
`:171-173`, `:189-205`, `:242`, and the older Enterprise commands). The
correct helper `encoded_api_path` (`main.rs:1283-1307`) is used only by the
newer Enterprise commands. Neither the server nor Native restricts key
characters beyond NUL, and the dump importer stores ArangoDB keys verbatim.

Failure cases:

- `cognigraph doc delete notes 'report?v=2'` sends
  `DELETE /api/documents/notes/report?v=2` and deletes document `report`.
- `cognigraph doc get c 'a%41'` fetches key `aA`.
- `cognigraph index drop users 'idx#1'` drops index `idx`.

The TypeScript client encodes path segments correctly.

## Acceptance

- [ ] Every path segment and query value goes through `encoded_api_path` or an equivalent.
- [ ] Unit tests assert the built URL for keys containing `?`, `#`, `%`, `/` and a space on the document, index, user, token, tenant and neuron commands.
