# CG-177: OpenAPI drift tests leave merged routers, HTTP methods and Community stubs unchecked

- Status: Open
- Priority: P3
- Area: Server / contract tests
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`crates/cognigraph-server/src/openapi_drift.rs` compares `openapi.yaml` with
the router, with these gaps:

- `nest_mapping_is_complete` asserts `.nest(` coverage in `main.rs`, but
  `MERGED_MODULES` is maintained by hand and nothing checks that every
  `.merge(...router())` inside route modules is listed.
- Methods are compared only for the hand-listed M18, M19, M20, M24, M25 and
  M26 tables; every other route is compared by path only, and only in
  Enterprise builds.
- Community mounts `/api/tenants*` stub routes
  (`routes/tenants_community.rs:11-14`) that both the specification build and
  `mounted_paths()` filter out, so they are never compared.
- `route_methods` uses substring matching (`contains("get(")`).
- The guard against a vacuous run is 25 paths.

A router fragment merged into an existing module, or a `DELETE` added to a
generic path, ships undocumented while the suite stays green. The prose
reference has its own gap ([CG-156](CG-156.md)).

## Acceptance

- [ ] A test asserts every merged router fragment in `routes/` is listed.
- [ ] Methods are compared for all paths in both editions.
- [ ] The Community tenant stubs are covered or explicitly exempted.
