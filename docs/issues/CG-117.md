# CG-117: Login hashes on async workers, has no attempt throttling and reveals usernames by timing

- Status: Open
- Priority: P2
- Area: Auth / login
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`verify_password` (`crates/cognigraph-auth/src/lib.rs:510-535`) scans all of
`_users`, returns at once for an unknown username, and otherwise runs
`Argon2::default().verify_password` synchronously inside the async login
handler (`crates/cognigraph-server/src/routes/auth.rs:55-73`). There is no
failure counter per account or per source, and the request rate limiter is off
by default.

Consequences:

- Concurrent unauthenticated `POST /api/auth/login` requests for an existing
  username each pin a Tokio worker for the hash, so a modest rate stalls every
  other request.
- Response time distinguishes existing from unknown usernames.
- Password guessing is unthrottled.

Admission has a related cost: every authenticated request takes the global
`tenant_lifecycle_lock` and scans all of `_tokens`
(`auth_middleware.rs:67-69`).

## Acceptance

- [ ] Hashing and verification run off the async workers with bounded concurrency.
- [ ] The unknown-user path performs an equivalent dummy verification.
- [ ] Failed logins are throttled per username and source, with tests; token lookup does not scan the collection.
