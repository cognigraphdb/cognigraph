# CG-32: Semantic and graph-augmented cache keys still conflate distinct parameters

- Status: Resolved
- Priority: P2
- Area: Search result-cache identity
- Found: 2026-09-08
- Reviewed revision: `291fbb1` (review/remediation through CG-31)
- Verification: Both defects reproduced in the pre-fix release; Rust gates and fixed release HTTP exact/strong/assisted/restart checks passed across resident/paged storage and memory/persistent caches

## Problem

CG-31 replaces the hybrid fingerprint. Two other search routes retain lossy
parameter encodings:

1. Semantic search uses `model_name.as_deref().unwrap_or_default()`, giving
   `None` and `Some("")` the same key. Native execution treats these as different
   filters: omitted means any model; an empty string matches only that literal
   model name. A warmed unfiltered answer therefore bypasses the empty filter.
2. Graph-augmented search flattens arbitrary edge/neuron collection names into
   a delimiter-separated fingerprint. One name can contain the literal text
   between the two string fields, making distinct collections share a key.
   Direct cached answers (including graph facts) and assisted cached result
   signals use that key. Weak-hit graph facts are still recomputed fresh.

## Evidence

- `crates/cognigraph-server/src/routes/search/semantic.rs:130-147` — lossy
  optional model encoding followed by the unchanged backend filter.
- `crates/cognigraph-native/src/memory/vector.rs:102-104,132-134` — explicit
  empty model values are filtered differently from an absent filter.
- `crates/cognigraph-server/src/routes/search/graph_augmented.rs:78-100` —
  unescaped collection names in the parameter fingerprint.
- [Sanitized observations and concrete graph request values](../evidence/engineering-historical-checks.md#artifact-9d383a1efdeaafe58677).

## Reproduction

With the query cache enabled and a loopback embedder returning `[1,0]`, store
`modeldocs/a` with `embedding: [1,0]` and `model_name: "alpha"`. POST semantic
search with `{ "collection": "modeldocs", "query": "needle" }`, then repeat
with `"model_name": ""`. Both responses return one document; the second says
`cached: true`. Clear the cache and repeat the empty filter: zero documents.
This was reproduced in both resident and paged Native modes.

For graph-augmented search, let `S` be the literal substring
`;t=0.7;seeds=5;l=10;depth=2;dir=outbound;minc=;decay=0.8;neurons=`.
The pair `(edge_collection = "edges" + S + "first", neurons_collection =
"second")` and `(edge_collection = "edges", neurons_collection = "first" + S
+ "second")` serialize identically when the common numeric/direction options
match S. The evidence JSON includes concrete request values. This equality
was checked during discovery. Closure additionally reproduced the wrong graph
documents and strong-hit graph facts over real HTTP using this pair, then
verified correct behavior in the fixed release.

## Acceptance criteria

- [x] Structurally encode all semantic and graph-augmented result parameters,
  preserving optional values and string boundaries.
- [x] Preserve the literal empty model filter and distinguish it from an
  omitted filter before exact or similarity-based cache lookup.
- [x] Use production key builders in route/cache fixtures.
- [x] Prove exact, strong-similarity, and assisted lookup isolation, while
  preserving valid same-parameter reuse and graph-fact freshness behavior.
- [x] Pass Rust gates and release HTTP regressions for both routes.

## Resolution — 2026-09-08

Both routes now use versioned JSON parameter identities and production
builders in cache fixtures. Empty semantic model filters retain their literal
meaning and are distinct from omitted/null filters. Formatting, Clippy, all
876 tests, OpenAPI checks, and release HTTP regressions passed. See
[verification, commit boundary, and reproduction script](search-cache-2026-09-08.md).
