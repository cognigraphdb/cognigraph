## Problem and evidence

[The README](../../README.md) states that the published Docker image is
linux/amd64 only and that ARM hosts such as Apple Silicon need Docker's
emulation. [The running guide](../operations/running.md) documents a source
build but no released binary for macOS on arm64.

Application developers on Apple Silicon need a database they can run in a
disposable local container for their own test harnesses. Emulated amd64
containers are slow enough to make a database-backed inner loop impractical,
and a source build requires the Rust toolchain in every consumer environment
and diverges from the qualified release artifact.

This is a packaging gap confirmed from documentation at 2.7.15, not a
reproduced defect.

## Scope and dependencies

Independent of [CG-84](CG-84.md), [CG-85](CG-85.md) and [CG-86](CG-86.md).
Follows the existing release workflow and image provenance rules; the amd64
image remains the deployment artifact for Railway.

## Acceptance

- [x] The release publishes a multi-architecture image manifest covering
      linux/amd64 and linux/arm64 under the existing tags: `<version>` and
      `latest` become indexes with `<version>-amd64`/`<version>-arm64`
      members, composed by one publish job from receipted, natively tested
      image IDs. Takes effect at the first publication after 2.7.27, once
      the owner updates the Docker Hub immutable-tag rule on both repositories.
- [x] A macOS arm64 binary is attached to the release, or the documented source
      build is verified on Apple Silicon as part of the release checklist:
      no GitHub releases exist, so a required `macos-15` CI job builds both
      editions and runs `scripts/check-platform-smoke.py`.
- [x] CI runs a startup and `/health/database` smoke check on an arm64 target
      for both editions: the Docker matrix leg on `ubuntu-24.04-arm` runs the
      full packaged-server checks, and the macOS job runs the bare-binary smoke.
- [x] `README.md` and `docs/operations/running.md` drop the emulation caveat
      and state the supported platforms.

## Resolution

Implemented 2026-09-22 under the
[multi-architecture images decision](../decisions/decision_multi_architecture_images.md)
(per-architecture tags plus an index, native runners, receipts linking tested
image IDs to uploads, Apple Silicon source-build smoke). Docker Hub tags through
v2.7.14 remain `linux/amd64` only. Owner action before the next publication:
set the immutable-tag rule on both repositories to
`^[0-9]+\.[0-9]+\.[0-9]+(-(amd64|arm64))?$`.
