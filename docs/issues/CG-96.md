# CG-96: Promotion lifecycle tests overflow the default test-thread stack in x86_64 debug builds

- Status: Resolved
- Priority: P2
- Area: Server tests / CI
- Found: 2026-09-23
- Verification: Governed flow passes with a 256 KiB test-thread stack after the fix (it needed more than 1.5 MiB before); every remaining test in both editions passes with a 1 MiB test-thread stack; release build of the same flow needs under 512 KiB; full local gate before the re-push of the integration PR on 2026-09-23
- Resolved: 2026-09-23

## Problem and evidence

The first remote run of the v2.7.21–v2.7.28 integration candidate
([PR #21](https://github.com/cognigraphdb/cognigraph/pull/21), run
35826261846) failed `cargo test --locked --all --features enterprise` on
`ubuntu-24.04`:

```
thread 'promotions::tests::governed_lifecycle::signed_governed_lifecycle_blocks_failed_promote_and_recovers' has overflowed its stack
fatal runtime error: stack overflow, aborting
```

The same toolchain (rustc 1.98.1) passed the suite on Apple Silicon before
the push and at v2.7.20 on the same runner. Measured locally with
`RUST_MIN_STACK`, the flow needed between 1.5 and 2 MiB of stack on
aarch64 in debug mode; x86_64 debug frames are larger, so the 2 MiB default
test thread was exceeded there. A sweep at 1.5 MiB found three lifecycle
flows at the limit (`governed_lifecycle`, `raw_document_lifecycle`,
`repair_lifecycle`). The release build of the governed flow passes at
512 KiB and fails at 256 KiB, so production worker threads keep at least
four times the headroom; this is a debug-build test-harness limit.

Cause: each promotion lifecycle test drives the whole server flow inside a
single `#[tokio::test]` future, which the macro pins on the test thread's
stack. Every layer added since v2.7.20 (refusal ledger, LIMIT bind
resolution, unique-index checks on the batch and document paths) grows that
nested state machine and its debug poll frames.

## Resolution

The six promotion lifecycle tests (artifact, consumption, derivation,
governed, raw document, repair) now call a shared `lifecycle` helper in
`crates/cognigraph-server/src/promotions/tests/mod.rs` that runs the flow
on a named thread with an explicit 16 MiB stack under a current-thread
Tokio runtime with all drivers enabled, matching `#[tokio::test]`
semantics. Test names are unchanged. Alternatives and the reasoning are in
the [decision record](../decisions/decision_lifecycle_test_stack.md).

## Scope and dependencies

Test harness only; no runtime code, storage or API behavior changes. Found
while landing [CG-87](CG-87.md) and fixed on the same integration branch.

## Acceptance

- [x] The Enterprise test suite passes on `ubuntu-24.04` in CI.
- [x] No test in either edition depends on more than half of the default
      test-thread stack (sweep at 1 MiB passes).
- [x] The fix does not hide a production stack risk (release measurement
      recorded above).
