# CG-54: Review queue and space selectors silently truncate their datasets

- Status: Resolved
- Priority: P2
- Area: UI / review
- Found: 2026-09-11
- Verification: Source review and 201-neuron Enterprise browser/API reproduction

## Problem and evidence

[ReviewScreen.tsx](../../ui/src/screens/ReviewScreen.tsx), lines 34 and 64–74,
always requests `limit=200` without an offset and renders a table with
`pagination={false}` at line 311. Its count is only the loaded array length.
Both Review and Construct space selectors load at most 100 space documents.
There is no continuation or truncation indicator.

The isolated Enterprise server contained 201 valid proposed neurons in
`audit_space`. The browser rendered “200 neurons”, exactly 200 rows, no paging,
and no `audit-neuron-200`. An independent API request at offset 200 returned
that remaining neuron. [API page](../../ui/audit/2026-09-11-full-review/review-overflow.json),
[queue capture](../../ui/audit/2026-09-11-full-review/08-review-queue-200.png).
Reviewing/removing early rows may eventually expose later ones; the current
listing still misrepresents the pending queue. The 100-space boundary is
source-confirmed, not a separately seeded 101-space browser test.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [x] Implement continuation/paging with truthful counts or explicit partial-result labels for review queues and space selectors.
- [x] Ensure selection and graduation links can resolve items outside the initially loaded page.
- [x] Browser-test more than 200 neurons and more than 100 spaces, including status changes and selected-item continuity.

## Resolution — 2026-09-11

Review uses 50-row pages with one lookahead row. Its count states the visible
range and whether more rows are available; the API's page-local `count` is never
presented as a dataset total. Previous/Next controls expose continuation. If a
verdict empties the last page, the queue returns to page one; a far-out stale URL
also recovers with one retry rather than scanning every intervening page.

Review, Construct and the proposal dialog share a complete, searchable space
catalog loaded through 100-row requests. A failed continuation rejects the
catalog and exposes retry, rather than publishing a partial set as complete.
Repeated pages also produce an explicit retry error. Superseded requests are
aborted and their results ignored.

Review space, status, page and selected neuron live in the URL; Construct's space
selection does too. The inspector reads its neuron directly by key and verifies
the space, independently of the visible page. Selection and draft notes survive
queue paging/refresh, while persisted selection survives reload. After a verdict,
the inspector reloads the stored status and attribution even if the neuron leaves
the current filter. Graduation links therefore open off-page targets immediately.
Changing space or status clears the previous selection. New proposals select
their actual space and identity.

Verification: all 132 UI tests (19 files, 684 assertions), lint/types and production
build passed. A real Enterprise release binary with disposable Native storage
held 101 spaces, 201 proposed and 201 accepted neurons. Browser paging reached all
201 proposals exactly once; final-page acceptance, off-page retirement, direct
links/reload, the 101st space in both screens, and a persisted proposal there passed.
Independent HTTP reads confirmed statuses, notes, attribution and queue counts.
Scaled layouts and keyboard paging passed. A labelled local proxy injected a
503 on the second catalog page; both screens reported failure and Review's retry
restored all 101 choices.
