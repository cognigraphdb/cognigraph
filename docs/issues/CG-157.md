# CG-157: Configuration reference misdescribes OPENAI_BASE_URL and omits variables the binaries read

- Status: Open
- Priority: P2
- Area: Docs / configuration
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review)

## Problem and evidence

- **`OPENAI_BASE_URL`.** `docs/operations/configuration.md:48`,
  `docs/examples/api-usage.md:554` and `.env.example:44-47` describe it as the
  completion endpoint. `crates/cognigraph-server/src/main.rs:238-247` passes
  the same value to the OpenAI embedding provider, which uses it without the
  completion side's normalization (a trailing slash yields `//embeddings`).
  An operator who points completions at a proxy also moves embeddings there.
  [CG-103](CG-103.md) adds a separate embedding endpoint; until it lands the
  reference should state the coupling.
- **`GEMINI_BASE_URL`** is ignored for embeddings: the provider is built with
  no base URL, so document text goes to the public endpoint even when a
  gateway is configured for completions. The reference scopes the variable to
  completions, so this is a surprise rather than a contradiction.
- **Unlisted variables:** `COGNIGRAPH_CONTAINER_INIT` and
  `RAILWAY_VOLUME_MOUNT_PATH` (`container_init.rs`), `RUST_LOG`, and the CLI's
  `COGNIGRAPH_URL`, `COGNIGRAPH_TOKEN` and `COGNIGRAPH_PASSWORD`. They appear
  only in other guides.
- **Stale labels:** `.env.example` describes the governance and artifact
  settings as M19 and M21 only, where the reference says M19–M26 and M21–M23
  plus M26. The comment at `config.rs:11` lists providers without `gemini`.

Every documented default was checked against `config.rs` and matches, and no
documented variable is unread.

## Acceptance

- [ ] The reference, the API examples and `.env.example` state which endpoints each base-URL variable affects, or the code separates them.
- [ ] The reference lists or links every variable the server, the container start-up and the CLI read.
- [ ] `.env.example` wording matches the reference.
