# CG-163: Server accepts the placeholder secrets published in .env.example and any JWT secret length

- Status: Open
- Priority: P3
- Area: Server / configuration; authentication bootstrap
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`validate()` in `crates/cognigraph-server/src/config.rs:204-225` only checks
that a JWT secret is present when a bootstrap password is, and
`crates/cognigraph-auth/src/jwt.rs:35-37` accepts any key length. The values
shipped in `.env.example:9-11` (`change-me`, `use-a-different-secret`,
`replace-with-at-least-32-random-bytes`) all start a server with
authentication enabled. After `cp .env.example .env` the HS256 signing key is
public, so anyone who can reach the port can mint an Admin token for the
bootstrap user.

Related default: `CorsLayer::permissive()` is unconditional (`main.rs:697`).
With authentication off by default and a `0.0.0.0` bind, any web page can
reach a developer's local instance. `decision_management_ui.md` records
permissive CORS as intentional, so that part is an owner decision.

## Acceptance

- [ ] Startup refuses the literal placeholders and JWT secrets shorter than 32 bytes, with a test for each.
- [ ] `.env.example` ships those lines commented out or empty.
- [ ] The CORS default with authentication off is confirmed or narrowed, and the decision is recorded.
