# CG-167: Proposal and drafting paths trust the shape and governance fields of model output

- Status: Open
- Priority: P3
- Area: Construct / completion output handling
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

- **Proposals.** `propose_one` forces status, source, relation, target and id
  but not the neuron kind (`crates/cognigraph-construct/src/propose/neurons.rs:116-128`);
  the blocker path does force it (`propose/blockers.rs:289`). The schema allows
  additional properties. A completion that answers a hint request with
  `"type": "relation_blocker"` or `"alias"`, plus `entity`, `aliases`, `boost`
  or `reviewed_by`, survives and is stored whole
  (`crates/cognigraph-server/src/routes/construct/proposal.rs:160-165`).
  Document text can steer the model to do this. Evidence quotes are only
  checked for being non-empty (`validate.rs:114`), never against the corpus,
  although the module calls proposals evidence-bound. Automatic acceptance is
  not reachable for those kinds.
- **Malformed envelopes.** The drafter and answer evaluation read
  `["entities"].as_array().cloned().unwrap_or_default()`
  (`draft.rs:90`, `:150`, `answers.rs:239-248`, `:277`). A response without
  the expected array contributes nothing, with no error and no skip. In
  answer evaluation a malformed answer gives no asserted facts, so restraint
  is reported as satisfied. [CG-4](CG-4.md) fixed this class for directed
  construction only.

## Acceptance

- [ ] Both proposal paths set the kind and reset `reviewed_by`, `entity`, `aliases` and `boost`; evidence quotes are verified verbatim or flagged before storage.
- [ ] Envelope shape errors return an error or a recorded per-document skip in the drafter and answer evaluation.
- [ ] Tests use a wrong-kind completion and the malformed-envelope cases from CG-4.
