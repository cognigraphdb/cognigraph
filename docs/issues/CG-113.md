# CG-113: Snapshot import lets a tenant Admin create unsigned legacy promotion authority

- Status: Open
- Priority: P1
- Area: Server / promotions (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

Snapshot preflight accepts schema-v1 evidence (`created_by.role == "admin"`)
and v1 decisions without a governance block
(`promotions/snapshot_validation.rs:25-83`, `evidence_validation.rs:88-90`,
`decision_validation.rs:52-53`). Every check on them is structural or an
unkeyed digest. `validate_promotions_against_authority` skips records without
governance (`governance/historical_authority.rs:110-113`), and legacy v1 jobs
pass `validate_recoverable_job`. The only ordering rule blocks unsigned
decisions after signed ones in the same chain. Heads carry `schema_version: 1`
in every generation, so a legacy head looks like a signed one.

Failure sequence: an Admin builds a snapshot with four fabricated succeeded v1
evaluation jobs, one v1 evidence bundle and one v1 `promote` decision for a
channel that has no governed history, then calls `POST /api/admin/import`.
Preflight and post-import validation pass and reconcile writes a head. No
policy author, approver or promoter signed anything, and the channel is then
fixed to the unsigned generation, so real signed evidence is refused there.

This contradicts the M19 decision
(`docs/decisions/decision_m19_signed_governance_separation_of_duties.md`, D8,
D11, D13 and its acceptance matrix): Admin authentication alone cannot create
new evidence or a promote or reject decision.

## Acceptance

- [ ] Import refuses v1 evidence and decisions that are not already in the destination store unless an explicit legacy-restore switch is set, or a recorded cutover invalidates unsigned authority created after it.
- [ ] A head (or its projection) distinguishes unsigned legacy selection from signed selection.
- [ ] A regression test imports a fabricated v1 chain into a fresh target and is refused before any write.
