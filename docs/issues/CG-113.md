# CG-113: Snapshot import lets a tenant Admin create unsigned legacy promotion authority

- Status: Resolved
- Priority: P1
- Area: Server / promotions (Enterprise)
- Found: 2026-11-11
- Verification: A regression test imports an unsigned M18 chain into a fresh store through the function the import route calls, and both test suites pass (868 Community, 1,098 Enterprise); the release server was started with the switch on and off, but no snapshot was imported over HTTP
- Resolved: 2026-11-11

## Problem and evidence

Snapshot preflight accepts schema-v1 evidence (`created_by.role == "admin"`)
and v1 decisions without a governance block
(`promotions/snapshot_validation.rs:25-83`, `evidence_validation.rs:88-90`,
`decision_validation.rs:52-53`). Every check on them is structural or an
unkeyed digest. `validate_promotions_against_authority` skips records without
governance (`governance/historical_authority.rs:110-113`), and legacy v1 jobs
pass `validate_recoverable_job`. The only ordering rule blocks unsigned
decisions after signed ones in the same chain. Heads carry `schema_version: 1`
in every generation, so a legacy head looks like a signed one.

Failure sequence: an Admin builds a snapshot with four fabricated succeeded v1
evaluation jobs, one v1 evidence bundle and one v1 `promote` decision for a
channel that has no governed history, then calls `POST /api/admin/import`.
Preflight and post-import validation pass and reconcile writes a head. No
policy author, approver or promoter signed anything, and the channel is then
fixed to the unsigned generation, so real signed evidence is refused there.

This contradicts the M19 decision
(`docs/decisions/decision_m19_signed_governance_separation_of_duties.md`, D8,
D11, D13 and its acceptance matrix): Admin authentication alone cannot create
new evidence or a promote or reject decision.

## Resolution

- **Refusal.** Snapshot preflight refuses unsigned (schema-v1, no governance
  block) evidence and decisions that the target store does not already hold
  byte for byte. The refusal is a 403 raised before the backend import, so
  nothing of the snapshot is written and the tenant's promotion state is not
  latched. A store can take its own snapshot back.
- **Legacy-restore switch.** `COGNIGRAPH_ALLOW_LEGACY_PROMOTION_IMPORT=true`
  makes the server accept them. It is process configuration, off by default,
  and logs a warning at start when on.
- **Marked heads.** `PromotionHead` has `unsigned_legacy`, true when the
  applied decision is unsigned. It is not serialized on signed heads, so
  their stored form and digest are unchanged. Reconcile rewrites a legacy
  head stored before the field existed. The OpenAPI schema lists it.

The owner was not asked about the switch; it is the default chosen here,
recorded with its reasons and its cost in the
[decision record](../decisions/decision_legacy_promotion_import.md), which
amends D11 of the M19 decision. The recovery guide and the configuration
reference describe the restore procedure.

Test (`promotions/tests/legacy_import.rs`, Enterprise): a store builds an
unsigned chain (four evaluation jobs, v1 evidence, a v1 `promote` by an
Admin) and exports it. A fresh store refuses the snapshot with the evidence
named, and holds no evidence, decision, head, job, fact or marker document
afterwards. A snapshot with the evidence removed is refused at the decision.
The source store imports its own snapshot. A snapshot without promotion
records imports. With the switch on, the chain imports and the rebuilt head
equals the source head and is marked; switching it off again leaves recovery
healthy. A head stored without the marker is rewritten by reconcile. The
five restore cases in `durable_lifecycle.rs` work on M18 history and now set
the switch.

Not done: no snapshot was imported over HTTP against a release binary; an
unsigned chain cannot be produced through the API, only through the manager
functions the test uses. A signed rollback to v1 evidence yields an unmarked
head, because its decision is signed.

## Acceptance

- [x] Import refuses v1 evidence and decisions that are not already in the destination store unless an explicit legacy-restore switch is set, or a recorded cutover invalidates unsigned authority created after it.
- [x] A head (or its projection) distinguishes unsigned legacy selection from signed selection.
- [x] A regression test imports a fabricated v1 chain into a fresh target and is refused before any write.
