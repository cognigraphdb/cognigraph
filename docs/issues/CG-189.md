# CG-189: CGQL specification keeps superseded sections, and the migration guide asks for an edit that is no longer needed

- Status: Open
- Priority: P3
- Area: Docs / CGQL reference and migration guide
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review)

## Problem and evidence

`docs/reference/cgql.md`:

- `:748` ("no hash joins yet") and `:903` (hash joins listed as unsupported)
  contradict `:143-145` and the code
  (`crates/cognigraph-query/src/executor/run.rs:23-37`, `:606-625`).
- "Logical Planning" (`:584-600`) describes a plan with one source, one
  optional sort and one projection; the planner has a body of operations,
  COLLECT, DISTINCT and mutations (`planner.rs:16-40`).
- The query shape (`:43-58`) gives a fixed clause order starting with one
  `FOR`; the grammar allows zero or many `FOR`, `LET` and `FILTER` in any
  order, as the same document says later (`:713-750`).
- "Semantic Validation" (`:570-582`) omits the function-name and arity
  checks, the subquery depth limit and the mutation rules.
- `:172` still says "in v1", and `:464-466` says `DOCUMENT()` is unavailable
  in a traversal start, which holds only for uncorrelated starts.

`docs/reference/aql-to-cgql.md:255-263`: the worked rewrite says `LIMIT @top`
"became a literal" and shows `LIMIT 20`, although the grammar accepts a bind
variable and the same guide says so earlier (`:26-27`, `:81`). It also
announces three edits and names two.

More than 25 spot checks of the specification against the grammar and the
function table were correct, including all 50 functions and their arities.

## Acceptance

- [ ] The hash-join statements agree with the executor, and the query-shape, validation and planning sections describe the current plan or are marked historical.
- [ ] The worked rewrite keeps `LIMIT @top`, its prose matches the sample, and the sample is run against the corpus or a live server.
