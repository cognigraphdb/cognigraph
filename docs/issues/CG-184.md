# CG-184: TypeScript client lets body-read failures escape as raw platform errors and never retries them

- Status: Open
- Priority: P3
- Area: Clients / TypeScript
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

In `clients/typescript/src/client.ts:267-285` only the `fetch()` call is
wrapped; `await response.text()` is outside the try/catch. The timeout signal
also aborts body streaming, so a timeout or connection reset after the
headers rejects from `response.text()` with the platform error. `send()`
retries only `CogniGraphError` instances. The unit fake always returns a
complete body, so no test covers this.

When a large `query()` result stalls mid-body, the caller gets a
`DOMException` named `TimeoutError` that fails `instanceof CogniGraphError`,
has no `status` or `retryable`, and bypasses the configured read retry.

The client's routes, shapes and path encoding were checked against the server
and match.

## Acceptance

- [ ] Body-phase timeout, abort and reset map to `TimeoutError`, the caller's abort reason and `NetworkError`, and reads are retried under the policy.
- [ ] Unit tests cover a body that errors or stalls after the headers.
