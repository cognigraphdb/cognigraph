## Problem and evidence

The owner approved [Native-only storage](../decisions/decision_native_only.md),
but no qualified dump-to-Native migration profile exists. The current
[CLI importer](../../crates/cognigraph-cli/src/main.rs) accepts only a CogniGraph
JSON snapshot. The [AQL migration guide](../reference/aql-to-cgql.md) covers query
rewrites, not direct dump ingestion. Treating a dump as that snapshot fails to
map structure files, data markers and metadata.

This is planned compatibility work, based on source inspection at 2.7.1
(`efe9839`), not a newly reproduced production defect. The
[deferred import design](../plans/arangodump-import-design.md) records required
boundaries; exact versions, exporter options, CLI arguments and metadata
dispositions still need qualification.

## Scope and dependencies

The owner clarified on 2026-09-12 that CogniGraph has no users or live
deployments. This ticket is removed from the active
[Native-only batch](../plans/native-only-2026-09-12.md). It only blocks the
optional CG-66 importer if that work is prioritized later. It does not block
Arango deletion, readiness or first deployment. No customer installation or
legacy application-state inventory is required.

If resumed, scope the work around external Arango users considering a move to
Native, without reinstating runtime Arango support. The acceptance below applies
only to that future feature, not to this cleanup batch.

Use synthetic data and a disposable source database. Capture the exact exporter
and server versions, options, licensing/distribution provenance, file hashes
and expected Native results in a new versioned fixture package. No private
datasets, model calls or historical capture rewrites are needed.

## Acceptance

- [ ] Freeze a support matrix for plain/gzip/split JSON, supported 3.11/3.12 profiles, and explicit rejection of encrypted, binary, multi-database, incomplete and unknown layouts.
- [ ] Define CLI syntax, dry-run/error/report semantics, bounded processing and staging/publication behavior; distinguish this mode from the existing HTTP snapshot command.
- [ ] Define exact collection/key/edge/JSON and `_rev` mapping, marker ordering, duplicate/invalid-name handling, unresolved references and all index/view/constraint/system-state dispositions.
- [ ] Check in exporter-generated synthetic fixtures, a reproducible generation recipe and a hash manifest with independently inspectable expected documents, edges and failures.
- [ ] Define external user-data import limits; distinguish graph data from credentials, jobs and governed state without promising full application migration.
- [ ] Validate fixture structure/hashes and exact source export observations; run documentation, decision-index and issue checks. Rust changes, if needed for fixture tooling, receive the required Rust gates and real-binary checks.

## Verification and resolution

Resolved 2026-09-23. The [dump import contract](../reference/arangodump-import.md)
and its [decision record](../decisions/decision_arangodump_import_contract.md)
freeze the support matrix, CLI syntax and exit codes, limits, mapping, error
codes, report schema and publication rule. Owner choices: 3.11 and 3.12 JSON
dumps; unique indexes carried over as enforced constraints; importer as a
module tree in the CLI crate; the existing PLU Finder backup as a private
acceptance run for CG-66, sealed in `evidence/`.

[Fixtures](../../fixtures/arangodump/README.md) come from real `arangodump`
runs against disposable `arangodb:3.11.14` and `arangodb/enterprise:3.12.11`
containers (no 3.12 community image exists), loaded over HTTP from
[synthetic definitions](../../scripts/arangodump_dataset.py). The
[reference reader](../../scripts/arangodump_reader.py) is the executable
contract: it reaches every fixture's recorded outcome, and the expected data
comes from the definitions, not the dumps.

Findings from real exporter output that changed the original design:
3.12 has no envelope option; split dumps write no data file for an empty
collection; VPack uses `.data.vpack[.gz]`; encryption makes `dump.json`
unreadable; and 3.11 structure-only dumps are indistinguishable from dumps of
empty collections while 3.12.11 ignores `--dump-data false`, so structure-only
input imports as empty collections with a warning instead of being rejected.

- [x] Support matrix frozen, with explicit rejection of VPack, encrypted, multi-database, incomplete and unknown layouts (structure-only: see finding above).
- [x] CLI syntax, dry run, exit codes, report, limits and staging/publication defined and distinct from snapshot import.
- [x] Collection/key/edge/JSON/`_rev` mapping, marker handling, duplicate and invalid names, unresolved references and every metadata disposition defined.
- [x] Exporter-generated synthetic fixtures, generation recipe and hash manifest with independently derived expected results and failures checked in.
- [x] User-data scope separated from credentials, services, jobs and governed state.
- [x] Fixture hashes, structure and exporter observations validated in CI; documentation, decision-index and issue checks pass.
