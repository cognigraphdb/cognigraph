# CG-16: DOCUMENT converts backend failures into successful null results

- Status: Resolved
- Priority: P2
- Area: CGQL error propagation
- Found: 2026-09-08
- Reviewed revision: `bc4bff1` (workspace 2.6.0)

- Resolved: 2026-09-08

## Problem

Dynamic document fetching maps every backend error to absence. Authorization failures, storage errors, and connection failures therefore become a successful `null`, indistinguishable from a missing document. Filters and reports can silently omit real records during failures instead of preserving the backend's error contract.

## Evidence

- `crates/cognigraph-query/src/executor/mod.rs:507-519` — `.await.unwrap_or(None).unwrap_or(Value::Null)`.
- `crates/cognigraph-core/src/traits.rs:45-46` — absence is `Ok(None)`; failures are separate errors.

## Reproduction / failure sequence

Use a GraphBackend whose `get_document` returns Forbidden or BackendError for an otherwise valid ID, then execute a query returning DOCUMENT of that ID. The resolver inserts null and permits a successful result. This is directly determined by the error-discarding branch; an injected-backend regression should cover closure.

## Acceptance criteria

- [x] Map only `Ok(None)` to null; propagate backend failures through ExecutionError with appropriate HTTP status.
- [x] Keep malformed-ID handling distinct from lookup failure.
- [x] Test missing records, forbidden collections, unavailable backends, and storage errors through normal and analyzed query paths.

## Resolution and verification

`executor/resolve.rs` propagates failed lookups with the shared backend error
converter and aborts the batch. Forbidden and connection failures retain typed
execution errors; HTTP query routes and uncaught Lua errors return 403/503.
Other backend failures return 500. Missing documents and non-identifiers retain
their existing null behavior, while plain EXPLAIN performs no lookup.

Three query tests cover 210 injected-error executions, normal/analyzed and
precompiled paths, absence, malformed inputs, and batch termination. Three
server tests cover 96 error/status cases plus successful controls and Lua
handling. Formatting, Clippy, all 907 tests, and the release build passed.
The saved binary reproduced 72 silently successful forbidden lookups; the
corrected binary returned 403 in all 72 cases. Seventy-two controls, 36 plain
EXPLAIN checks, 12 Lua pcall checks, and resident/paged restarts passed.
Connection and storage outages were injected in route tests rather than
induced in real storage. See [the report and raw evidence](document-errors-2026-09-08.md)
and [original review evidence](review-2026-09-08.md).
