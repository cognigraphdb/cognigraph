# CG-179: Dump importer edge resolution is quadratic and its problem list is unbounded

- Status: Open
- Priority: P3
- Area: CLI / ArangoDB dump importer
- Found: 2026-11-11
- Verification: Pending (source-confirmed; magnitude estimated, not measured)

## Problem and evidence

`resolve` in `crates/cognigraph-cli/src/arangodump/load.rs:161-207` pages
with `list_documents(name, Some(1000), Some(offset))`. In paged mode that is
`range(..).skip(offset).take(limit)`
(`crates/cognigraph-native/src/storage.rs:288-308`), so each page re-walks
everything before it; `scan_collection_after_key` exists to avoid this. An
edge collection of 10 million edges means about 10,000 pages with an average
skip of 5 million. The largest test uses 5,000 documents.

Every unresolved edge is pushed to `problems` with no cap, held in memory and
printed to stdout and the report, although the contract says a collection
stops at its first problem. The reference reader also reports every edge, so
contract and reader disagree. A collection whose name is rejected is not
added to `failed_names` (`arangodump/mod.rs:286-289`), so edges into it are
reported as unresolved as well.

## Acceptance

- [ ] Resolution uses a key cursor or a single streaming pass.
- [ ] Reported unresolved edges are capped per collection with a total count, and the contract text and the reader agree.
- [ ] Tests cover at least 200,000 edges within a time bound, and mass-unresolved edges.
