# CG-169: A trigger match that ends inside a case-fold expansion aborts the whole ingest batch

- Status: Open
- Priority: P3
- Area: Construct / Unicode spans
- Found: 2026-11-11
- Verification: Pending (source-confirmed by trace; not executed)

## Problem and evidence

`map_cf_offset` in `crates/cognigraph-construct/src/grounding/negation.rs:80-92`
resolves an offset that falls inside a case-fold expansion to the start of
that character. U+0130 lowercases to two code points. If a lowercased trigger
ends on the first of them, the mapped end offset falls back, the slice is one
letter short, and the writer's check (`ingest.rs:308-320`,
`materialization.rs:296-312`) raises "invalid evidence span".

Failure case: template `acquired {target}` with an ASCII-spelled alias, and a
chunk that has the same name in Turkish capitals ending in U+0130. One such
chunk makes `ingest_chunks` and `derive_materialized_graph` fail for all
submitted chunks, and the caller cannot fix the document. The existing test
(`grounding_tests.rs:220-223`) covers an expanding character only before the
trigger.

Also noted: `judge.rs:122-129` applies an offset found in the lowercased text
to the original text; `floor_boundary` prevents a panic, but the excerpt can
drift or be empty.

## Acceptance

- [ ] A match that begins or ends inside a folded expansion is not accepted as an occurrence, or maps to the full character, so spans always validate.
- [ ] A regression test places the expansion at the match end.
