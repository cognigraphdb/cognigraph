# CG-69: Automate Native CI and enforce verified repository changes

- Status: Open
- Priority: P1
- Area: CI and delivery
- Found: 2026-09-12
- Verification: v2.7.4 GitHub source and packaged runtime passed; v2.7.5 corrects the Linux Helm backup inspector, with final qualification pending

## Problem and evidence

The workflow only accepted manual dispatch. GitHub listed no CI runs, main had
neither branch protection nor rulesets, and secret scanning/push protection were
disabled. Local verification omitted the CG-68 Native readiness harness, Helm
rendering/live backup checks, advisory scans and actionlint. Rust test/Clippy
commands could modify dependency resolution. The separate website had no workflow.

## Implementation

Automatic PR/main verification uses the same expanded CI and Docker runners as
local pre-push. The Native wrapper builds locked release binaries for both
editions and retains logs/failure summaries. Helm rendering and packaged backups
run in both editions. A required aggregate check rejects failed, skipped and
cancelled prerequisites. Full-SHA Actions and read-only credentials preserve
manual-main-only image publication. Dependabot proposes dependency updates.

The website has its own shared local/CI runner: workflow lint, frozen Bun
installation, audit, type/lint/tests and a disposable hardened Docker smoke
across all twelve SSR pages. Its private-repository plan currently does not
allow branch rulesets; no visibility/billing changes are authorized.

The first scan found h2 0.4.15 affected by RUSTSEC-2026-0258 and yanked
chacha20 0.10.1. The candidate updates them to 0.4.19 and 0.10.2 respectively.
Transitive informational advisories remain visible under [CG-70](CG-70.md).

### Lifecycle wait correction

The [v2.7.3 GitHub run](https://github.com/cognigraphdb/cognigraph/actions/runs/34698354986)
passed strict Clippy in both editions and the Community tests, then failed three
Enterprise lifecycle cases in `promotions/tests/job_fixtures.rs`. Its terminal
wait allowed 500 polls with five-millisecond sleeps and reported no final job
status. The tests assert job results and authority, not a 2.5-second completion
contract. The required aggregate failed; Native/browser/Docker qualification
was not reached in that run.

Version 2.7.4 replaces the poll-count limit with a bounded 60-second timeout,
including repository reads, and reports the last status/attempt/progress on
failure. A four-second delayed M21 evaluation exercises completion beyond the
old allowance while retaining the existing success and evidence assertions.
Production scheduling, consumption deadlines and retry behavior are unchanged.

The local negative control temporarily used the committed v2.7.3 helper with
the new delayed evaluation. It failed at the original terminal-wait panic as
expected; the corrected helper was restored afterward. All 22 promotion tests
then passed, including the delayed M21 case and all three lifecycle cases that
failed on GitHub. The delay fixture lives beside the shared submission helpers,
preserving the governed lifecycle module's size budget. The installed hook runs
the complete CI/Docker suites before the corrected commit is published, and
the next GitHub run must qualify Linux independently.

### Private backup inspection correction

The [v2.7.4 GitHub run](https://github.com/cognigraphdb/cognigraph/actions/runs/34700524053)
passed the complete source job, including all 299 Enterprise server tests,
all 514 Native release checks, twelve startup rejections and nine browser cases.
Both Docker images also built and passed packaged runtime checks. The Community
Helm backup was written successfully, but its host-side inspector failed with
`PermissionError`: Linux preserved backup UID 10001 and private mode `0600`,
which the host runner could not read. The required aggregate correctly failed.

Version 2.7.5 inspects the backup as its container owner. It verifies exact mode
`0600`, owner identity, snapshot contents, absence of partial files and denial
for another unprivileged UID. The denial probe exposed Docker Desktop bind-mount
ownership differences locally, so the disposable target now uses a Docker volume
with Linux ownership semantics on both platforms. Only that temporary volume is
initialized by a bounded provisioner; the actual backup and inspections remain
non-root without capabilities. No production backup permissions are changed.

The backup client's existing regression now also asserts mode `0600`. Fresh
Community and Enterprise live probes passed the new owner/denial checks; the
installed hook must rerun the complete versioned candidate before publication.
The PR's next check run owns the independent Linux qualification. Earlier failed
runs and the v2.7.4 source success remain part of the evidence.
