# CG-81: Triage remaining container CVEs without Debian fixes

- Status: Open
- Priority: P2
- Area: Container security
- Found: 2026-09-14
- Verification: Residual findings confirmed in local scans on 2026-09-14; exploitability and component-removal review pending

## Problem and evidence

After [CG-80](CG-80.md)'s available Debian upgrades, the 2026-09-14 Trivy
scan still reports 223 binary-package/CVE pairs (103 unique IDs) in each edition:
51 high, 81 medium, 90 low and 1 unknown. None has a fixed version in the
scanner's Debian database. These totals differ from Docker Scout's source-package
and severity model; they must not be compared as if they used one scale.

The original Scout report has 42 non-fixable findings, including high-severity
[CVE-2026-85091 in zlib](https://security-tracker.debian.org/tracker/CVE-2026-85091).
Debian marks its stable package affected and has no fixed version. Trivy does
not list this ID at this checkpoint: passing one scanner does not invalidate
another scanner's finding. No suppression or VEX exception was added.

The remaining Trivy high-severity IDs span:

| Source package | CVEs |
|---|---|
| ncurses | CVE-2025-69720 |
| curl | CVE-2026-12064, CVE-2026-8286, CVE-2026-8458, CVE-2026-8927 |
| systemd | CVE-2026-16742 |
| acl | CVE-2026-54369 |
| util-linux | CVE-2026-76642, CVE-2026-78408, CVE-2026-78409, CVE-2026-78410 |
| perl | CVE-2026-9538 |

Package presence alone does not prove an exposed CogniGraph execution path.
For example, [CVE-2026-9538](https://security-tracker.debian.org/tracker/CVE-2026-9538)
concerns Perl Archive::Tar; determining whether that module is installed matters
before making an exploitability claim. The current package refresh does not
establish non-reachability for these findings.

## Next work

Review advisory preconditions against the files and entry points actually
shipped. Prioritize zlib and the twelve high-severity Trivy IDs. Evaluate
removing unnecessary runtime components or using a smaller supported runtime
with compatible libc, health probes and privilege/volume initialization.
Keep package metadata and full reports; removing evidence is not remediation.
Do not replace supported packages with unreviewed upstream builds solely to
obtain a cleaner scanner total. Record each fix, confirmed non-applicability or
remaining upstream dependency with evidence. Re-scan before release.

The [dated verification](../verification/container-security-2026-09-14.md) identifies
the current evidence. This open issue is not a blanket risk acceptance or a
declaration that these images are safe from the listed vulnerabilities.

## Acceptance

- [ ] Review all remaining high/critical findings from both scanners against
  vendor advisories and actual shipped runtime files.
- [ ] Apply available fixes or justified component removal and record bounded
  dispositions for findings that remain.
- [ ] Qualify both edition images with full scans and real container/backup
  checks; separately verify any published replacement by immutable digest.
