# First remediation batch — 2026-09-08

This batch addresses five contained issues from the initial review. Changes are
local and uncommitted; the pre-existing documentation edits and deleted
`CLAUDE.md` were preserved. No external provider or production store was used.

## Changes

| Issue | Resulting behavior |
|---|---|
| [CG-2](CG-2.md) | Text-index directories and vector sidecar files use a shared SHA-256 filename helper. Collection names remain opaque data, including existing separator-bearing names; no derivative embeds them as path components. |
| [CG-4](CG-4.md) | Directed completion requires the complete declared JSON shape, including every fact's string fields and no unknown fields. Malformed output fails before backend access. An explicit valid `facts:[]` remains a supported empty reconciliation. |
| [CG-9](CG-9.md) | Keyed UPSERT checks every search predicate with the same numeric-aware equality as scanned matching. A nonmatching candidate remains unchanged and takes the INSERT branch. |
| [CG-17](CG-17.md) | Native text search rejects `_key` and duplicate fields before schema creation/cache lookup. The hybrid route also validates before embedding or result-cache work. Invalid HTTP requests return 400. |
| [CG-18](CG-18.md) | Native index identity uses a structured collection/ordered-fields tuple. Persistent warm opens require matching identity, exact schema, and data generation. Delimiter-bearing fields no longer collide. |

CG-2 uses encoding at the shared filesystem boundary instead of introducing a
new global collection-name grammar. This covers derivatives reached through
CRUD, query, Lua, batch, and import data without invalidating existing names.
The review of related paths found the same raw-name problem in vector sidecars;
that path is included in the fix.

## Verification

- `cargo fmt --all -- --check`: passed.
- `cargo clippy --all-targets -- -D warnings`: passed.
- `cargo test --all`: passed, 836 tests reported passed, 0 failed, 0 ignored
  across 64 result summaries. Environment-gated external integrations may
  return early; this is not a claim of live external integration coverage.
- `cargo build --release -p cognigraph-server`: passed.
- Real release-binary HTTP checks: passed in resident and paged modes, both with
  sidecar vectors, synthetic authentication, and an OpenAI-compatible loopback
  completion stub. Each mode was stopped and restarted against its own store.

The live checks verified distinct field-list results before/after restart,
successful vector search for a separator-bearing collection, absence of files
outside the store, HTTP 400 for duplicate/reserved fields in text and hybrid
search, nonmatching UPSERT preservation, and six malformed directed responses
preserving the prior facts. A valid explicit empty response still removed the
old occurrences. See [sanitized HTTP evidence](../evidence/engineering-historical-checks.md#artifact-b217bd7cdb482ab507bc).

Regression tests additionally check every required directed field missing or
wrongly typed, mixed valid/invalid proposals, a complete store snapshot after
each rejected response, keyed/scanned UPSERT parity for numeric/null/missing
values, and warm-open rejection of mismatched schema, identity, or generation.

Early validation caught a SHA-256 formatting incompatibility and two mistakes
in the new UPSERT test (unsupported single-quoted literals and an integer
assertion against CGQL's floating-point numeric representation). These were
corrected before the final validation run. No failed live check was hidden.

## Compatibility and remaining work

Existing derivative files are left untouched. New names cause an on-demand
rebuild from redb, so the first search may be slower and old derivative files
can consume additional disk space. No truth-store migration is needed.

The server hybrid result cache has its own ambiguous request fingerprint,
recorded separately as [CG-31](CG-31.md); Native index correctness does not close
that issue. Tenant-incarnation reuse (CG-11/CG-12), concurrent paged-cache
validity (CG-10/CG-14), and directed deployment fencing (CG-3) also remain open.
External provider behavior and live ArangoDB were not revalidated in this batch.

The next bounded priorities are CG-1/CG-6 (Lua execution controls), CG-3
(directed deployment fencing), then CG-10/CG-14 (paged-cache validity).
