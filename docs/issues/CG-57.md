# CG-57: Clickable table rows cannot be opened with the keyboard

- Status: Resolved
- Priority: P2
- Area: UI / accessibility
- Found: 2026-09-11
- Verification: UI checks, 146 tests, production build, real Rust/Native browser keyboard and pointer journeys

## Problem and evidence

Several tables make their rows clickable but provide no keyboard-operable
control for the same action: [CollectionsIndexScreen](../../ui/src/screens/CollectionsIndexScreen.tsx)
line 184, [OverviewScreen](../../ui/src/screens/OverviewScreen.tsx) line 185,
[UsersScreen](../../ui/src/screens/UsersScreen.tsx) line 144,
[ReviewScreen](../../ui/src/screens/ReviewScreen.tsx) line 308 and
[SearchPanel](../../ui/src/components/SearchPanel.tsx) line 220.

Rendered Users rows had `tabIndex=-1`, no links and no buttons. Review rows had
the same structure, and vector-result cells were plain text. Thus keyboard users
cannot open an account, inspect a neuron or follow a search hit through these
controls. The Collections index exposes Delete buttons while the corresponding
open action remains pointer-only. DocumentTable already demonstrates accessible
key/selection buttons, so this is not a requirement to make every row focusable.
This audit inspected DOM and accessibility trees; it did not certify screen-reader
narration or full WCAG conformance.

[Full UI review and environment](../evidence/ui-2026-09-11-full-review.md#artifact-2a08bd45b55e9bd0cb9c). No application fix was made in this audit.

## Acceptance

- [x] Provide native links for navigation and buttons for selection, with descriptive names and visible focus.
- [x] Keep pointer row shortcuts if useful without adding conflicting nested click behavior.
- [x] Walk catalog-to-document, users-to-detail, review-to-inspector and search-to-document using only Tab and Enter/Space.

## Resolution — 2026-09-11

Collections, Overview, Users and search results now expose native React Router
links in their identity columns. Review facts expose a native selection button
with the neuron identity and fact in its name, pressed state and the existing
busy restriction. Links/buttons stop click propagation to the containing row;
ordinary row cells retain their pointer shortcuts. Shared focus styling covers
anchors, and the action text uses the console accent with hover underlining.

Edge collections remain outside the document browser. Search links require a
complete, unambiguous document handle and encode both identifiers; incomplete
handles remain plain text. No whole-row tab stops or new permissions were added.

## Verification and limits

- `bun run check`, `bun test` (146 tests, 733 assertions) and `bun run build` pass.
  Added route tests cover punctuation and incomplete/ambiguous search handles.
- The Rust-served production UI passed Tab/Enter journeys from catalog and
  Overview to documents, Users to account details and vector results to the
  matching document. Existing document selection works with Space; Review
  selection works with Enter and Space, followed by keyboard inspector dismissal.
- Pointer shortcuts pass on all five tables. Collection Delete/Cancel remains
  isolated from navigation. Direct account, neuron and document URLs reload.
- Focus and layout were measured at 1280 × 800 and 1067 × 667. Tab scrolls the
  final Overview link into view. Admin and Viewer checks preserve data-read,
  mutation and account-management boundaries; a fresh Viewer `/users` call
  returned 403. Fresh reads confirm no document or neuron mutation.
- [Evidence, source/asset manifest and limits](../evidence/ui-2026-09-11-table-keyboard.md#artifact-a5b3ed52a87a809a63dc).
  This verifies Native Enterprise with synthetic fixtures and a shared search

  native OS scaling and full WCAG conformance were not certified. No Rust source
