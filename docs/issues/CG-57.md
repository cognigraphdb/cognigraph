# CG-57: Clickable table rows cannot be opened with the keyboard

- Status: Open
- Priority: P2
- Area: UI / accessibility
- Found: 2026-09-11
- Verification: Source review and rendered DOM/keyboard-target inspection

## Problem and evidence

Several tables make their rows clickable but provide no keyboard-operable
control for the same action: [CollectionsIndexScreen](../../ui/src/screens/CollectionsIndexScreen.tsx)
line 184, [OverviewScreen](../../ui/src/screens/OverviewScreen.tsx) line 185,
[UsersScreen](../../ui/src/screens/UsersScreen.tsx) line 144,
[ReviewScreen](../../ui/src/screens/ReviewScreen.tsx) line 308 and
[SearchPanel](../../ui/src/components/SearchPanel.tsx) line 220.

Rendered Users rows had `tabIndex=-1`, no links and no buttons. Review rows had
the same structure, and vector-result cells were plain text. Thus keyboard users
cannot open an account, inspect a neuron or follow a search hit through these
controls. The Collections index exposes Delete buttons while the corresponding
open action remains pointer-only. DocumentTable already demonstrates accessible
key/selection buttons, so this is not a requirement to make every row focusable.
This audit inspected DOM and accessibility trees; it did not certify screen-reader
narration or full WCAG conformance.

[Full UI review and environment](../../ui/audit/2026-09-11-full-review/audit.md). No application fix was made in this audit.

## Acceptance

- [ ] Provide native links for navigation and buttons for selection, with descriptive names and visible focus.
- [ ] Keep pointer row shortcuts if useful without adding conflicting nested click behavior.
- [ ] Walk catalog-to-document, users-to-detail, review-to-inspector and search-to-document using only Tab and Enter/Space.
