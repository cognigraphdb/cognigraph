# CG-142: A failed snapshot import can leave the tenant's job queue fenced, depending on other tenants' health

- Status: Open
- Priority: P2
- Area: Server / jobs; snapshot import (Enterprise)
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`import_snapshot` (`crates/cognigraph-server/src/routes/admin.rs:196-229`)
pauses the tenant's jobs with `pause_tenant_if_idle`. On an import error it
resumes them only `if state.promotions.health().is_ok()` (`:220-224`).
`health()` aggregates errors across all tenants
(`promotions/manager.rs:58-72`), while `ensure_mutations_healthy` is per
tenant. The Admin promotion `recover` route heals promotion health but never
resumes jobs (`routes/promotions.rs:334-352`). The remaining ways out are a
later successful import, a host-admin suspend and activate cycle, or a
restart.

Failure sequences:

- Tenant B has any recorded promotion error. Tenant A's Admin submits a
  snapshot that fails preflight, a pure validation error with nothing
  written. A's queue stays paused and every submit or retry returns 403 "not
  accepting durable jobs".
- In one tenant, a failed import records an error, the Admin runs promotion
  recovery successfully, and jobs stay fenced.

The CLI's 30-second timeout ([CG-147](CG-147.md)) makes an interrupted import
more likely.

## Acceptance

- [ ] The decision to lift the job fence uses only the importing tenant's state.
- [ ] Promotion recovery or an explicit Admin action lifts a fence left by a failed import, and queue status explains why a tenant is paused.
- [ ] Tests cover a failed import while another tenant is degraded, and failed import, recover, then submit.
