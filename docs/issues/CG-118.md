# CG-118: Paged-mode atomic batch creates a collection without recording its type

- Status: Open
- Priority: P2
- Area: Native / paged mode
- Found: 2026-11-11
- Verification: Pending (source-confirmed in the 2026-11-11 review; not executed)

## Problem and evidence

`execute_batch` in `crates/cognigraph-native/src/memory/batch.rs` persists
`PutCollection` for an implicitly created collection (`:207-219`), but its
paged branch (`:245-257`) updates only `state.keys`. The resident branch goes
through `collection_mut`, which also records the type. Until the next restart
`state.collection_types` has no entry, and `check_collection_type` treats a
missing entry as "anything goes".

After a paged `POST /api/batch` inserts into a new collection `notes`:

- `create_edge("notes", …)` succeeds (resident mode refuses it) and persists
  `notes` as an edge collection. From then on `create_document("notes")` fails
  with "not a Document collection".
- `ensure_collection("notes", Edge)` flips the stored type instead of being a
  no-op.
- `bulk_insert("notes", …)` returns `CollectionNotFound` for a collection that
  exists.

## Acceptance

- [ ] The paged batch path records the type of implicitly created collections in memory.
- [ ] A test batch-inserts into a new collection in paged mode, then expects a refused `create_edge`, a no-op `ensure_collection(Edge)` and a working `bulk_insert`, before and after reopening.
